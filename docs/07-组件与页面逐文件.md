### 1.3 判据：什么叫"笨"组件（R5 的两条禁令）

| 禁令 | 含义 | 为什么 |
|---|---|---|
| **不许 import `@/stores/**`** | 组件不知道任何全局状态 | 组件要能**复用**（同一个 `BoardView` 服务游玩盘/答案盘/预览盘/求解结果盘） |
| **不许 import `vue-router`** | 组件不知道"我在哪一页" | 跳转是页面的决定 → 组件只 `emit` |

**两条推论**（本册会反复看到）：
1. **组件的数据全部来自 props**（或插槽的 slot props）；
2. **组件的"动作"全部是 `emit`，或 props 里传进来的回调**（例：`FormField` 收 `update:modelValue`；`TextAction` 收 `onClick`）。

### 1.4 数据流总图（一次交互的完整往返）

```
composable（06 册）
   │ 暴露"数据 + 动作 + 控件数据"
   ▼
page（只接线）
   │ props 往下传（常常用 v-bind="obj"）
   ▼
component（只画）
   │ 用户操作 → emit / 调用 props 里的回调
   ▲
page 把事件接回 composable / store 的动作
```
**本册的每一节，都是在看"这条链上的一小段"。**

## 2. 通用三件：`TextAction` / `Flex` / `EyeGlyph`

> 这三个文件加起来 115 行，但**全站所有交互与布局都靠它们**。**"少而通用"是这一层最重要的原则。**

### 2.1 `TextAction.vue`（36 行）—— 全站唯一的"按钮"

```ts
/**
 * 可点击文本（全站唯一一种「按钮」）：**传文本 + 点击函数**
 * · 不传 `onClick` → 纯文本（禁用态就这么表达，不再另设 disabled）
 * · 样式就是全站的 `.text-btn`（无框、无底、hover 下划线）—— 不额外加任何悬停提示
 */
const props = defineProps<{
    /** 显示文本（图形也算文本：`➖` / `👁` / `▶ 挑战`） */
    text?: string
    /** 点击函数；不传就是纯文本 */
    onClick?: () => void
}>()

/** 可点 → `<button>`；纯文本 → `<span>`（键盘 / 读屏语义也对） */
const tag = computed<string>(() => (props.onClick ? 'button' : 'span'))
```

```html
<component :is="tag" class="text-action" :class="{ 'text-btn': !!onClick }" :type="onClick ? 'button' : undefined"
    @click="onClick">
    <slot>{{ text }}</slot>
</component>
```

**① 它为什么能取代全站所有按钮**：

| 需求 | `TextAction` 怎么满足 |
|---|---|
| 普通按钮 | `<TextAction text="上一页" :on-click="goPrev" />` |
| **禁用态** | **不传 `onClick`** → 渲染成 `<span>`、**没有 `.text-btn`**（无 hover 下划线）、点击无效 |
| 图形按钮 | `text="➖"` / `text="👁"`（**图形也算文本**） |
| 自定义内容（如 SVG） | **默认插槽**：`<TextAction :on-click="..."><EyeGlyph /></TextAction>` |
| 全站样式一致 | 样式集中在全局 `.text-btn`（03 册归位原则："跨页共用的视觉规格 → 全局样式"） |

**② `:is="tag"` 的深意（语义正确性）**：
- **可点时**渲染成 `<button>` → **天然可聚焦、可回车/空格触发、读屏念"按钮"**；
- **不可点时**渲染成 `<span>` → 不会被 Tab 聚焦、读屏不会念"按钮"（**它本来就不能点**）。
> **如果一律用 `<div @click>`**：键盘用户 Tab 不到它、读屏也不知道它是按钮 —— **这是最常见的无障碍缺陷**。
> 本项目用 12 行把它做对了。

**③ `<slot>{{ text }}</slot>`**：
`slot` 的内容就是"**没有插槽内容时的默认值**" → 传了 `text` 就显示 `text`，给了插槽就显示插槽内容。
**一个组件同时支持"文本模式"和"自定义内容模式"，不需要额外的 prop。**

**④ `:type="onClick ? 'button' : undefined"`**：
`<button>` 在 `<form>` 里**默认是 submit**（会触发表单提交）→ 显式 `type="button"` 防止意外提交。
（不可点时是 `<span>`，传 `undefined` 就不会渲染这个属性。）

**⑤ 样式为什么只有 5 行**：
```css
.text-action { display: inline-flex; align-items: center; gap: 4px; line-height: 1.5; font-family: inherit; }
```
**只补"图形与文字对齐"**（`gap: 4px` 让 `👁 预览` 里的间距一致），其余（颜色/字号/下划线/光标）**全部来自全局 `.text-btn`**。
> **"组件样式只做自己特有的那一点"** —— scoped 样式的正确姿势：**不复制全局规格**。

### 2.2 `Flex.vue`（44 行）—— 全站唯一的布局件

```ts
const props = withDefaults(defineProps<{
    direction?: 'row' | 'column'
    gap?: number
    align?: 'start' | 'center' | 'end' | 'baseline' | 'stretch'
    justify?: 'start' | 'center' | 'end' | 'between'
    wrap?: boolean
}>(), { direction: 'row', gap: 8, align: 'center', justify: 'start', wrap: false })

const ALIGN = { start: 'flex-start', center: 'center', end: 'flex-end', baseline: 'baseline', stretch: 'stretch' } as const
const JUSTIFY = { start: 'flex-start', center: 'center', end: 'flex-end', between: 'space-between' } as const

const style = computed<CSSProperties>(() => ({
    flexDirection: props.direction === 'column' ? 'column' : 'row',
    gap: `${props.gap}px`,
    alignItems: ALIGN[props.align],
    justifyContent: JUSTIFY[props.justify],
    flexWrap: props.wrap ? 'wrap' : 'nowrap',
}))
```

**① 它解决什么问题**（注释原文）：
> *"省掉各组件里那堆 `display:flex; gap; align-items` 的 scoped 样式"*

**对比**（真实收益）：
```html
<!-- ❌ 之前：每个组件自己写一遍（还要起类名） -->
<div class="row-between">
  <style scoped>.row-between { display:flex; align-items:center; justify-content:space-between; gap:8px }</style>
</div>

<!-- ✅ 现在：一行，语义自明 -->
<Flex justify="between" :gap="8"> … </Flex>
```

**② `ALIGN` / `JUSTIFY` 两个映射表（值得学的一招）**：
- **props 用"短语义名"**（`start` / `between`）→ 调用方好写、类型好收窄；
- **映射到真实 CSS 值**（`flex-start` / `space-between`）→ **CSS 细节收在组件内部**，调用方不用背 `space-between` 的拼写；
- `as const` 让 `ALIGN[props.align]` 的类型是精确的字符串字面量联合（00 册 §4.3）。
> **"对外短名、对内长名"+"用映射表收口"** 是可以到处套用的模式（后端的 `visibilityOf`、04 册的形态归一化都是它）。

**③ 为什么"特殊尺寸仍由调用方挂 class 补"**（注释原文）：
`flex: 1`、固定宽度、`margin-top` 这些**不可能用 5 个 prop 覆盖所有情况**（否则 props 会膨胀成"CSS 的翻版"）。
**边界很清楚**：`Flex` 管"方向/间距/对齐"这三件**最常重复**的事，其余交给调用方的 class。
> **"通用组件不要试图吃掉所有样式需求"** —— 不然它会变成"配置式 CSS"，比直接写 CSS 更难用。

### 2.3 `EyeGlyph.vue`（35 行）—— 全站唯一的眼睛图形

```ts
/**
 * 眼睛图形（全站唯一一套）：睁眼 = 遮蔽中（点它显示）/ 闭眼 = 已明文（点它隐藏）
 * uid / pid 的裸图标组与密码框共用，避免各画一套
 */
defineProps<{
    /** 值当前是否已明文 */
    revealed: boolean
}>()
```
```html
<!-- 已明文 → 闭眼 -->
<svg v-if="revealed" class="glyph" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2"
    stroke-linecap="round" aria-hidden="true"> … </svg>
<!-- 遮蔽中 → 睁眼 -->
<svg v-else class="glyph" viewBox="0 0 24 24" … aria-hidden="true"> … </svg>
```

**① "全站唯一一套"的价值**：它被三处使用 —— `FormField` 的密码框、`SecretValue` 的 pid、`SecretValue` 的 uid。
如果每处各画一个 SVG：**样式会飘、语义会不一致**（有的"点一下显示"有的"点一下隐藏"）。
**现在只有一个 prop：`revealed`**（"值当前是否已明文"）→ **两种状态由组件自己映射到两个图形**。

**② `stroke="currentColor"`**：颜色**继承父元素** → 放在不同上下文里自动跟着变（父级给 `color` 即可）。

**③ `aria-hidden="true"`（无障碍细节）**：
这是**装饰性 SVG**（真正可点的元素是外层的 `TextAction`）→ 加 `aria-hidden` 让读屏**不要念它在画什么**，只念外层按钮的文本。
> **原则**：**装饰性图形 `aria-hidden`，功能性元素给可读文本**。

**④ `width/height: 16px` + `display: block`**：在 `inline-flex` 的 `TextAction` 里**不会出现基线空隙**（inline 元素默认按基线对齐，`display:block` 消掉这个间隙）。

## 3. `FormField.vue`（187 行）—— 一个通用件吃掉一族表单控件

**① 它是谁**：**全站所有表单控件的唯一实现**：单行文本 / 多行文本 / 密码（带 👁）/ 下拉 / 滑动条。
**谁在用它**：登录页（3 个输入）、出题页（标题）、难度页（大小下拉 + 比例滑杆）、求解页（模式/大小/解数）、搜索页与我的题目（工具条两个下拉、行内两个下拉）、自定义页（两个大文本框）、编辑页……

### 3.1 契约（看这张表就知道它能干什么）

```ts
const props = defineProps<{
    /** 渲染方式：单行文本 / 多行文本 / 密码（带 👁）/ 下拉 / 滑动条 */
    type?: 'text' | 'textarea' | 'password' | 'select' | 'range'
    /** 标签文案（不传就不显示标签） */
    label?: string
    /** v-model 绑定的值（下拉可传数字，如盘面大小 B） */
    modelValue: string | number
    /** 下拉选项（type=select） */
    options?: readonly SelectOption[]
    /** 滑动条范围（type=range） */
    min?: number
    max?: number
    step?: number
    placeholder?: string
    /** 最大长度（与常量一致） */
    maxlength?: number
    /** 说明行（格式提示 / 字符计数都由调用方算好传进来） */
    hint?: string
    /** 等宽字体（账号 ID、题面串这类要逐字核对） */
    mono?: boolean
    /** 浏览器自动填充提示（如 'off'） */
    autocomplete?: string
    /** 小号（列表工具条 / 卡片设置项） */
    compact?: boolean
    /** 标签放上面（表单用）；默认放左边 */
    vertical?: boolean
    /** 固定宽度（例如卡片里两个下拉要等宽） */
    width?: string
}>()

const emit = defineEmits<{ 'update:modelValue': [value: string | number] }>()
```

| 维度 | 说明 |
|---|---|
| **渲染方式** | `type` 一个字段决定画哪种控件（**不是五个组件**） |
| **值** | 标准 `v-model`（`modelValue` + `update:modelValue`），且**允许 `number`**（如盘面大小 `B`） |
| **形态** | `vertical`（标签在上，表单用）/ 默认横向（工具条、行内设置用）；`compact` 小号 |
| **展示辅助** | `hint`（说明行）、`mono`（等宽）、`width`（等宽对齐） |

### 3.2 模板：`v-if / v-else-if` 分发五种形态

```html
<label class="field" :class="{ 'is-vertical': vertical }">
    <span v-if="label" class="text">{{ label }}</span>

    <textarea v-if="type === 'textarea'" class="input textarea" :value="modelValue" :placeholder="placeholder"
        :maxlength="maxlength" spellcheck="false" @input="onInput"></textarea>

    <select v-else-if="type === 'select'" class="select" :class="{ 'is-sm': compact }"
        :style="width ? { width } : undefined" :value="modelValue" @change="onValue">
        <option v-for="opt in options ?? []" :key="opt.value" :value="opt.value">{{ opt.label }}</option>
    </select>

    <input v-else-if="type === 'range'" class="slider" type="range" :min="min" :max="max" :step="step"
        :value="modelValue" @input="onValue">

    <span v-else class="control">
        <input class="input" :class="{ 'is-mono': mono, 'has-eye': type === 'password' }"
            :type="type === 'password' && !visible ? 'password' : 'text'" :value="modelValue"
            :placeholder="placeholder" :maxlength="maxlength" :autocomplete="autocomplete" spellcheck="false"
            @input="onInput">

        <!-- 密码右侧的 👁 就是通用的「可点击文本」（自绘图形走插槽） -->
        <TextAction v-if="type === 'password'" class="eye" :on-click="() => (visible = !visible)">
            <EyeGlyph :revealed="visible" />
        </TextAction>
    </span>

    <span v-if="hint" class="hint">{{ hint }}</span>
</label>
```

**① 为什么要用 `<label>` 包住整块**：
- **点标签即聚焦控件**（原生行为）→ 小屏幕/触屏用户受益；
- 语义上"这一块是一个表单字段"（读屏会念标签 + 控件）。

**② `:type="type === 'password' && !visible ? 'password' : 'text'"`**：
`visible` 为真时把 input 的 `type` 从 `password` 换成 `text` → **浏览器自己就把字显示出来了**（不需要改 value）。
**这就是"明文开关"的最简实现**（0 行 JS 逻辑，只改一个属性）。

**③ 为什么"可点元素"是 `TextAction` + 插槽里的 `EyeGlyph`**：
```html
<TextAction v-if="type === 'password'" class="eye" :on-click="() => (visible = !visible)">
    <EyeGlyph :revealed="visible" />
</TextAction>
```
- **文字按钮不需要"再定义一个图标按钮组件"** → `TextAction` 的默认插槽直接接住 SVG（§2.1 的"文本模式/自定义内容模式"）；
- `EyeGlyph` 与 `SecretValue` 用的是**同一个**（§2.3 的"全站唯一一套"）。

### 3.3 两个事件处理器（**本项目最容易看漏的一处细节**）

```ts
/** 文本类控件：直接回传文本 */
const onInput = (e: Event): void => {
    emit('update:modelValue', (e.target as HTMLInputElement | HTMLTextAreaElement).value)
}

/** 下拉 / 滑动条：下拉按键值还原原始类型（数字选项如盘面大小 B），滑动条转数字 */
const onValue = (e: Event): void => {
    const raw = (e.target as HTMLInputElement | HTMLSelectElement).value
    const hit = props.options?.find((o) => String(o.value) === raw)
    emit('update:modelValue', hit ? hit.value : Number(raw))
}
```

**为什么需要两个处理器（而不是合成一个）**：

| 控件 | 事件 | 值的类型 | 处理 |
|---|---|---|---|
| `input[text]` / `textarea` | `@input` | **`string`**（本来就要字符串） | 直接回传 |
| `select` | `@change` | **`string`**（**但选项的 value 可能是数字**） | **按键值查回原始类型** |
| `range` | `@input` | `string`（数字的字符串形式） | `Number(raw)` |

**关键在 `select` 那一行** —— 这行代码解决一个真实问题：

```ts
const hit = props.options?.find((o) => String(o.value) === raw)
emit('update:modelValue', hit ? hit.value : Number(raw))
```
- **`<select>` 的 DOM value 永远是字符串**：`BOX_SIZE_SELECT_OPTIONS` 的 `value` 是数字 `B`（3、4、6…），但读出来是 `'3'`；
- **按 `String(o.value) === raw` 反查**：找到那个选项 → **回传原始类型 `hit.value`（number）**；
- **找不到就 `Number(raw)`**：这是 `range` 的分支（滑动条没有 options）；
- **为什么必须还原**：`config.boxSize` 的类型是 `number`，它会被喂进 `cellCountOf(B)`、`sideOf(B)`、`getSudoku(B)` —— 一旦是字符串，`B * B` 虽能靠隐式转换过关，但**任何字符串拼接/比较都会出问题**（例如 `BOARD_ZOOM.default[boxSize]` 用字符串 `'3'` 查数字键 `3` 的表 → **查不到 → 回落到 min**，缩放就不对了）。
> **知识点：DOM 里没有"数字"，只有字符串。** 凡是"把一个带类型的数据存进 DOM 再读回来"的地方，都要做**类型还原**（本项目用"选项表 + 字符串比较"来做，而不是无脑 `Number()` —— 因为选项的 value 也可能是字符串，`Number('public')` 会变 `NaN`）。

**④ `spellcheck="false"`**（textarea 与 input 都有）：题面串、账号 ID 这类内容**不需要拼写检查**（波浪线只会干扰阅读，而且浏览器可能对超长串卡顿）。

**⑤ `hint` 完全由调用方算好传进来**（注释原文：*"格式提示 / 字符计数都由调用方算好传进来"*）：
例如自定义页的"456 字符 · 识别为 9×9"（06 册 §5.5 的 `puzzleInfo`）。
**组件不做任何文本计算** → 它连"还能输入几个字"都不算（保持"笨"）。

### 3.4 样式里的四个"约定"（都值得记）

```css
/* 横向：标签在左、控件在右（列表工具条 / 卡片设置项）—— 必须显式 row，否则会继承全局 .field 的纵向 */
.field {
    display: inline-flex;
    flex-direction: row;
    align-items: center;
    gap: 6px;
    margin-bottom: 0;
}

/* 纵向：标签在上（表单用），沿用全局 .field 的间距 */
.field.is-vertical {
    display: flex;
    flex-direction: column;
    align-items: stretch;
    gap: 6px;
    margin-bottom: 18px;
}
```

**① "必须显式 row，否则会继承全局 `.field` 的纵向"** —— 这是一条**真实踩坑记录**：
全局 `styles/form.css` 里的 `.field` 是**纵向**（表单默认），组件默认要**横向**（工具条/行内设置）→ 如果只写 `inline-flex` 而不写 `flex-direction: row`，**全局的 `flex-direction: column` 会把它变成纵向**（同名类，后加载的全局样式可能覆盖组件样式，或反之 —— 取决于顺序，非常不稳定）。
**解法**：**组件显式声明自己需要的方向**，不依赖"谁覆盖谁"。

**② 两种形态的差别（以及为什么"不传 `vertical` 是横向"）**：
| | 默认（横向） | `vertical`（纵向） |
|---|---|---|
| 用在 | 列表工具条、卡片里的设置项 | 表单（登录/出题/自定义） |
| 标签位置 | 左侧，`white-space: nowrap`（不换行） | 上方，`font-weight: 600`（加粗） |
| 底部间距 | `0`（行内不留白） | `18px`（表单字段之间要留白） |
**默认值选"横向"**：因为**行内场景更多**（两个列表页的工具条 + 卡片 4 个下拉），表单只有 3 个页面。

**③ `.textarea` 强制等宽 + `resize: vertical`**：
```css
.textarea {
    height: 96px; padding: 8px 10px; line-height: 1.5;
    font-family: ui-monospace, Menlo, monospace;
    resize: vertical;
}
```
- **等宽字体**：题面串要"逐字核对"（数字对齐才看得清哪一位错了）；
- **只允许纵向拉伸**：横向拉伸会撑破卡片布局。

**④ `.label`/`.control`/`.has-eye`/`.eye` 这组"密码框留位"**：
```css
.control { position: relative; display: block; }
.input.has-eye { padding-right: 38px; }          /* 给 👁 留出位置，文字不会钻到图标下面 */
.eye { position: absolute; right: 4px; top: 50%; transform: translateY(-50%); width: 30px; height: 28px; justify-content: center; }
```
**"绝对定位 + 父级留 padding"** 是"输入框里放图标"的标准做法（`top:50%` + `translateY(-50%)` 是垂直居中的经典组合）。

**⑤ `.input` / `.select` / `.slider` 这些类名来自全局 `styles/form.css`**：
组件里只写"自己特有"的部分（等宽、留位、滑动条外观）→ **与 §2.1 的 `.text-btn` 同一原则**。
**为什么要自己写滑动条外观**：`<input type="range">` 的原生外观在各浏览器差异极大 → 必须自绘（`appearance: none` + 分别给 `::-webkit-slider-thumb` 与 `::-moz-range-thumb` —— **两个都要写**，否则 Firefox 里还是原样）。

**⑥ 它故意不做什么**：
- **不做校验**（正则、必填、长度——都由 composable 做）；
- **不算任何文本**（`hint` 由调用方给）；
- **不管提交**（没有 `@submit`/`@keyup.enter` → 页面自己绑，如登录页的"回车提交"）；
- **不弹提示**（没有 tooltip / 气泡）。
> **"表单字段"这件小事，本身就够一个组件的全部职责了。**

## 4. `Overlay.vue`（119 行）—— 全站唯一的遮罩

**① 它是谁**：**所有弹窗/加载层/确认框的唯一实现**。
**谁在用它**：参考答案遮罩、题目导出、通关提示、预览遮罩、出题失败/成功、删除确认、难度页与求解页的"生成中"转圈。
**契约**（注释原文：*"传数据 → 自己决定画什么"*）：

```ts
withDefaults(defineProps<{
    show: boolean
    /** 主文案 */ text?: string
    /** 次要说明 */ desc?: string
    /** 是否遮蔽背景 */ shade?: boolean
    /** 是否转圈 */ spinning?: boolean
    /** 按钮条（有才渲染） */ actions?: Actions
    /** 宽盒子（长文本 / 一串题面用） */ wide?: boolean
}>(), { text: '', desc: '', shade: true, spinning: false, wide: false })
```

| prop | 效果 | 真实用法 |
|---|---|---|
| `show` | 显示/隐藏（`v-if` + `Transition` 淡入淡出） | 所有调用方 |
| `text` / `desc` | 主标题 / 次要说明（**不传就不占位**） | 通关遮罩、导出说明 |
| `shade` | `true`（默认）半透明 + 模糊；`false` = 不遮背景（只当浮层框） | 预览遮罩有时要"看得见后面" |
| `spinning` | 显示转圈 | "生成中""保存中" |
| `actions` | 按钮条（`Actions`，有才渲染） | 几乎每个遮罩 |
| `wide` | 宽盒子（`max-width: 720px`） | 导出题面串、答案预览 |

**模板三件套**：
```html
<Teleport to="body">
    <Transition name="overlay-fade">
        <div v-if="show" class="overlay" :class="{ 'is-plain': !shade, 'is-wide': wide }">
            <div class="overlay-box">
                <div v-if="spinning" class="spinner"></div>
                <p v-if="text" class="overlay-title">{{ text }}</p>
                <p v-if="desc" class="overlay-desc">{{ desc }}</p>

                <slot />

                <Flex v-if="actions?.length" class="overlay-actions" :gap="14" justify="center" wrap>
                    <TextAction v-for="a in actions" :key="a.key" :text="a.text" :on-click="a.onClick" />
                </Flex>
            </div>
        </div>
    </Transition>
</Teleport>
```

**② `<Teleport to="body">` 为什么必要**：
遮罩用 `position: fixed`（相对视口定位）→ 如果它被渲染在某个 `overflow: hidden` / `transform` 的祖先里，**`fixed` 会相对那个祖先定位**（`transform` 会创建新的定位上下文）→ 遮罩可能被裁掉或位置错乱。
**挂到 `<body>` 下** → 永远相对视口、不受任何祖先影响。
> **这也是本项目唯一用 `Teleport` 的地方**（03 册的"适配器"思路：把"和外部世界打交道"集中在一处）。

**③ `<Transition name="overlay-fade">` + `v-if`**：
- **`v-if`**：`show` 为假时**整棵 DOM 不存在**（不是隐藏）→ 不会拦截点击、不会被读屏看到；
- **`<Transition>`**：给出现/消失加 0.2s 的透明度过渡（`overlay-fade-enter-from / leave-to { opacity: 0 }`）。

**④ 五处 `v-if` 的"有才渲染"**（`spinning` / `text` / `desc` / `slot` / `actions?.length`）：
**一个组件服务了五类弹窗，靠的就是"每一块都可缺省"**：
| 场景 | 用了哪些块 |
|---|---|
| 加载中 | `spinning`（+ 可选 text） |
| 通关 | `text` + `desc` + `actions` |
| 参考答案 | `text` + **插槽（只读棋盘）** + `actions` |
| 导出题面 | `text` + `desc` + **插槽（小标题 + textarea）** + `actions` + `wide` |
| 删除确认 | `text` + `desc` + `actions` |

**⑤ `actions?.length` 而不是 `actions`**：
空数组也是 truthy → 如果不判断长度，会渲染一个**空的 `Flex`**（带 `margin-top: 14px`）→ 遮罩底部多出一块空白。
> **`v-if="arr?.length"`** 是渲染按钮条/列表的通用写法（04 册 `hasEmptyGroup` 那类"空数组要当'没有'"的同一意识）。

**⑥ `is-plain` / `is-wide` 两个变体（用 class 而不是 prop 组合）**：
```css
.overlay.is-wide .overlay-box { max-width: 720px; width: 100%; }
.overlay.is-plain { background: transparent; backdrop-filter: none; }
```
**用"变体 class"而不是"给每个细节加一个 prop"** → props 保持少而清晰（与 §2.2 `Flex` 的边界同一条原则）。

**⑦ 转圈为什么收在这里（不再单独做一个 `SpinnerIcon`）**：
注释原文：*"原 SpinnerIcon 一并收进来：一个组件够用就别再拆一个"*。
**12 行 CSS**（一个圆 + `border-top-color` 高亮 + `@keyframes` 旋转）→ **不值得为它单独一个文件**。
> **"组件粒度"的判断：能内联进现有组件、且只有一个使用场景的，就不要拆文件**（与 04 册 R9 的"单函数模块 ≥50 行"是同一种"别碎"的考虑）。

## 5. `SecretValue.vue`（91 行）—— 敏感值（pid / uid 共用）

**① 它是谁**：**"一个默认看不见、点开才看得见、还能一键复制"的值**。
**谁在用它**：`MyPuzzleRow`（`pid`）、`useAccountPanel` 所在的「我的」页账号区（`uid`）。

**契约**（注释原文：*"传标签 + 传取值方式 → 自己决定怎么显示"*）：

```ts
const props = withDefaults(defineProps<{
    /** 值标签（`pid` / `uid`；遮蔽与明文都带同一前缀，点开不会换模样） */
    label: string
    /** 取真值（点了才调；返回空 = 没取到，保持遮蔽） */
    load: () => Promise<string | null>
    /** 初始就是明文 */
    revealed?: boolean
}>(), { revealed: false })
```

**只有三个 prop**：
| prop | 作用 |
|---|---|
| `label` | 前缀（`pid` / `uid`）—— 遮蔽时也显示，所以"点开后样子不变，只是内容变了" |
| `load` | **取真值的函数（不是值本身）** —— 点了才调用，见下 |
| `revealed` | 初始是否明文（默认 `false` = 遮蔽） |

### 5.1 三段逻辑：取真值 / 切换 / 复制

```ts
const { copied, copy } = useClipboard()
/** 是否明文 */
const open = ref<boolean>(props.revealed)
/** 已取到的真值 */
const value = ref('')

const MASK = '▮▮▮▮▮▮▮▮'

/** 现取真值（取过就复用） */
const fetchValue = async (): Promise<string> => {
    if (!value.value) value.value = (await props.load()) ?? ''
    return value.value
}

/** 👁：明文 ↔ 遮蔽 */
const toggle = async (): Promise<void> => {
    if (open.value) { open.value = false; return }
    if (await fetchValue()) open.value = true
}

/** 📋：真值进剪贴板 */
const copyValue = async (): Promise<void> => {
    const v = await fetchValue()
    if (v) await copy(v)
}

const text = computed<string>(() => `${props.label} ${open.value ? value.value : MASK}`)
```

**① `if (!value.value)` 的"取过就复用"**：
- **不点就不请求**（安全 + 省流量）；
- **点第二次不再请求**（缓存）；
- **`?? ''`**：`load` 返回 `null`（取不到）→ 归一成 `''` → `if (await fetchValue())` 为假 → **保持遮蔽**（不会显示一个空白的明文）；
- **注意它不做"失败提示"**：取不到就"点不动"（`SecretValue` 的接口里没有 `error`）——**这是有意的极简**（调用方也不需要知道）。

**② `toggle` 的"已明文就直接关"**：
```ts
if (open.value) { open.value = false; return }
```
**关的时候不请求**（已经取过值了）→ 只有"从遮蔽到明文"才需要 `fetchValue`。

**③ `copyValue` 走同一个 `fetchValue`**：
**复制也不需要明文显示**（注释原文："点 📋 直接复制真值（**不进界面**）"）→ 用户不必先把值显示出来再复制。
**这就是把"取真值"抽成一个函数的好处**：两个入口（显示 / 复制）共用。

**④ `text` 用 computed 拼**：`${label} ${open ? value : MASK}` → **遮蔽与明文共用同一个前缀**（注释："点开不会换模样"）。

### 5.2 模板与"为什么调用方不用管状态"

```html
<p class="secret">
    <span>{{ text }}</span>

    <span class="icon-row">
        <TextAction class="glyph" :on-click="() => { void toggle() }">
            <EyeGlyph :revealed="open" />
        </TextAction>

        <TextAction class="glyph" :text="copied ? '✅' : '📋'" :on-click="() => { void copyValue() }" />
    </span>
</p>
```

**① 注释里最关键的一句**：
> *"点击事件就在组件里响应，调用方不用管「遮蔽 / 明文 / 复制」那套状态"*

**调用方的代码只有一行**（`MyPuzzleRow.vue:75`）：
```html
<SecretValue :label="MINE_COPY.pidTag" :load="controls.loadPid" />
```
**`open` / `value` / `copied` 三个状态全在组件内部**，调用方只提供"怎么取真值"（`controls.loadPid`，06 册 §6.4）。
> **这是"组件自治"的正面例子**：**一组互相纠缠的展示状态（遮蔽/明文/已复制）封在组件里**，对外只暴露"数据从哪来"。
> 它**不违反 R5** —— 它没 import store、没 import router，只是"自己管自己的显示状态"。

**② 两颗图标都是 `TextAction`**：
- 眼睛那颗走**默认插槽**（自绘 SVG，§2.1）；
- 复制那颗走**`text`**（`📋` / `✅` 是字符）→ **同一个组件两种内容形式**。

**③ 样式为什么这么写**：
```css
.secret { margin: 0; font-family: ui-monospace, Menlo, monospace; font-size: 0.78rem;
          color: #4b5563; word-break: break-all; }
.glyph { justify-content: center; padding: 2px 4px; font-size: 1rem; line-height: 1; color: #4b5563; }
```
- **等宽字体 + `word-break: break-all`**：20 位 base62 的 id 要能**逐字核对**，且长了要能换行（不撑破卡片）；
- **`.glyph` 覆盖 padding/font-size/color**：注释说"裸图标：没有框，也没有 hover 效果（就是普通文字）"—— 靠这几个覆盖让它看起来像**普通文字里的两个字符**，而不是按钮。

**④ 它故意不做什么**：
- **不做"复制成功"的提示条**（只把图标从 📋 变成 ✅，用 `useClipboard` 的 `copied`）；
- **不许自定义遮蔽字符**（固定 `▮×8`）；
- **不管"什么时候该遮蔽"**（那是页面的决定 —— 只通过 `revealed` 给初始值）。

## 6. `RenameText.vue`（79 行）—— 就地重命名（**零状态的受控组件**）

**① 它是谁**：「**一段文本 + 一个「重命名」**」；点"重命名"就地把文本换成输入框。
**谁在用它**：`MyPuzzleRow`（列表行标题）、`useAccountPanel` 所在的「我的」页账号区（显示名）—— **同一套键位、同一套样式**。

**契约**：

```ts
const props = defineProps<{
    /** 显示文本（列表行标题 / 「我的」页显示名） */
    text: string
    /** 文本前的小图标（账号区传 👤；不传就只有文本） */
    icon?: string
    /** 是否处于编辑态（父组件控制；编辑时文本位置换成输入框） */
    renaming: boolean
    /** 编辑中的文本 */
    renameText: string
    /** 最大长度（与常量一致） */
    maxlength: number
    placeholder: string
    /** 「重命名」四个字的文案来源（MINE_COPY / AUTH_COPY） */
    label: string
    /** 文本用什么标签渲染：标题传 'h3'，其余默认 span */
    tag?: string
}>()

const emit = defineEmits<{
    /** 点了「重命名」 */ start: []
    /** 输入变化 */ input: [value: string]
    /** 回车 / 失焦 → 提交 */ commit: []
    /** Esc → 取消 */ cancel: []
}>()
```

**② 它自己只有一个状态**：

```ts
/** 进入编辑态就聚焦（本组件常驻，输入框由内部 v-if 控制出现） */
const box = ref<HTMLInputElement | null>(null)
watch(() => props.renaming, async (on) => {
    if (!on) return
    await nextTick()
    box.value?.focus()
})
```

**这个 `watch + nextTick + focus` 是最值得学的一小段**：
- `renaming` 变 `true` 的那一瞬间，输入框**还没渲染出来**（模板里是 `v-if="renaming"`）→ 直接 `focus()` 会拿到 `null`；
- **`await nextTick()`**：等 Vue 把 DOM 更新完，`box.value` 才有值；
- **为什么不用 `onMounted`**：输入框是 `v-if` 出来的，**每次进入编辑态都是新元素**，不会触发"组件的 mounted" → 只能靠 `watch` 监听"编辑态开关"。

### 6.1 模板：两个分支 + 三个键位

```html
<span class="rename">
    <input v-if="renaming" ref="box" class="input rename-input" :value="renameText" :maxlength="maxlength"
        :placeholder="placeholder" @input="emit('input', ($event.target as HTMLInputElement).value)"
        @keyup.enter="emit('commit')" @keyup.esc="emit('cancel')" @blur="emit('commit')">

    <template v-else>
        <!-- 图标与文本一起插值，避免模板把 `{{ icon }}` 后面的空格吃掉 -->
        <component :is="tag ?? 'span'" class="rename-text" :title="text">{{ icon ? `${icon} ` : '' }}{{ text }}</component>
        <button class="text-btn" type="button" @click="emit('start')">{{ label }}</button>
    </template>
</span>
```

**① 三个键位/事件 = 一套完整的"就地编辑"语义**：

| 交互 | 事件 | 结果 |
|---|---|---|
| 回车 | `@keyup.enter` | `commit`（提交） |
| **失焦**（点别处、Tab 走） | `@blur` | `commit`（提交） |
| Esc | `@keyup.esc` | `cancel`（放弃修改） |

**"失焦也提交"是就地编辑的常见语义**（用户点了别处 = "我改完了"）；**Esc 才是不保存的出口**。

**② 为什么 Esc 不会"取消之后又被 blur 提交"**：
Esc → `emit('cancel')` → 父组件把 `renaming` 置 `false` → **输入框从 DOM 被移除**。
**元素从 DOM 移除时浏览器不会触发 `blur`** → 所以不会再有 `commit`。
> 这个细节很关键：**如果换个实现（用 `v-show` 隐藏而不是 `v-if` 卸载）**，Esc 之后紧接着就会触发 blur → **"取消"变成"提交"**（一个很难查的 bug）。

**③ `{{ icon ? `${icon} ` : '' }}{{ text }}` 为什么拼在一行插值里**（注释原文）：
> *"图标与文本一起插值，避免模板把 `{{ icon }}` 后面的空格吃掉"*

如果写成 `<span>{{ icon }}</span><span>{{ text }}</span>` 或 `{{ icon }} {{ text }}`：**HTML/模板的空白处理规则**（编译器会合并/裁剪标签间的空白）会让"图标后面的空格"时有时无。
**最稳的写法**：在 JS 里把空格拼进去 → 渲染结果完全可控。

**④ `<component :is="tag ?? 'span'">`**：
- 列表行标题传 `tag="h3"` → **语义上是标题**（读屏/大纲友好）；
- 账号显示名不传 → 默认 `<span>`（行内文本）。
**同一个组件两种语义层级**，靠一个可选 prop 决定。

**⑤ `:title="text"`**：长标题被 CSS 截断时，鼠标悬停能看到完整内容（**这里用的是传入的文本，不是自己编的文案** —— 符合 03 册 §6 那条"悬浮提示只在传入数据里有才用"）。
**⑥ 这里为什么不用 `TextAction`**：它用了一个 `<button class="text-btn" type="button">`。
原因：这个按钮**永远可点**（不存在"禁用态=纯文本"的需求）→ 直接复用全局类名就够，**少一层组件**。
（用 `TextAction` 也完全可以；这是"够用就好"的选择。）

### 6.2 样式：`flex: 1` + 与文本同高

```css
.rename { display: inline-flex; align-items: baseline; gap: 8px; min-width: 0; }
.rename-text { margin: 0; font-size: 0.95rem; font-weight: 600; color: #111827; word-break: break-all; }
.rename-input { flex: 1; height: 30px; font-size: 0.9rem; }
```
- **`height: 30px` 与 `font-size: 0.9rem`**：让输入框与原来的文本**视觉高度接近** → "就地替换"的感觉（不会突然撑高整行）；
- **`align-items: baseline`**：文本与「重命名」按**基线**对齐（不是中心对齐）→ 视觉更自然；
- **`min-width: 0`（在 flex 容器里）**：允许子项**收缩**（否则长标题会把"重命名"挤出容器）；
- **`word-break: break-all`**：超长标题能换行（不撑破卡片）。

## 7. `NumberPad.vue`（73 行）—— 数字键盘

**① 它是谁**：**点击输入数字的键盘**（游玩页与求解页共用）。
**契约**（注释原文：*"布局是纯样式，数据全部来自 props"*）：

```ts
const props = defineProps<{ max: number; columns: number }>()
const emit = defineEmits<{ pick: [n: number] }>()

/** 布局是纯样式，数据全部来自 props */
const gridStyle = computed(() => ({
    gridTemplateColumns: `repeat(${props.columns}, minmax(0, 1fr))`,
}))
```

```html
<div class="num-pad-wrapper">
    <div class="num-grid" :style="gridStyle">
        <button v-for="n in max" :key="n" class="num-btn" @click="emit('pick', n)" title="单击填入数字">

    </div>
```

**② 三个值得记的点**：

| 点 | 说明 |
|---|---|
| **`v-for="n in max"`** | Vue 支持"数字范围循环"→ 直接产出 `1..max`（**不需要** `Array.from` / `new Array`） |
| **`columns` 控制每行几个** | 由页面传 `padColumns = sudoku.B`（06 册 §7）→ **与宫宽对齐**（9×9 的键盘是 3 列，16×16 是 4 列），数字排列与盘面结构呼应 |
| **"清除"走同一个 `pick` 通道（`pick(0)`）** | 页面对"填数字"和"清除"**不需要两套事件** —— 0 就是"空"（05 册 §2.16 ⑥：`inputNum(0)` 会清格，且 `cell.v === n` 顺带挡住空清除） |

**③ `gridStyle` 用 computed 而不是模板里拼字符串**：
`repeat(${columns}, minmax(0, 1fr))` 是"**每列等宽且能收缩**"的标准写法（`minmax(0, 1fr)` 防止内容把网格撑破）→ **放在 computed 里便于阅读与测试**。

**④ ⚠️ 一处值得注意的不一致（可收口点）**：
这两处 `title` 是**硬编码的中文文案**：
```html
title="单击填入数字" / title="清除当前格数字"
```
按 03 册 §六 的归位原则（*"悬浮提示 / 无障碍名 → 只在传入数据里有才用；没给就不加（**不自行发明文案**）"*），**这里偏离了规则**。
**要严格统一的话**：应提到 `constants`（例如 `GAME_COPY.padHint`），或由页面作为 prop 传入。
> **发现这类不一致，本身就是"读懂项目"的标志** —— 规则活在文档里，而实现总会有几个漏网之鱼；把漏网的地方记下来，比"假装完全一致"有价值得多。

**⑤ 样式细节**：
```css
.num-btn { width: 32px; height: 32px; border-radius: 50%; border: 2px solid #d1d5db; … transition: 0.15s; }
.num-btn:hover { background: #eef2ff; border-color: #6366f1; }
```
**圆形小按钮 + hover 变主色**（与全局主色 `#6366f1` 一致）；`clear-btn` 只把字号放大一点（用 `X` 表示清除）。
**网格居中**：`.num-grid { width: fit-content; margin: 0 auto }` —— 让"3 列的数字区"整体居中，而"清除"按钮单独在上方/下方居中（`flex-direction: column` + `align-items: center`）。

## 8. 分页三件：`PagerBar` + 两个形态组件

**① 分工**：`PagerBar` 是**外壳**（决定"要不要显示、点了要发什么"），两个 `Pager*View` 是**形态**（进度条 / 滑动条 / 步骤条）。

```
PagerBar（外壳：visible / go 归一化 / 进度条形态）
  ├─ PagerSliderView（滑动条形态）
  └─ PagerStepsView（步骤条形态）
```

### 8.1 `PagerBar.vue`（65 行）—— "一分支一形态" + **索引语义归一化**

```ts
const props = defineProps<{
    page: number
    pageCount: number
    /** 浏览方式（进度条 / 滑动条 / 步骤条）—— 只报数据，怎么画由本组件决定 */
    mode: PagerMode
    /** 步骤条用：每一步的文案（不传就显示下标） */
    stepLabel?: (index: number) => string
    /** 步骤条用：信息行文案（不传 = 历史步数语义） */
    infoText?: string
}>()

const emit = defineEmits<{ change: [page: number] }>()

/** 步骤条只有 1 步也显示（历史记录），分页条要在 2 页以上才出现 */
const visible = computed(() => props.pageCount > (props.mode === PAGER_MODE.Steps ? 0 : 1))

/** 越界 / 原地不动就不发（三种渲染方式的交互都走这里）
 *  页码从 1 开始 → 最大 = pageCount；步骤从 0 开始 → 最大 = pageCount - 1 */
const go = (next: number): void => {
    const steps = props.mode === PAGER_MODE.Steps
    const min = steps ? 0 : 1
    const max = steps ? props.pageCount - 1 : props.pageCount
    if (next < min || next > max || next === props.page) return
    emit('change', next)
}
```

**② `go`：本组件最值得学的一段（两种索引语义的归一化）**

**问题**：同一个组件要服务两种完全不同的"位置"语义：

| 形态 | 索引 | 范围 | 例子 |
|---|---|---|---|
| 分页（进度条 / 滑动条） | **1-based 页码** | `1 .. pageCount` | 搜索页"第 2 页 / 共 5 页" |
| 步骤条 | **0-based 步号** | `0 .. pageCount-1` | 游戏页历史"第 0 步（开局）… 第 3 步" |

`go` 用两行把差异**收在一个函数里**：
```ts
const steps = props.mode === PAGER_MODE.Steps
const min = steps ? 0 : 1
const max = steps ? props.pageCount - 1 : props.pageCount
```
**收益**：**两个形态子组件都只管"我想跳到第 k 个"，不用知道自己是哪种语义**；对外也只有**一个 `change` 事件**。
> **这就是"把差异收口在一个地方"** —— 与 04 册的 `visibilityOf`（三态白名单）、06 册的 `useListQuery`（`load` 注入）是同一手法在不同层的应用。

**③ `if (… || next === props.page) return`**：**"原地不动不发"** —— 与 06 册 §8.2 那条纪律同源（防无意义动作/请求；这里还防"点当前页导致重新请求"）。

**④ `visible` 为什么两种阈值**（注释原文）：
- **分页条**：`pageCount > 1` 才显示 —— 只有 1 页时"1 / 1"毫无意义；
- **步骤条**：`pageCount > 0` 就显示 —— **即使只有"第 0 步"也要显示**（它是历史记录的入口/状态显示，本身有信息量）。

**⑤ 模板：三分支（一分支一形态）**

```html
<Flex v-if="visible" class="pager" :gap="10" justify="center">
    <!-- 滑动条：拖动 · 键盘左右 -->
    <PagerSliderView v-if="mode === PAGER_MODE.Slider" :page="page" :page-count="pageCount" @change="go" />

    <!-- 步骤条：一串可点选的步骤（游戏页历史记录） -->
    <PagerStepsView v-else-if="mode === PAGER_MODE.Steps" :page="page" :page-count="pageCount"
        :step-label="stepLabel" :info-text="infoText" @change="go" />

    <!-- 进度条（默认）：上一页 / 页码 / 下一页 —— 都是可点击文本 -->
    <template v-else>
        <TextAction text="上一页" :on-click="page > 1 ? () => go(page - 1) : undefined" />
        <span class="pager-info">{{ page }} / {{ pageCount }}</span>
        <TextAction text="下一页" :on-click="page < pageCount ? () => go(page + 1) : undefined" />
    </template>
</Flex>
```

**⑥ 两个子组件都把 `@change="go"` 直接接上**：**归一化只在这里发生一次**（子组件不需要再判断语义）。

**⑦ 上一页/下一页的"到界禁用"**：
```html
:on-click="page > 1 ? () => go(page - 1) : undefined"
```
**到第 1 页时 `onClick` 是 `undefined`** → `TextAction` 渲染成**纯文本**（不聚焦、没有 hover 下划线）——**§2.1 那个契约在这里被用上了**。
**注意 `go` 里其实也有边界判断**（`next < min` 会 return）→ **两层防护**（组件层的 UI 禁用 + 逻辑层的守卫）。

**⑧ `:mode` 的取值来自 `constants/puzzle.ts` 的 `PAGER_MODE`**（`'bar' | 'slider' | 'steps'`，00 册 §4.3 的字面量联合）：
- **`PAGER_MODE.Bar` 是"默认分支"**（`v-else`）→ 因为它**没有独立子组件**（三个 `TextAction` 就够了，不值得为它拆一个文件）。
> **"什么值得拆成文件"的判断**：**有独立布局逻辑的**（滑动条/步骤条有各自的滚动、样式、交互）就拆；**三行模板能写完的**（进度条）就内联。

### 8.2 `PagerSliderView.vue`（31 行）—— 滑动条形态

```ts
defineProps<{
    /** 当前页 */ page: number
    /** 总页数 */ pageCount: number
}>()

const emit = defineEmits<{ change: [page: number] }>()

const onSlide = (e: Event): void => { emit('change', Number((e.target as HTMLInputElement).value)) }
```
```html
<input class="pager-slider" type="range" min="1" :max="pageCount" :value="page" @input="onSlide">
<span class="pager-info">{{ page }} / {{ pageCount }}</span>
```

**三个点**：
1. **`min="1"` 写死** —— 这是**页码语义**（1-based）；`max` 来自 props；
2. **`:value + @input` 而不是 `v-model`** —— 组件是**受控的**：值由父组件给（`page`），变化只是"通知"（`emit`），**父组件才是真源**。**`v-model` 在这里反而不合适**（它暗示"组件自己改值"）；
3. **`Number(...)` 转换**：`input.value` 是字符串（与 §3.3 `FormField` 的 `onValue` 同一个坑）→ 这里没有选项表可查，所以直接 `Number`。
   样式只有两行关键：`flex: 1`（占满外壳给的空间）+ `accent-color: #6366f1`（**一行给原生 range 上主题色**，现代浏览器直接支持）。

### 8.3 `PagerStepsView.vue`（127 行）—— 步骤条形态（历史记录专用）

```ts
const props = defineProps<{
    /** 当前步（从 0 开始） */ page: number
    /** 总步数（= 快照数） */ pageCount: number
    /** 每一步的文案（不传就显示下标） */ stepLabel?: (index: number) => string
    /** 信息行文案（不传 = 历史步数语义 page / pageCount - 1） */ infoText?: string
}>()

const emit = defineEmits<{ change: [page: number] }>()

/** 信息行：默认沿用历史步数语义，调用方给了 infoText 就用它 */
const info = computed<string>(() => props.infoText ?? (props.page + ' / ' + (props.pageCount - 1)))

const stepsEl = ref<HTMLElement | null>(null)
const labelOf = (index: number): string => props.stepLabel?.(index) ?? String(index)
/** 当前步高亮、后面的步骤置灰 */
const classOf = (step: number): Record<string, boolean> => ({ active: step === props.page, future: step > props.page })

/** 当前步变化后把它滚进视野，否则步数多时看不到「当前步」 */
watch(() => props.page, async () => {
    await nextTick()
    stepsEl.value?.querySelector('.step-block.active')?.scrollIntoView({ inline: 'nearest', block: 'nearest' })
})
```

```html
<div ref="stepsEl" class="steps">
    <button v-for="i in pageCount" :key="i - 1" type="button" class="step-block" :class="classOf(i - 1)"
        @click="emit('change', i - 1)">
        {{ labelOf(i - 1) }}
    </button>
</div>
<span class="pager-info">{{ info }}</span>
```

**① `info` 的默认值为什么是 `pageCount - 1`**（把 05 册 §2.9 的历史机制对上）：
`PagerBar` 的 `:page-count="gameStore.snapshots.length"` —— **快照数**（N 张）。
而**步数**是 N-1：因为**第 0 张快照是"开局那一刻"**（`resetHistory` 建的，不算"走了一步"）。
所以信息行显示 `当前步 / (快照数 - 1)` —— 例如"3 / 5"表示"走了 3 步，一共走过 5 步"。
**注释也写明了**："不传 = 历史步数语义"；如果别的场景想要别的文案，就传 `infoText`（可选覆盖）。

**② `scrollIntoView({ inline: 'nearest', block: 'nearest' })` —— 一小段很实用的代码**

```ts
watch(() => props.page, async () => {
    await nextTick()
    stepsEl.value?.querySelector('.step-block.active')?.scrollIntoView({ inline: 'nearest', block: 'nearest' })
})
```
| 要点 | 说明 |
|---|---|
| **`watch(page)` + `nextTick`** | `classOf` 依赖 `page` → **要等 DOM 把 `.active` 类更新上去**再去找它（同 §6 的 `focus` 一样的时序问题） |
| **`inline: 'nearest'`** | 横向滚动时**最小化滚动**：当前步已经可见就不动，否则滚到最近边缘（而不是粗暴地滚到最左） |
| **`block: 'nearest'`** | 纵向同理（这里其实用不上，但写上更稳） |
| **`?.`** | 找不到元素（例如列表已卸载）也不报错 |

**为什么需要它**：玩法中途步数可能有几十步 → 步骤条横向滚动 → **不自动滚动的话，用户看不到"我现在在哪一步"**（当前步滑到了视野外）。

**③ `v-for="i in pageCount"` + `:key="i - 1"` + `emit('change', i - 1)`**：
`v-for` 从 1 开始计数 → **`i - 1` 就是 0-based 的步号**（与 `PagerBar.go` 的 `min = 0` 对上）。
`:key` 用 `i - 1`（步号）而不是 `i` —— **key 要和"业务身份"一致**（否则将来加删步骤时 diff 会错位）。

**④ `labelOf`：不传 `stepLabel` 就显示下标**
```ts
const labelOf = (index: number): string => props.stepLabel?.(index) ?? String(index)
```
游戏页传的是 `stepLabel = (i) => `${i}步``（01 册 §1.4 的 `GamePage`）；求解页传的是 `解 ${i+1}`（06 册 §7 ⑩）。
**默认值是"0 / 1 / 2…"这样的下标** —— 够用，但**不瞎编文案**（符合"没有就显示最朴素的东西"的原则）。

**⑤ `classOf` 的两个类（含 `future` 的语义）**

```ts
const classOf = (step: number): Record<string, boolean> => ({ active: step === props.page, future: step > props.page })
```
| 类 | 样式 | 含义 |
|---|---|---|
| `active` | 主色填充 + 白字 + 加粗 | 当前步 |
| `future` | 极浅灰底 + 灰字 | **"未来"的步骤**（用户曾走到过、又回退掉的） |

**关键理解**：`future` 的步骤**仍然可以点**（`@click` 没有条件）——
因为**快照还在 `snapshots` 里**（`jump` 只是移动 `currentStep`，`pushHistory` 才截断，05 册 §2.9）→ **点"未来"= 重做**。
**置灰只是视觉提示**（"这些是你已经回退掉的"），**不是禁用**。

**⑥ 横向滚动容器与"统一滚动条风格"**

```css
.steps { display: flex; flex: 1; flex-wrap: nowrap; gap: 6px; min-height: 46px; padding: 4px 0 8px;
         overflow-x: auto; overflow-y: hidden; box-sizing: border-box; … }
.steps::-webkit-scrollbar { height: 12px; background: #f1f5f9; border-radius: 6px; }
.steps::-webkit-scrollbar-thumb { background: #94a3b8; border-radius: 6px; }
```
- **`flex-wrap: nowrap` + `overflow-x: auto`**：**不换行、横向滚动**（步骤条的经典布局）；
- **`flex: 0 0 auto`（在 `.step-block` 上）**：每颗步骤块**不收缩**（否则会被压扁成竖条）；
- **自定义滚动条（`::-webkit-scrollbar*` + `scrollbar-width`/`scrollbar-color`）**：与 `BoardView` 的滚动框**同一套视觉**（深灰圆角条 + 浅灰轨道）。
> **"跨页共用的视觉规格"本该进全局样式**（03 册归位原则）—— **这里是个可收口点**：滚动条样式目前在 `BoardView` 与 `PagerStepsView` 里各写了一遍（外加全局或组件级），将来可以抽成 `styles/*.css` 里的一组公共类。

**⑦ `.step-block` 的尺寸与交互**：
```css
.step-block { flex: 0 0 auto; min-width: 44px; height: 32px; padding: 0 8px; border-radius: 6px;
              border: 1px solid #e2e8f0; background: #f8fafc; … cursor: pointer; transition: all 0.15s; }
.step-block:hover { background: #eef2ff; border-color: #a5b4fc; }
```
- **`min-width: 44px`**：`44px` 是**触屏最小可点尺寸**的常用经验值（Apple HIG 的 44pt）→ 步骤块即使只有一个字符也不会太小；
- **`height: 32px` + `border-radius: 6px`**：与全局按钮/卡片风格一致（不尖、不圆得夸张）；
- **`transition: all 0.15s`**：hover/active 切换的轻微过渡（不拖沓）。

## 9. `ListSection.vue`（68 行）—— 列表骨架（**唯一的泛型组件**）

**① 它是谁**：**搜索页与我的题目页共用的列表骨架**：页头工具条 + 三态 + 条目（插槽）+ 分页。
**为什么要抽它**：两个列表页的"骨架"完全一样（工具条两个下拉、加载/错误/空三态、`<ul>` + 分页）；不同的只有**条目长什么样**（`PuzzleCard` vs `MyPuzzleRow`）和**数据从哪来**。

**契约**（注意第一行的 `generic="T"`）：

```html
<script setup lang="ts" generic="T">
const props = defineProps<{
    /** 列表数据（每一项交给 #item 插槽自己渲染） */
    items: readonly T[]
    loading: boolean
    error: string
    /** 空态文案（空态里的动作走 #empty 插槽） */
    emptyText: string
    /** 列表项的 key（默认按下标） */
    keyOf?: (item: T, index: number) => string | number

    /** 页头工具条：左「浏览方式」、右「排序」—— 标签/选项都由调用方给，组件不认识业务常量 */
    bar: ListBar
    /** 分页数据（怎么画由 PagerBar 按渲染表决定） */
    pager: ListPager
}>()

const emit = defineEmits<{
    /** 错误态里的「重试」 */ retry: []
    changeMode: [value: string]
    changeSort: [value: string]
    changePage: [page: number]
}>()

/** 默认按下标做 key（列表整体替换时够用；有稳定 id 的调用方传 keyOf） */
const keyOf = (item: T, index: number): string | number => props.keyOf?.(item, index) ?? index
```

**② `generic="T"`：本项目的泛型组件（唯一一处）**

```html
<script setup lang="ts" generic="T">
```
- **没有它**：`items` 只能是 `any[]`（或 `unknown[]`）→ 调用方传错、`keyOf` 里 `item` 没有类型；
- **有了它**：`items: readonly T[]` —— **`T` 在调用处由实际传入的数组推断出来**（与 00 册 §4.9 的泛型函数同一个道理，只是这里作用于组件）；
- 于是 `keyOf` 的签名 `(item: T, index: number)` 能**精确到具体元素类型**。

> **知识点**：Vue 3.3+ 支持 `<script setup generic="…">`。**它解决的是"组件本身与元素类型无关，但又要保持类型安全"的场景** —— 列表、表格、下拉这类"容器型组件"最需要它。

**③ `bar` / `pager`：把散装 props 收成两个数据对象**

`ListSection` 的 props 从 12 个降到 6 个（`REQUIREMENTS.md` 决策 56 记录的那次重构），关键就是这两行：

```ts
/** 页头工具条：左「浏览方式」、右「排序」—— 标签/选项都由调用方给，组件不认识业务常量 */
bar: ListBar
/** 分页数据（怎么画由 PagerBar 按渲染表决定） */
pager: ListPager
```
`ListBar` / `ListPager` 定义在 `types/item.ts`，形状大致是：

| 对象 | 字段 | 由谁提供 |
|---|---|---|
| `bar` | `modeLabel` / `mode` / `modeOptions` / `sortLabel` / `sortOptions` | **页面**（标签与选项都来自 `constants`，但组件不认识它们） |
| `pager` | `page` / `pageCount` / `mode` | **页面**（`mode` 来自本地偏好/URL） |

**"组件不认识业务常量"是这句话的重点**（注释原文）：
如果 `ListSection` 自己 import `SORT_OPTIONS` / `PAGER_MODE_OPTIONS`，它就**和"题目列表"这个概念绑死了** → 换个场景（比如将来的"我的收藏"）就不能复用。
**现在它只认 `{label, value}[]` 这种形状** → **完全通用**。

**④ 模板：工具条 + 三态 + 条目 + 分页**

```html
<div class="list-section">
    <!-- 页头工具条：两个下拉都用通用 FormField(type='select') -->
    <div class="list-bar">
        <FormField type="select" compact :label="bar.modeLabel" :options="bar.modeOptions"
            :model-value="bar.mode" @update:model-value="(v) => emit('changeMode', String(v))" />
        <FormField type="select" compact :label="bar.sortLabel" :options="bar.sortOptions"
            :model-value="bar.sort" @update:model-value="(v) => emit('changeSort', String(v))" />
    </div>

    <!-- 调用方额外的页头内容（如搜索命中的出题人） -->
    <slot name="top" />

    <!-- 三态：加载中 / 错误（可重试）/ 空（可带动作） -->
    <p v-if="loading" class="state">加载中…</p>
    <p v-else-if="error" class="state is-error">
        {{ error }}
        <button class="retry" type="button" @click="emit('retry')">重试</button>
    </p>
    <p v-else-if="!items.length" class="state">
        {{ emptyText }}
        <slot name="empty" />
    </p>

    <ul v-else class="list">
        <li v-for="(item, i) in items" :key="keyOf(item, i)">
            <!-- 条目交给调用方选渲染方式：私人列表 → MyPuzzleRow / 公开列表 → PuzzleCard -->
            <slot name="item" :item="item" />
        </li>
    </ul>

    <PagerBar :page="pager.page" :page-count="pager.pageCount" :mode="pager.mode"
        @change="emit('changePage', $event)" />
</div>
```

**⑤ 三个插槽（各司其职）**：

| 插槽 | 用途 | 真实调用 |
|---|---|---|
| `#top` | 追加页头内容（在工具条下方） | 搜索页的"出题人：X 的公开题"表头 |
| `#item`（带 `:item`） | **条目渲染方式由调用方选** | `<template #item="{ item }"><PuzzleCard :item="item" /></template>` |
| `#empty` | 空态里的动作 | 我的题目页的"去出题 →"按钮 |

**`#item` 的 `:item="item"` 是"作用域插槽"**：**列表骨架不知道每一项是什么类型**（泛型 `T`），于是**把 item 原样递出去**，让调用方决定怎么画。
> **这正是"传数据 + 传渲染方式"哲学在列表上的体现**（01 册 §1.8、03 册 R8）：**骨架管结构，条目管内容。**

**⑥ 三态用 `v-if / v-else-if / v-else` 串起来**：
- **三态互斥**（不会同时出现"加载中"和"空"）—— 这是**互斥状态必须用同一串条件分支**的意义；
- **错误态带"重试"按钮**（`emit('retry')`）→ 页面接到 `list.retry()`（06 册 §2.4）；
- **`<ul>/<li>` 而不是一堆 div**：**语义上是列表**（读屏会念"列表，N 项"），且 `<li>` 天然是列表项。

**⑦ 分页永远是 `PagerBar` 的最后一块**（`v-if="visible"` 在 `PagerBar` 内部判断，§8.1）→ **`ListSection` 不需要自己判断"要不要显示分页"**。
> **职责链**：`ListSection` 给 `PagerBar` 三个数据（page / pageCount / mode）→ `PagerBar` 自己决定"显不显示、画哪种形态、点了发什么"。

## 10. 两种列表项：`MyPuzzleRow`（101 行）与 `PuzzleCard`（47 行）

**① 为什么要两种**（而不是一个组件加一堆 `v-if`）：

| | `MyPuzzleRow`（私人） | `PuzzleCard`（公开） |
|---|---|---|
| 用在 | 我的题目页 | 搜索页 |
| 选项 | **多**：重命名、可见性下拉、答案下拉、pid 遮蔽/复制、预览、答案预览、挑战、编辑、删除 | **少**：预览、挑战 |
| 数据 | `MyPuzzle`（含 `rowId`、`visibility`、`showSolution`） | `SearchResult`（含 `pid`、`uname`） |
| 动作传递方式 | **`controls` 控件包**（13 个回调） | **`emit`**（2 个事件） |

**判据（本册会反复用）**：
> **回调少（≤2~3 个）→ 用 `emit`；多到一整套"行内控件"→ 用 `controls` 打包**（06 册 §6.4 的 `controlsFor` 工厂）。
> **硬把它们合成一个组件**：要传十来个 `v-if` 开关 + 一大堆可选 props → 谁都不敢改（这正是 `REQUIREMENTS.md` 决策 56 里"列表项不再分层"的由来）。

### 10.1 `MyPuzzleRow`（私人列表项）

**契约**：

```ts
const props = defineProps<{
    item: MyPuzzle
    /** 行内控件（可见性 / 参考答案下拉、内联重命名、预览、挑战、编辑、删除、pid 取值） */
    controls: MyPuzzleRowControls
}>()
```

**两个 prop 就够**：`item`（数据）+ `controls`（一整套回调，由 `useMyPuzzles.controlsFor(item)` 现场生成，06 册 §6.4）。

**① `metaTextOf(props.item)` —— 直接传 item 就行（形状兼容的好处）**

```ts
const metaText = computed<string>(() => metaTextOf(props.item))
```
`metaTextOf(parts: MetaParts)` 只要求 `{ sideS, blankCount, createdAt, playCount?, author? }`（06 册 §2.3）；
而 `MyPuzzle` 有 `sideS / blankCount / createdAt / playCount`，**没有 `author`** → 结构上兼容 ✅。
**顺带的效果**：**"我的题目"列表不显示出题人**（因为 `author` 缺省）—— **正好符合语义**（都是自己的题）。
> **"形状兼容 + 可选字段"让组件不需要中间转换层** —— 这是把 `MetaParts` 的可选字段设计成"不传就不显示"带来的直接收益（06 册 §2.3 ④）。

**② 两个"可写 computed"：读 item、写回走 controls（**本组件最值得学的一招**）**

```ts
/** 两个设置下拉都用可写 computed：读 item、写回走 controls（落库） */
const visPick = computed<Visibility>({
    get: () => props.item.visibility,
    set: (value) => props.controls.onVisibility(value),
})

const solutionPick = computed<string>({
    get: () => (props.item.showSolution ? SOLUTION_VALUE.On : SOLUTION_VALUE.Off),
    set: (value) => props.controls.onSolution(value === SOLUTION_VALUE.On),
})
```

**它解决的问题**：
- `FormField` 需要 `v-model`（`modelValue` + `update:modelValue`）；
- 但**数据的真源在 store**（通过 props 传进来），而**组件不能直接改 props**（Vue 单向数据流）；
- **可写 `computed` 恰好是那个"适配器"**：`get` 从 props 读、`set` 调回调 → **`v-model="visPick"` 直接用**，而"改数据"这件事交给了 composable（也就走了后端 PATCH）。

```html
<FormField v-model="visPick" type="select" compact :label="MINE_COPY.visibilityLabel"
    :options="PUZZLE_VISIBILITY_OPTIONS" :width="SELECT_WIDTH" />
```

**`SOLUTION_VALUE.On / Off`（`'on'` / `'off'`）为什么存在**：
`<select>` 的值是字符串（§3.3 同一个坑），而 `showSolution` 是布尔 → **用两个字符串代表布尔**，`set` 里再转回 `true/false`。
（`constants/puzzle.ts` 的注释也写了："布尔用 on / off 便于 `<select>` 绑定"。）

**③ 三组 `Actions` 都用 computed 生成**

```ts
/** 右上角：删除 · 编辑（左删除右编辑） */
const cornerItems = computed<Actions>(() => [
    { key: 'remove', text: MINE_COPY.remove, onClick: props.controls.onRemove },
    { key: 'edit', text: MINE_COPY.edit, onClick: props.controls.onEdit },
])
/** 题目预览 / 答案预览（同一行的纯文字） */
const previewItems = computed<Actions>(() => [
    { key: 'preview', text: MINE_COPY.preview, onClick: () => props.controls.onPreview(false) },
    { key: 'answer', text: MINE_COPY.answerPreview, onClick: () => props.controls.onPreview(true) },
])
/** 挑战：本行唯一的动作 */
const challengeItems = computed<Actions>(() => [
    { key: 'challenge', text: `▶ ${MINE_COPY.challenge}`, onClick: props.controls.onChallenge },
])
```
**为什么要用 `computed` 而不是普通常量数组**：`controls` 对象**每次父组件渲染都会重建**（`controlsFor(item)` 返回新对象）→ `computed` 保证模板每次都拿到**最新的回调**（普通常量会闭包住第一次那个）。
**注意"预览 / 答案预览"共用一个回调、只传一个布尔**（`onPreview(false/true)`）→ **接口最小化**（一个回调服务两个按钮）。
**"挑战"单独一组**：因为它是本行**唯一的强调动作**，模板里被放到最右。

**④ 模板结构（四层，全用已有的通用件搭）**

```html
<article class="item-card">
    <Flex class="item-head" align="baseline" justify="between" :gap="8">
        <div class="item-title-line">
            <RenameText :text="item.title" :renaming="controls.renaming" :rename-text="controls.renameText"
                :maxlength="TITLE_MAX" :placeholder="MINE_COPY.renamePlaceholder" :label="MINE_COPY.rename"
                tag="h3" @start="controls.onRenameStart()" @input="controls.onRenameInput"
                @commit="controls.onRenameCommit()" @cancel="controls.onRenameCancel()" />
        </div>
        <Flex class="item-corner" :gap="6">
            <TextAction v-for="a in cornerItems" :key="a.key" :text="a.text" :on-click="a.onClick" />
        </Flex>
    </Flex>

    <p class="meta-line">{{ metaText }}</p>

    <SecretValue :label="MINE_COPY.pidTag" :load="controls.loadPid" />

    <Flex justify="between" :gap="12" wrap>
        <FormField v-model="visPick" type="select" compact :label="MINE_COPY.visibilityLabel"
            :options="PUZZLE_VISIBILITY_OPTIONS" :width="SELECT_WIDTH" />
        <FormField v-model="solutionPick" type="select" compact :label="MINE_COPY.solutionLabel"
            :options="SOLUTION_OPTIONS" :width="SELECT_WIDTH" />
    </Flex>

    <Flex class="op-bar" justify="between" :gap="12">
        <Flex :gap="6">
            <TextAction v-for="a in previewItems" :key="a.key" :text="a.text" :on-click="a.onClick" />
        </Flex>
        <TextAction v-for="a in challengeItems" :key="a.key" :text="a.text" :on-click="a.onClick" />
    </Flex>
</article>
```
**读这段要看出**：**它把 5 个通用件拼起来**（`Flex` / `RenameText` / `SecretValue` / `FormField` / `TextAction`），**自己没有写一行模板逻辑**（没有业务 `v-if`、没有计算、没有自定义元素）。

**⑤ 它的 `<style scoped>` 是空的（只有注释）**

```html
<style scoped>
/* 列表项外壳 .item-card/.item-head/.item-title-line/.item-corner 来自全局 styles/card.css；
   间距与对齐由 Flex 给，这里不再需要样式 */
</style>
```
**这是一个"设计到位"的信号**：**样式全部来自"全局类 + `Flex` 的 props"** → 组件**一条 CSS 都不需要写**。
> 对比常见写法：每个列表项各自写 `padding / margin / display:flex / gap / align-items` → 想调个间距要改 N 个文件。
> **这里间距全是 `:gap="8"` 这样的字面参数**：一眼可见、一处可改、不需要查 CSS。

### 10.2 `PuzzleCard`（公开列表项）

```ts
const props = defineProps<{ item: SearchResult }>()
const emit = defineEmits<{ preview: [pid: string]; challenge: [pid: string] }>()

/** 元信息行文本（组件只画一行；文案与时间格式在 metaTextOf 一处） */
const metaText = computed<string>(() => metaTextOf(props.item))

const actions = computed<Actions>(() => {
    const preview: Action = {
        key: 'preview', text: `👁 ${SEARCH_COPY.preview}`,
        onClick: () => emit('preview', props.item.pid),
    }
    const challenge: Action = {
        key: 'challenge', text: `▶ ${SEARCH_COPY.challenge}`,
        onClick: () => emit('challenge', props.item.pid),
    }
    return [preview, challenge]
})
```
```html
<article class="item-card">
    <Flex class="item-head" align="baseline" justify="between" :gap="8">
        <div class="item-title-line">
            <h3 class="item-title" :title="item.title">{{ item.title }}</h3>
        </div>
    </Flex>

    <p class="meta-line">{{ metaText }}</p>

    <Flex class="op-bar" :gap="6" justify="center">
        <TextAction v-for="a in actions" :key="a.key" :text="a.text" :on-click="a.onClick" />
    </Flex>
</article>
```

**① 为什么用 `emit` 而不是 `controls`**：
只有两个动作（预览 / 挑战）→ **两个 emit 就够了**，不需要打包（判据见本节开头）。
**`emit('preview', props.item.pid)` 的语义**：**组件只报"用户点了哪道题的预览"**，不决定"怎么打开"。
接法链条（06 册 §6.3）：`@preview="openPreview"` → `useSearchPuzzle.openPreview(pid)` → `usePuzzlePreview.showPreview(...)`。
> **这就是"组件不碰 router / store"的完整链条**：组件 → emit → 页面 → composable → 遮罩。

**② 连 `<style>` 块都没有**：
`PuzzleCard.vue` 全文 47 行，**没有 `<style>`** —— 完全靠全局 `.item-card` / `.item-title` / `.meta-line` / `.op-bar` + `Flex`。
**这是"两种列表项能共享视觉"的最直接原因**：**视觉在全局，结构在组件。**

**③ `metaTextOf(props.item)` 这里不会显示出题人（有意如此）**：
`SearchResult` 的字段是 `uname`，而 `MetaParts` 的字段名是 `author` → **传进去后 `author` 是 `undefined` → 不显示**。
**所以"出题人"是靠列表页的 `#top` 插槽在页头说一次**（06 册 §6.3 的 `authorLabel`），而不是每行重复"出题人：X"。
> **这是个很好的界面判断**：搜索"某人的题"时，**出题人在页头说一次就够**（每行重复既啰嗦又占宽度）。

**④ 两种列表项的对照（本节小结）**：

| | `MyPuzzleRow` | `PuzzleCard` |
|---|---|---|
| props | `item` + `controls` | `item` |
| emits | 无 | `preview` / `challenge` |
| 标题 | `RenameText`（可就地改名） | 纯 `<h3>`（公开题不能改名） |
| 额外块 | `SecretValue`（pid）+ 两个下拉 | 无 |
| 动作 | 6 组（角标 2 + 下拉 2 + 预览 2 + 挑战 1） | 2 个 |
| `<style>` | 空（只有注释） | **完全没有 style 块** |
| 元信息 | 不显示出题人（自己） | 出题人在页头（`#top` 插槽） |

## 11. `BoardView.vue`（135 行）—— 棋盘（**只读 / 可玩双形态**）

> 01 册 §3 从"浏览器平台"角度讲过它（canvas / DPR / ResizeObserver）。这里从**组件契约**角度把它讲完。

**① 它是谁**：**唯一画棋盘的组件**，两种形态：
| 形态 | `interactive` | 用在哪 |
|---|---|---|
| 可玩 | `true`（默认） | 游戏页游玩盘、求解页输入盘 |
| **只读** | **`false`** | 参考答案遮罩、预览遮罩、求解页结果盘 |

### 11.1 契约（`withDefaults` + 7 个 props）

```ts
const props = withDefaults(
    defineProps<{
        board: Board
        boxSize: number
        selected?: Position | null
        conflictMask?: ConflictMask
        zoom?: number
        /** 可玩（接点击）还是只读（纯 canvas 画出来）；默认可玩 */
        interactive?: boolean
        /** 缩放按钮的数据（`useZoom().zoomActions`）：给了就在棋盘正上方画一对，左缩小右放大 */
        zoomActions?: Actions
    }>(),
    { selected: null, zoom: BOARD_ZOOM.min, interactive: true },
)

const emit = defineEmits<{ 'cell-click': [pos: Position] }>()
```

**`board` / `boxSize` 是必填，其余 5 个都可选** —— 这正好对应"**最小可用** + **按需增强**"：
- 只要给盘面和宫宽就能画（预览场景）；
- 给 `selected` / `conflictMask` 就有选中框与红底（游玩场景）；
- 给 `zoomActions` 才有缩放按钮（**R14 要求有棋盘必须有缩放**，但"给不给"由页面决定数据）。

**它只有一个事件**：`cell-click`（只读时不发，见下）。

### 11.2 两个 DOM ref + 交给 composable

```ts
const canvasEl = ref<HTMLCanvasElement | null>(null)
/** 外层滚动框：量它（canvas 的直接父级会随棋盘收缩，量它会把当前宽度当上限） */
const boxEl = ref<HTMLElement | null>(null)
const { onCanvasClick } = useBoardCanvas(canvasEl, boxEl, () => props, pos => emit('cell-click', pos))
```

**三行代码，三个关键点**：
| 行 | 说明 |
|---|---|
| `canvasEl` | **模板 ref**（`<canvas ref="canvasEl">`）→ 指向真实 DOM（01 册 §3.1） |
| `boxEl` | **外层滚动框的 ref**，注释解释了"为什么量它"（01 册 §3.4 的**反馈循环**） |
| `useBoardCanvas(canvasEl, boxEl, () => props, …)` | **把画布交给 composable**；**`() => props` 是"取值函数"**（01 册 §1.11 坑 2：保证重绘时读到最新 props）；**emit 包成回调传进去**（`pos => emit('cell-click', pos)`） |

> **注意最后一个参数**：`useBoardCanvas` 只要求"点击时给我坐标"，**"发什么事件"由组件决定** → 组件把 `pos` 转成 `emit('cell-click', pos)`。
> **composable 不知道有 emit 这回事**，组件也不知道 canvas 是怎么画的 —— **两层都保持通用**。

### 11.3 模板：三个细节

```html
<div class="board-box">
    <!--
      缩放：**固定在棋盘上方、水平居中** —— 放在滚动框外面，
      所以棋盘放大到要横向 / 纵向滚动时，这一对也不会跟着滚走
    -->
    <Flex v-if="zoomActions?.length" class="board-zoom" justify="center" :gap="8">
        <TextAction v-for="a in zoomActions" :key="a.key" class="zoom-btn" :text="a.text"
            :on-click="a.onClick" />
    </Flex>

    <!-- 只读（interactive=false）= 纯 canvas，不接任何动作；可玩才接 cell-click -->
    <div ref="boxEl" class="board-scroll-container">
        <div class="board-fit">
            <canvas ref="canvasEl" class="board-canvas" v-on="interactive ? { click: onCanvasClick } : {}"
                :class="{ 'is-interactive': interactive }"></canvas>
        </div>
    </div>
</div>
```

**① 缩放行放在滚动框**外面**（注释原文）**：
如果缩放按钮在滚动容器**里面**，棋盘放大后**横向出现滚动条**时，按钮会**跟着内容一起被滚走**（用户放大后就找不到"缩小"按钮了）。
**放在外面** → 按钮永远贴在棋盘上方、水平居中，与滚动无关。

**② `v-on="interactive ? { click: onCanvasClick } : {}"`（对象语法绑事件）**：
- **可玩**：绑 `click`；
- **只读**：绑一个**空对象** —— **事件根本不绑定**（不是"绑了但里面判断"）。
> 这是 01 册 §1.9 那个"`v-on` 一次绑一组事件"的实战用法，也是**双保险的第一层**（`useBoardCanvas.onCanvasClick` 里还有 `interactive === false` 的判断，§4.2）。

**③ `:class="{ 'is-interactive': interactive }"`**：
只读时不加这个类 → **不显示手型光标**（`.board-canvas.is-interactive { cursor: pointer }`）→ 视觉上就告诉用户"这里不能点"。

### 11.4 样式里的三处"布局机关"

```css
.board-box { width: 100%; }

/* 棋盘框：滚动 + 边框 + padding；量它测宽度 */
.board-scroll-container {
    box-sizing: border-box; width: 100%; max-height: 60vh; overflow: auto;
    scrollbar-gutter: stable; border: 1px solid #e5e7eb; border-radius: 4px; padding: 8px;
    display: flex; scrollbar-width: auto; scrollbar-color: #94a3b8 #f1f5f9;
}

/* 棋盘 + 缩放圆圈同一框：这个框随棋盘收缩，圆点正好贴棋盘左边界、在棋盘正上方 */
.board-fit { display: flex; flex-direction: column; align-items: flex-start; gap: 6px; margin: auto; }
```

| 机关 | 为什么 |
|---|---|
| **`max-height: 60vh`** | 大棋盘不至于把整页撑到没法看（超出就**在框内滚动**） |
| **`scrollbar-gutter: stable`** | **预留滚动条的位置** → 从"不需要滚动"变成"需要滚动"时，**内容不会突然横向跳一下**（这个属性专门解决这种抖动） |
| **`margin: auto`（在 flex 容器里）** | 让 `.board-fit` 在容器里**水平居中**（flex 容器里的 `margin:auto` 是"吸满剩余空间"的经典用法） |
| **`align-items: flex-start` + `flex-direction: column`** | 让"缩放行"与"棋盘"**左对齐**（棋盘变小时缩放行不会漂到中间） |
| **`scrollbar-gutter` / 自定义滚动条（`::-webkit-scrollbar`）** | 与 `PagerStepsView` 同款视觉（§8.3 提到的"可收口点"） |
| **`touch-action: manipulation`（在 canvas 上）** | 手机上**去掉双击缩放/300ms 延迟**的干扰（点格子更跟手） |
| **`user-select: none`** | 拖拽选格子时不会把页面文字一起选中（拖出蓝色选中区很难看） |

**⑤ 它故意不做什么**：
- **不画盘面**（`render/board.ts` 画）；
- **不管缩放状态**（`useZoom` 管，它只收 `zoom` 与 `zoomActions` 两个数据）；
- **不知道规则**（不判冲突，只按 `conflictMask` 上色）；
- **不决定点击后干什么**（`emit('cell-click')`）。
> **135 行里，真正的"逻辑"只有 3 行（两个 ref + 一行调 composable）** —— 其余全是模板与样式。**这就是"笨组件"的极限形态。**

**① 用 `Menus` 这个数据结构描述"首页有哪些入口"**（`types/item.ts`）：
每个入口是 `{ key, icon, message, routeName, disabled? }` —— **数据化**，模板里一个 `v-for` 搞定。
**加一个入口 = 数组里加一项**（不动模板、不动样式）。

**② `disabled: userStore.isGuest` —— "要登录的入口"的实现**：
- **不写 `v-if`**（入口一直都在，只是**灰显**）→ 用户能看到"有出题模式这回事，但要登录"；

**③ 灰显用 `:class="{ 'is-dim': m.disabled }"` + `opacity: 0.5`**：
**不是 `disabled` 属性**（`TextAction` 的契约是"不给 onClick 才是禁用"，见 §2.1）—— 这里**仍然给 onClick**（因为要弹提示），只是**视觉上淡一点**。
> **"要不要能点"和"要不要显眼"是两件事** —— 这里选择了"能点但灰显 + 点了给理由"。**这是比"直接禁用"更好的交互。**

**④ `.entry-icon { display: inline-block; width: 1.6em; text-align: center }`**（注释原文）：
> *"图标列固定宽 + 居中：emoji 字宽不一（👤 ▶ ✏️ 🔍 🧩），不定宽的话每条标签起点都会错开"*

**这是个很实际的排版问题**：emoji 宽度不同（`👤` 与 `▶` 差很多），如果不用固定宽度的图标列，**五条入口的文字起点会参差不齐**。
**`1.6em` 是"够放下最宽的 emoji"的一个经验值**（配合 `text-align: center` 让图标在列内居中）。

**⑤ 页面级的三处"最小状态"**：`tip`（一次提示）—— 只有它放在页面里，其余全是"取 composable / 常量 / store"。

**① 两个 `FormField` 的绑定方式不同（值得对比）**：
| 控件 | 写法 | 为什么 |
|---|---|---|
| 下拉（`select`） | `:model-value` + `@update:model-value="(v) => (draft.boxSize = v as number)"` | `FormField` 的 emit 类型是 **`string \| number`**，而 `boxSize` 是 `number` → **需要 `as number` 收窄**；`v-model` 的语法**塞不进类型断言** |
| 滑杆（`range`） | **`v-model="draft.blankRatio"`** | `blankRatio` 本来就是数字，不需要断言 → 直接用 `v-model` 最简洁 |

> **两种写法都对**：`v-model="x"` 只是 `:model-value="x"` + `@update:model-value="v => x = v"` 的语法糖。
> **需要"在赋值时做点别的事"（断言 / 转换 / 日志）时，就手写展开版** —— 这就是本项目同时出现两种写法的原因。

**② 三个 core 派生直接喂给控件**（`totalCells` / `blankCount` / `blankPercent`，06 册 §5.1）：
```html
:label="`挖空比例:${blankPercent}%`"        ← 滑杆标签实时显示百分比
:hint="`共 ${totalCells} 格，挖空 ${blankCount} 格`"   ← 说明行实时显示两个数
```
**页面在"拼字符串"** —— 这**不违反 R6**（没有 `Math.`、没有 import core）：它只是把 composable 给的**数字**放进模板串里。
> **界限很清楚**：**"算"在 core / composable，"拼显示"可以在模板**（R6 禁的是 `Math.` 与 import core，不是字符串模板）。

**③ `BLANK_RATIO.min / max / step` 直接传给滑杆**：
滑杆的范围就是**业务常量本身**（`0.4 ~ 0.65`，步长 `0.01`）→ **用户根本滑不出非法值**（防御前置到 UI）。
> **"让非法的状态不可达"比"事后校验"更好** —— 这里 UI 层就从源头限制了范围。

**④ `Overlay :show="loading" spinning text="正在生成题目" desc="大盘面可能需要几秒…"`**：
**加载遮罩三件套**（转圈 + 主文案 + 说明）→ 顺手告诉用户"为什么要等"（大盘面确实慢）。
**⑤ `actions` 里 `loading ? undefined : apply`**：生成中按钮变**纯文本**（06 册 §5.1 ④）。

**① `<form @submit.prevent="submit">` + `<button type="submit">`（本页最地道的写法）**
```html
<form class="form" @submit.prevent="submit">
    …
    <button class="btn-primary" type="submit" :disabled="loading">{{ title }}</button>
</form>
```
- **回车即提交**：输入框里按回车 → 浏览器自己触发 `submit` → **不需要给每个 input 绑 `@keyup.enter`**；
- **`.prevent`**：阻止浏览器默认的"提交并刷新页面"（SPA 里绝不能让页面刷新）；
- **`<button type="submit">` 才是"表单提交按钮"**（回忆 §2.1：`TextAction` 的 `<button>` 是 `type="button"`，**不会触发提交** —— 两者互不冲突）；
- **`type="password"`** 的 `FormField` 自带 👁 明文开关（§3.2 ②）。
> **附带好处**：浏览器/密码管理器能正确识别这是登录表单（自动填充、保存密码）。

**② `@paste="onUidPaste"` 为什么绑在 `FormField` 上也能生效**（注释原文）：
> *"事件从 input 冒泡到根 label，见 `useAuth.onUidPaste`"*

`FormField` 的根元素是 `<label>`，`paste` 事件从内部 `<input>` **冒泡到 label** → 外层监听照样收到（`event.clipboardData` 完好）。
**所以组件不需要为"粘贴清洗"专门加 prop/emit**（`useAuth` 里 `e.preventDefault()` + 自己写回，06 册 §3.1 ⑤）。
> **知识点：原生事件冒泡让"在组件外层做加工"成为可能** —— 想给某个内层元素加行为，先看看"能不能在父级监听到"。

**③ `v-if="isSignUp"` 三处切换**（显示名/账号 ID、确认密码、按钮/标题文案）：
**注册多两个输入框**（显示名、确认密码），登录只要"账号 ID + 密码"→ **同一个页面 + `mode` 切换**（不必写两个页面）。
**`title` 一个派生、三处使用**（`<h2>`、提交按钮、切换按钮的判断）。

**④ 注册成功卡片 = `Overlay` + 插槽**

- **插槽**里放"那一长串账号 ID"（`.uid-card` 是全局样式）；
- **两个按钮都是 `Action`**：`📋 复制`（`copied` 变化时文案跟着变 → `已复制`）+ `➡️ 我已保存`（`doneAfterSignUp`）；

**⑥ `:disabled="loading"`**：提交中按钮**原生禁用**（灰 + 不可点）—— 与"`Action` 不给 `onClick`"是**两种禁用表达**：
| 场景 | 用哪种 | 为什么 |
|---|---|---|
| 原生 HTML 按钮（`<button class="btn-primary">`） | **`:disabled`** | 原生语义（读屏会念"不可用"） |
| 数据化按钮（`TextAction`） | **不给 `onClick`** | 没有 props 之外的地方能表达"禁用" |
> **两者是在各自体系内的正确选择**，不矛盾。

**① `listBar` / `listPager` 两个数据对象（本节的关键）**
这就是"**组件不认识业务常量**"的落地（§9 ③）：

| 数据 | 来源 | 组件怎么用 |
|---|---|---|
| `modeLabel: SEARCH_COPY.browseLabel` | 常量（"浏览方式"） | 直接显示 |
| `modeOptions: PAGER_MODE_OPTIONS` | 常量（`[{value:'bar',label:'进度条'},…]`） | 喂给 `FormField(type=select)` |
| `mode: pagerMode.value` | composable（本地偏好，06 册 §2.4） | 当前选中项 |
| `sortLabel / sortOptions / sort` | 同理（`SORT_OPTIONS` + `sort.value`） | 第二个下拉 |
| `page / pageCount` | composable（URL + store 派生） | 喂给 `PagerBar` |

**两个 computed 把"六个 props"变成"两个对象"** → 模板里只剩 `:bar="listBar" :pager="listPager"`（决策 56 那次"12 props → 6 props"的收益）。

**② 四个事件接回 composable**
```html
@retry="retry" @change-mode="changePagerMode" @change-sort="(v) => changeSort(v as ListSort)" @change-page="changePage"
```
| 事件 | 接到哪 |
|---|---|
| `retry` | `useListQuery.retry`（同参数重取） |
| `change-mode` | `useListQuery.changePagerMode`（**写 localStorage**，06 册 §2.4 ③） |
| `change-sort` | `useListQuery.changeSort`（**只改 URL**，并回第 1 页） |
| `change-page` | `useListQuery.changePage`（**只改 URL**） |

> **注意 `(v) => changeSort(v as ListSort)` 那个收窄**：
> `ListSection` 的 emit 类型是 `[value: string]`（它不认识业务类型）→ **页面负责把它收窄成 `ListSort`**。
> **这正是"泛型/宽类型在页面边界处收窄"的标准位置**（`FormField` 的 `v as number` 同理，§12.3）。

**③ `:key-of="(item) => item.pid"`**：
`ListSection` 的 `keyOf` 默认按下标（§9 ②）；这里**传了稳定 id**（`pid`）→ 翻页/数据替换时 **diff 更准**（不会出现"某个行为的状态串到另一行"）。
**④ 两个插槽**（`#top` 出题人表头 / `#item` 用 `PuzzleCard`）—— 与 §9 ⑤ 的插槽设计一一对应。
**⑤ 预览遮罩拆成两个 `Overlay`（一个值得注意的细节）**
```html
<Overlay :show="previewOpen && !previewLoading" :text="previewTitle" :actions="previewActions">
    <BoardView v-bind="previewInput" :zoom-actions="previewZoomActions" />
</Overlay>
<Overlay :show="previewLoading" spinning />
```
**为什么要两个**：`previewLoading` 与 `previewOpen` 是**两个独立状态**（06 册 §6.2 ⑤）：
- **加载中** → 显示**纯转圈**（没有标题/按钮/棋盘）；
- **加载完** → 显示**内容遮罩**（标题 + 只读棋盘 + 返回）。

**如果合成一个**：加载期间会出现"空棋盘 + 空标题 + 返回按钮"的闪动。
> **`previewOpen && !previewLoading`** 这个组合条件就是"内容遮罩只在加载完显示"的实现 —— **不新增状态，用两个已有状态算出来**（与 05 册 §3.2 的 `empty` 三条件同一思路）。

**① 页面级三态（加载 / 错误 / 内容）**：
与 `ListSection` 内部的列表三态同构，但这里是**整页**三态；`v-else` 用 `<template>` 包住一整块。
**② `useBoardZoom(() => boardInput.value.boxSize)` —— "取值函数里再套取值函数"（很值得看）**
```ts
const { zoom, zoomActions } = useBoardZoom(() => boardInput.value.boxSize)
```
- `boardInput` 本身是 `usePuzzleDetail` 的 **computed**（06 册 §6.1 ③）；
- 再包一层 `() => boardInput.value.boxSize` → **盘面载入后（`boxSize` 从 0 变成 9/16）`useBoardZoom` 的 `watch` 会自动复位缩放**（01 册 §1.5）；
- **若传 `boardInput.value.boxSize`（值）**：载入时读到 `0`，之后永远 `0` → 缩放不会跟着盘面走（"16×16 显示成半个盘"）。
> **"哪一层传函数、哪一层传值"**：**凡是"跨层的、可能后到的响应式数据"，一律传取值函数**（01 册 §1.11 坑 2 的同一条）。

**③ `boardParams` 用展开合并（另一个 `BoardRenderInput`）**
```ts
const boardParams = computed<BoardRenderInput>(() => ({ ...boardInput.value, zoom: zoom.value, interactive: false }))
```
**"复用 `boardInput` 的 board + boxSize，再补 zoom 与 interactive"** —— 这正是 06 册 §6.1 ③ 说的"`boardInput` 只给'画什么'，'多大 / 能不能点'由消费方补"的落地。

**④ `goBack` 用 `window.history.length > 1` 判断（与 `useGameFlow` 的写法不同）**
```ts
if (window.history.length > 1) router.back()
else void router.replace({ name: PAGE.Home })
```
对比 06 册 §5.6 ⑤ 的 `router.options.history.state.back`：
- **两种都是"有没有历史"的判据**（`window.history.length` 更粗；`history.state.back` 更准）；
- **兜底目标不同**：游戏页回**难度页**（它的上一级），落地页回**主页**（它是从外部链接直接进的）。
> **同一意图、两种实现并存** —— 这算一处**可收口的轻微不一致**（将来可以抽一个 `goBackOr(fallback)` 工具，两处共用）。

**⑤ `onMounted(() => { void load(String(route.params.pid ?? '')) })`**：
`pid` 从路径参数取（`/p/:pid`），与 `EditPuzzlePage` 同款（06 册 §5.4 ①）。
**⑥ 只有"返回 + 挑战"两个按钮** → **落地页是"给外人看的"**：
没有编辑、没有删除、没有"我的题目"入口（02 册 §5.9 的权限矩阵：非作者拿不到这些能力）。

### 12.11 十三个页面的共性（本册的结论）

**句式总结**（每个页面都能套进去）：

```
【取数】const { … } = useXxxFlow()                       ← 1~2 个 composable（可多个）
【入参】const params = computed(() => ({ … }))            ← 喂给组件的"对象"
【控件】const actions = computed<Actions>(() => [ … ])     ← 喂给 v-for 的"按钮条"
【三态】v-if="loading" / v-else-if="error" / v-else
【接线】v-bind / v-for / v-model / @事件
【遮罩】若干 <Overlay :show="…" :actions="…">（真正需要时）
```

**六个反复出现的模式**（都在本册验证过）：

| 模式 | 出现位置 |
|---|---|
| **按钮条数据化 + 条件拼装** | GamePage / SystemPage / CustomPage / CreatePage / EditPuzzlePage / SolvePage / MyPuzzlesPage / SearchPage …（**每个页面都有**） |
| **渲染入参对象化（`v-bind="obj"`）** | GamePage / CreatePage / EditPuzzlePage / SolvePage / Preview / PuzzleViewPage |
| **可写 computed 做 v-model 适配** | `MyPuzzleRow.visPick/solutionPick`、`CreatePage.boxSize` |
| **页面级三态** | PuzzleViewPage（整页）、SearchPage/MyPuzzlesPage（`ListSection` 内部） |
| **遮罩服务多场景** | 每个页面末尾的 `Overlay` 群（同一个组件 + 不同数据） |
| **路由 = 位置 / 状态 = 过程** | 难度页 Tab（子路由）vs 求解页 Tab（本地状态）；`?q&sort&page`（URL）vs `pagerMode`（localStorage） |

**一句话总结第七册**：
> **组件只做"画"（props 进、事件出），页面只做"接线"（取数据、摆位置、接事件）；把"判断与计算"全部留在 composable / store / core。**
> 于是**整套 UI（2,300 行）里没有一行业务算法** —— `pnpm guard` 的 R5/R6 就是在机器上守着这条线。

## 13. 横向模式与检查清单（能直接迁移）

### 13.1 组件层的五条模式

| # | 模式 | 说明 | 本册实例 |
|---|---|---|---|
| 1 | **数据化** | 列表/按钮/选项/渲染方式都当数据传，模板只 `v-for` | `Actions` / `Menus` / `SelectOption[]` / `ListBar` / `ListPager` / `BoardRenderInput` |
| 2 | **契约化** | 用 props 表达"能不能点"（`onClick` 缺省 = 禁用），不用额外 `disabled` | `TextAction` / `useZoom.zoomActions` / `PagerBar` 的上一页下一页 |
| 3 | **插槽化** | 结构留在组件内，"内容/渲染方式"交给调用方 | `Overlay`（内容）、`ListSection`（`#top`/`#item`/`#empty`）、`TextAction`（图形） |
| 4 | **样式分工** | 跨页规格走全局类；组件只写"自己特有"的一点点 | 全局 `.text-btn` / `.item-card` / `.field` / `.sub-nav`…；组件里只剩对齐/尺寸微调（`MyPuzzleRow` 的空 style、`PuzzleCard` 无 style） |
| 5 | **语义与无障碍** | 该是 `<button>` 就 `<button>`；装饰图形 `aria-hidden`；列表用 `<ul>/<li>` | `TextAction` 的 `:is="tag"`；`EyeGlyph` 的 `aria-hidden`；`ListSection` 的 `<ul>` |

### 13.2 新增一个**组件**的检查清单（8 问）

1. 它是"画"吗？（如果是"算" → core；"编排" → composable；"记住" → store）
2. 数据能不能**全部从 props 来**？（不许 import store / router —— R5）
3. 动作怎么出去？**回调 prop**（`onClick`）还是 **emit**？（少 → emit；多 → 打包成一个 `controls` 对象）
4. 有没有"可变部分"该做成**插槽**（而不是加一堆 `v-if` prop）？
5. 有多少 prop 是"一类东西"？能不能**收成一个对象**（像 `bar`/`pager`）？
6. 样式里**哪些是全局已有的**？（不要复制全局规格）
7. 触碰无障碍了吗？该用 `<button>`/`<label>`/`<ul>` 的地方用对了吗？
8. 加进 `ARCHITECTURE.md §十` 的组件清单了吗？（它是"共 15 个"的账本）

### 13.3 新增一个**页面**的检查清单（8 问）

1. 它的**数据/动作**有没有现成的 composable？没有 → 先写 composable（**不要直接写进页面**，会顶到 R6 的"声明 ≤10"）
2. 需要**几个** composable？（"功能块独立"就各来一个，例如我的题目页 = 列表 + 账号区）
3. 页面上要显示的"**算好的值**"从哪来？（composable / store 派生；**页面禁 `Math.`**）
4. 需要**渲染入参对象**吗？（`computed<BoardRenderInput>` 之类 → 喂 `v-bind`）
5. 需要**按钮条**吗？（`computed<Actions>` → 喂 `v-for`；条件用 `...(cond ? [x] : [])`）
6. 有**三态**吗？（加载 / 错误 / 空 —— 用一串 `v-if/v-else-if/v-else`）
