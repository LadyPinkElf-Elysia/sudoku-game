## 1. Node.js、包管理器与"依赖"到底是什么

### 1.1 知识点：Node 与包管理器的分工

- **Node.js**：让 JavaScript **脱离浏览器**运行的运行时。本项目里它负责三件事：
  1. 跑开发服务器与构建工具（Vite）；
  2. 跑**架构守卫脚本**（`scripts/check-arch.mjs`，纯 Node 脚本）；
  3. 跑 `wrangler`（Cloudflare 命令行工具，本地起后端 + 模拟 D1 数据库）。
- **包管理器**（npm / yarn / **pnpm**）：把别人写好的库下载下来、放进项目、记录版本。
- **包（package）**：可复用的代码库，最少包含一个 `package.json`（名字、版本、入口、依赖）。
- **依赖（dependency）** 分两类：
  - `dependencies`：**运行时要用的**（`vue`、`pinia`、`vue-router`）→ 会被打包进产物；
  - `devDependencies`：**只在开发/构建时用的**（`vite`、`typescript`、`prettier`、`wrangler`）→ 不进产物。

### 1.2 知识点：pnpm 的"全局 store + 硬链接"

pnpm 与 npm 最大的区别：

- 包只下载一份，存进**全局 store**（你机器上：`C:\Users\lenovo\AppData\Local\pnpm\store\v11`）；
- 项目 `node_modules` 里**不是复制文件**，而是**硬链接**指向 store → "看起来几百 MB 的 node_modules"实际几乎不额外占磁盘；
- 第二次装同一个包（别的项目、或删掉重装）**不用重新下载**，直接从 store 链接回来。

**这解释了三个"吓人现象"（都不是文件丢失）**：

| 现象 | 真相 |
|---|---|
| `node_modules/vue` 之类"像是快捷方式" | pnpm 的**硬链接 / 符号链接**，正常 |
| 包内找不到 `pnpm-lock.yaml`、`node_modules/.modules.yaml` | **monorepo 只认根的那一份**（见 §1.4） |
| `node_modules/.bin/vite.CMD` 里路径指向"上层目录" | pnpm workspace 把可执行文件集中到根，正常 |

### 1.3 知识点：`package.json` 与 `scripts`（命令别名）

**本项目 `sudoku/package.json` 的 scripts（逐条）**：

| 脚本 | 命令 | 干什么 |
|---|---|---|
| `dev` | `vite` | 起开发服务器（热更新） |
| `guard` | `node scripts/check-arch.mjs` | **架构守卫**：扫 `src/` 与 `functions/`，违规 exit 1 |
| `build` | `vue-tsc -b && tsc --noEmit -p functions/tsconfig.json && vite build` | ① 前端类型检查 ② 后端类型检查 ③ 打包到 `dist/`（**不含 guard**） |
| `preview` | `vite preview` | 本地预览已打包的 `dist/` |
| `typecheck` | `vue-tsc --noEmit -p tsconfig.app.json` | 只检查前端类型 |
| `typecheck:functions` | `tsc --noEmit -p functions/tsconfig.json` | 只检查后端类型 |
| `format` | `prettier --write "src/**/*.{ts,vue,css}"` | 格式化源码 |

`"type": "module"`：这个包的 `.js` 按 **ESM**（现代模块）解析（见 §2.1）。

### 1.4 知识点：monorepo（工作区）—— 你的项目现在的真实形态

**数独不是一个孤立项目，而是一个工作区里的子包**：

```
C:\Users\lenovo\Desktop\学习资料\vue3\      ← 工作区根（VS Code 应该开这一层）
├─ pnpm-workspace.yaml    packages: sudoku / todo / sudoku_demo
│                         allowBuilds: esbuild / workerd   （允许它们跑安装脚本）
│                         modulesDir: "node_modules"
├─ package.json           name: vue3 · script: "dev:sudoku": "pnpm --filter sudoku dev"
├─ pnpm-lock.yaml         ← 唯一的 lockfile（记录三个子包的依赖版本）
├─ node_modules/          ← 唯一的依赖安装处（.modules.yaml、.pnpm 都在这）
├─ sudoku/                ← 你的数独（本系列的主角）
├─ todo/                  ← 另一个练习项目
└─ sudoku_demo/           ← 另一个练习项目
```

**为什么这么设计**：三个 Vue 练习项目共享同一份依赖（只装一次、版本统一），并且能只启动其中一个（`pnpm --filter sudoku dev`）。

**必背三条**：
1. **lockfile 在根**：`学习资料/vue3/pnpm-lock.yaml`；
2. **`node_modules` 在根**：`sudoku/node_modules` 里只有指向根的链接；
3. 因此"包内 lockfile 不见了"= **正常**，别手动补。

### 1.5 坑与对策：什么时候必须重装依赖

| 情况 | 做法 |
|---|---|
| 换机器 / 删过 `node_modules` | 在**根**执行 `pnpm install`（按 lockfile 还原，绝大多数不用重新下载） |
| 想加一个库 | 根目录执行 `pnpm --filter sudoku add <包>`（会同时改 `sudoku/package.json` 与根 lockfile） |
| 只缺个别包（例如 `@vue/tsconfig`） | 同样 `pnpm install` 就能补回来 —— 它是 `devDependencies` 里的**包内容**，不是项目源文件 |
| 移动过项目文件夹、依赖全坏 | 删掉根 `node_modules` 重装；**项目与 store 保持同一个盘**（都在 C 盘）才能用硬链接 |

## 2. 模块系统、TypeScript 与构建：谁在什么时候做什么

本节解决最常见的困惑：**"我改了代码，是谁把它变成浏览器能跑的？类型检查又是谁做的？"**

### 2.1 知识点：ESM 模块（`import` / `export`）

```ts
// 导出
export const add = (a: number, b: number): number => a + b
export interface User { uid: string }
export default router                      // 默认导出：一个文件只能一个

// 导入
import { add } from './math'                // 具名导入
import type { User } from './types'         // 只导入类型：编译后会被彻底删除
import router from './router'               // 默认导入
```

**本项目的三条模块约定（守卫会查）**：

1. **只用 ESM**（`package.json` 里 `"type": "module"`），不用 `require`。
2. **类型一律 `import type`**（编译器开了 `verbatimModuleSyntax`）→ 打包后类型导入被完全删掉，不把"只是类型"的东西带进产物。
3. **禁桶文件**（`export * from './x'`，规则 **R12**）：谁用谁直接 import 源文件，避免"表面一个 import、实际拖出十个文件"的隐式依赖。

### 2.2 知识点：TypeScript 只做"检查"，真的跑起来靠构建工具

- 浏览器**不能直接跑 TS**；TS 只是"带类型的 JS 超集"。
- 把 `.ts` / `.vue` 变成浏览器能跑的 JS 的是**构建工具**（本项目 = Vite + Wrangler）。
- `tsc` 在本项目里一律 `--noEmit`（**只检查、不产出**）；前端因为要检查 `.vue`，用的是 **`vue-tsc`**（"懂 Vue 的 tsc"）。

| 角色 | 谁 | 干什么 | 出现在哪条命令 |
|---|---|---|---|
| 前端类型检查 | `vue-tsc` | 检查 `src/**/*.ts` + `*.vue` 的 `<script setup>` | `pnpm typecheck`；`pnpm build` 第 1 步 |
| 后端类型检查 | `tsc` | 检查 `functions/**/*.ts` | `pnpm typecheck:functions`；`pnpm build` 第 2 步 |
| 转译 + 打包（前端） | Vite（内部 esbuild/rolldown） | TS→JS、CSS、依赖打包、产物进 `dist/` | `pnpm dev`（内存里）、`pnpm build` 第 3 步 |
| 转译（后端） | Wrangler（内部 esbuild） | `functions/*.ts` → Worker 可执行代码 | `npx wrangler pages dev` / 部署时 |
| 静态检查（架构） | `scripts/check-arch.mjs` | 规则 R1~R15，违规 exit 1 | `pnpm guard` |

**一句话**：`pnpm build` = `vue-tsc` 查前端类型 → `tsc` 查后端类型 → `vite build` 打包。

### 2.3 知识点：为什么必须"打包（bundle）"

浏览器原生虽然支持 `import`，但工程里仍需要打包，因为：

- **`.vue` 浏览器不认识**（必须编译成 JS + 渲染函数）；
- **TS 要转译**成 JS；
- **依赖文件太多**（一个库可能几十个文件，零散请求很慢）；
- 可以**压缩**、**按需拆包（路由懒加载）**。

本项目能在 `pnpm build` 的输出里看到拆包效果：`dist/assets/GamePage-*.js`、`dist/assets/SolvePage-*.js`…
—— 每个页面一个 chunk，**只有访问那条路由才会下载**，因为 `router/index.ts` 里写的是动态导入：

```ts
{ path: PAGE.Game, name: PAGE.Game, component: () => import('@/pages/GamePage.vue') }
```

### 2.4 知识点：四个 `tsconfig` 为什么分开

| 文件 | 管谁 | 关键内容（本项目实况） |
|---|---|---|
| `tsconfig.json` | 总入口 | `"files": []` + `references: [app, node]` —— 只把两个子配置拼起来 |
| `tsconfig.app.json` | 前端 `src/` | `extends "@vue/tsconfig/tsconfig.dom.json"`（Vue 官方 DOM 环境配置）+ `paths: { "@/*": ["./src/*"] }` |
| `tsconfig.node.json` | `vite.config.ts` 等"跑在 Node 里的配置脚本" | 用 Node 的类型 |
| `functions/tsconfig.json` | 后端 `functions/` | `types: ["@cloudflare/workers-types"]`；**没有 `paths`**（后端只用相对路径） |

**常见误会**：`tsconfig.app.json` 第一行 `"extends": "@vue/tsconfig/tsconfig.dom.json"` —— 那个文件**属于依赖包**（`node_modules/@vue/tsconfig/`），不是项目源文件。
它"消失"只有一个原因：**依赖没装好**（`pnpm install` 还原），不是你把项目文件弄丢了。

### 2.5 知识点：路径别名 `@/` 与"为什么 core / 后端只用相对路径"

`@/xxx` 是构建与 TS 约定的别名 → 指向 `src/xxx`。它需要**两处一致配置**：
`tsconfig.app.json` 的 `paths`（给类型检查用）+ `vite.config.ts` 的 `resolve.alias`（给打包用）。

本项目的规定：

| 位置 | 用什么 import | 为什么 |
|---|---|---|
| `src/**`（前端其余部分） | `@/core/...` 或 `./兄弟` 都行 | Vite 与 vue-tsc 都认识别名 |
| `src/core/**` | **只用相对路径**（`../board/ops`） | core 要被三个环境复用（浏览器 / Worker / 后端），不依赖任何构建别名 |
| `functions/**` | **只用相对路径**（`../../src/core/sudoku/parse`） | 后端 tsconfig **没有 `paths`**（已核对），别名在这里不存在 |
| `services/sudoku/worker.ts` | 用别名 | 它由 Vite 打包（走前端配置） |

### 2.6 坑：`TS6133` 是什么（为什么删了模板分支，构建立刻红）

```
src/pages/SolvePage.vue(3,1): error TS6133: 'BoardView' is declared but its value is never read.
```

= "声明了但从没用过"。原因：本项目把"未使用变量/导入"当作**错误**（不是警告）。
典型场景：你把某个 `v-if` 分支删掉，那个分支用到的 `computed` / 组件 import 就成了"没人用" → 立即报错。

**正确反应**：这不是 bug，是检查在帮你清理死代码 —— **把不再需要的 import / 变量一并删掉**（本项目历史上清理过一批"早已废弃的字段"，就是这么发现的）。

## 3. JavaScript 必会清单（读本项目够用的全部）

> 格式统一：**是什么 → 最小例 → 本项目真实用法（带文件与行号）**。
> 顺序按"从最容易看到 → 越到后面越是这份代码的关键"。

### 3.1 `const` / `let` / 块级作用域

**是什么**：`const` = 绑定不可改（对象内容仍可改）；`let` = 可重新赋值；`var` 本项目不用（函数作用域、会提升，容易出错）。
`{}`、`for` 循环体、`if` 分支都形成**块级作用域**。

```js
const S = 9                  // 不能再 S = 4
let count = 0                // 可以 count++
for (const [r, c] of cells) { /* 这里 r/c 每轮都是新的绑定 */ }
```

**本项目**：`src/core/sudoku/rules.ts:31-33` —— `const B = boxSize`、`const S = sideOf(B)`，把"盒宽"和"边长"先算好，后面反复用（避免到处写 `boxSize * boxSize`）。

### 3.2 解构（取出来）与展开（摊开）

**是什么**：
- 解构：从数组/对象里"按位置/名字"取出值；
- 展开：把数组/对象"摊平"进新数组/新对象（**浅拷贝**的关键手段）。

```js
const [r, c] = [3, 5]                       // 数组解构：r=3, c=5
const { puzzle, solution } = data           // 对象解构
const { name: title } = obj                 // 解构成新名字
const next = [...cells, [r, c]]             // 展开 → 新数组（不改原数组）
const cfg = { ...config, boxSize: 9 }       // 展开 → 新对象（覆盖某字段）
```

**本项目**：
- `rules.ts:11` —— `for (const [r, c] of cells)`：坐标是 `[行, 列]` 二元组（`Position` 类型就是 `[number, number]`）。
- `rules.ts:24` —— `conflicts.push(...ps)`：把一整批坐标**展开**推进结果数组（等价于逐个 push）。
- `generator.ts:143` —— `return { puzzle: digPuzzle(...), solution }`：返回对象；调用方 `const { puzzle, solution } = await generateInWorker(...)`（见 `useDifficultyFlow.ts:32`）。

### 3.3 箭头函数与 `this`

**是什么**：`(a, b) => a + b` 是函数简写。两个特点：① 写法短（单表达式可省略 `return` 与 `{}`）；② **不绑定自己的 `this`**（继承外层）——这正是"回调里不用管 this"的原因。

```js
const double = (n: number) => n * 2                 // 简写
const cell = ([r, c]: Position) => ({ r, c })       // 返回对象要包括号
```

**本项目**：`src/core/**` 几乎全是箭头函数（`const tally = (grid: NumBoard, g: Int32Array): number => {...}`，`groups.ts`）。原因见 **04 册**：core 要求"无状态、不看 this"，箭头函数天然贴合。

### 3.4 模板字符串

**是什么**：反引号里用 `${表达式}` 拼字符串；也支持多行。

```js
const label = `第${i}步`
```

**本项目**：`src/core/sudoku/label.ts` 生成"第 3 行 第 5 列"这类定位文案；页面按钮 `stepLabel = (i) => `${i}步``（`GamePage.vue`）。

### 3.5 可选链 `?.` 与空值合并 `??`

**是什么**：
- `a?.b`：`a` 是 `null`/`undefined` 时**不报错**，直接得到 `undefined`（比 `a && a.b` 更准，因为 `0`、`''` 不会被误判）；
- `a ?? b`：只在 `a` 为 `null`/`undefined` 时取 `b`（`a || b` 会把 `0`、`''`、`false` 也当"空"，这是经典 bug）。

```js
const id = puzzle?.id ?? ''       // puzzle 为 null → ''
const n = row?.length ?? 0
```

**本项目**：`src/composables/puzzle/usePuzzleDetail.ts`、`src/services/api/puzzleApi.ts`、`src/stores/user.ts` 里用得多（后端返回的字段可能缺省）。**记住区别**：显示"0 步"时必须用 `??`，用 `||` 会变成空串。

### 3.6 短路求值 `&&` / `||` 与三元 `? :`

```js
isOpen && doClose()               // 左侧为真才执行右侧
const text = failed ? '失败' : '成功'
```

**本项目**：`src/composables/auth/useAuth.ts:89` —— `if (!(await copy(createdUid.value))) error.value = AUTH_COPY.copyFailed`（失败才写错误文案）；`useAuth.ts:79` —— `await router.replace(safeRedirect(route.query.redirect) || { name: PAGE.Home })`（**这里用 `||` 是对的**：目标是对象，不存在 `0`/`''` 的坑）。

### 3.7 数组方法（core 里出现最多的一批）

| 方法 | 作用 | 本项目例子 |
|---|---|---|
| `.map(fn)` | 每个元素 → 新元素，返回**新数组** | 把数字盘转成格子盘（`core/board/model.ts`） |
| `.fill(v)` | 填充 | `new Array(S + 1).fill(false)`（`rules.ts:75` 的"已用数字"标记表） |
| `Array.from({length:n}, fn)` | 造定长数组 | 造 `S×S` 的二维数组 |
| `.every(fn)` | 全部满足？ | 判断"这一行/这一盘是否合法" |
| `.some(fn)` | 存在满足？ | 判断"有没有冲突" |
| `.flat()` | 二维 → 一维 | 把整盘格子摊平（统计用） |
| `.push()` | 末尾追加 | `rules.ts:24` `conflicts.push(...ps)` |
| `.includes(x)` | 是否含 | 判断某数字是否在候选里 |

**关键观念**：`.map / .filter / .flat` 都**返回新数组，不修改原数组**；而 `.push / .sort / .splice` **会改原数组**。本项目 core 的"不改入参"铁律（R7 相关）正是靠"优先用前者"实现。

### 3.8 `Map` / `Set`（以及为什么不用普通对象）

**是什么**：
- `Map`：键可以是**任意类型**（对象、数字），有 `has/get/set/values`；普通对象 `{}` 的键只能是字符串/符号，还有原型链污染问题；
- `Set`：不重复集合，`add/has/delete`。

**本项目（两个真实例子，都在 `src/core/sudoku/rules.ts`、`src/services/api/client.ts`）**：

```ts
// rules.ts:9-27 —— 找出一组格子里重复的数字（Map<数字, 这些格子的坐标>）
const map = new Map<number, Position[]>()
for (const [r, c] of cells) {
    const v = grid[r][c]
    if (v === 0) continue                 // 0 = 空格，不参与冲突
    if (!map.has(v)) map.set(v, [])        // 没见过这个数字 → 先放空数组
    map.get(v)!.push([r, c])               // 见过 → 追加坐标（! 断言"一定有"）
}
const conflicts: Position[] = []
for (const ps of map.values()) {
    if (ps.length > 1) conflicts.push(...ps)   // 同一数字出现 ≥2 次 → 全是冲突格
}
```

```ts
// src/services/api/client.ts:14 —— 一个"401 无人登录"的监听者集合
const unauthorizedListeners = new Set<Listener>()
```

**为什么 `map.get(v)!` 要加 `!`**：TS 不知道"刚 `set` 过就一定存在"，`!`（非空断言）是我们向它保证。**先 `has` 判断再 `get`** 是标准写法（见 §4.8）。

### 3.9 生成器 `function*`：这份代码里最关键的一个语法

**是什么**：普通函数"一次跑完返回一个值"；**生成器函数**（`function*`）可以"**跑到 `yield` 就暂停**，下次调用继续"，像一个可以随时按暂停的流水线。

```js
function* countdown(n) {
    while (n > 0) yield n--      // 每调用一次 next() 才产出下一个值
}
const it = countdown(3)
it.next()   // { value: 3, done: false }
it.next()   // { value: 2, done: false }
it.next()   // { value: 1, done: false }
it.next()   // { value: undefined, done: true }
```

- `yield x`：产出一个值并**暂停**；
- `yield* other()`：**把另一个生成器的所有值接力过来**（委托）；
- `for (const x of gen())`：自动一个个取，直到结束。

**本项目（历史实现：`src/core/sudoku/rules.ts:35-68`；**现已改为 `Int32Array` 组单元表 —— 因为这条路径每次落子都要走，见 04 册 §9.3 / 11 册 §4.1**）**：

```ts
function* allRows(): Generator<Position[]> {     // 每次 yield 一组格子的坐标
    for (let r = 0; r < S; r++) {
        const cells: Position[] = []
        for (let c = 0; c < S; c++) cells.push([r, c])
        yield cells                               // ← 第 1 次产出：第 0 行全部坐标
    }
}

function* allGroups(): Generator<Position[]> {
    yield* allRows()      // 先接力所有"行"
    yield* allCols()      // 再接力所有"列"
    yield* allBoxes()     // 再接力所有"宫"
}
```

**为什么用生成器而不是直接返回 `Position[][]`**：

| 返回数组 | 生成器 |
|---|---|
| 一次性把 S 行 + S 列 + S 宫全部构造出来（9 阶 = 27 组、共 243 个坐标）再遍历 | **用到才构造下一组**，内存 O(1) 组 |
| 调用方拿到一个"大数组"，还得自己按顺序遍历 | `for (const g of table.cells)` 一条语句搞定，且**顺序被封在表里** |

**校验逻辑只关心"一组一组查冲突"**，不需要同时拥有全部三组 —— 生成器把"顺序"封装成接口，这就是它在这里的价值。

### 3.10 类型化数组 `Uint8Array`（值 0~255 的高效数组）

**是什么**：`Uint8Array` 是"每个元素固定 1 字节的无符号整数"的数组（0~255），底层是一段连续内存；比普通数组更省内存、更快。

**本项目（`src/core/sudoku/generator.ts:121-127`）**：挖空时用一张 `Uint8Array` 当"这一格要不要保留"的开关表：

```ts
const keep = new Uint8Array(total)                  // total = S*S
for (let i = 0; i < keepCount; i++) keep[indices[i]] = 1     // 选中的位置标 1
...
if (keep[r * S + c]) seed[r][c] = full[r][c]        // 一维下标换算：r * S + c
```

**顺带学会一个高频技巧**：二维坐标 ↔ 一维下标
`index = 行 * 边长 + 列`（`r * S + c`）。

### 3.11 浅拷贝 vs 深拷贝（"为什么改棋盘必须先复制"）

**是什么**：
- **浅拷贝**：只复制最外层。`[...arr]`、`{...obj}`、`arr.slice()` 都是浅拷贝；**里面嵌套的数组/对象仍是同一个引用**；
- **深拷贝**：连里层一起复制（手工逐层、或 `structuredClone(x)`）。

**为什么这份代码总在复制**：棋盘是 `number[][]`（**二维数组 = 数组里套数组**）。
`const copy = [...board]` 只复制了"外层那 9 个引用"，`copy[0]` 和 `board[0]` **还是同一个行数组** —— 你改 `copy[0][1]`，原棋盘也变了。所以 core 里改盘面前必须**逐行复制**：

```ts
const next: NumBoard = board.map(row => [...row])   // 每行也复制 → 真独立
```

**坑**：棋盘用 `structuredClone` 也行，但 core 偏向手写 `map(row => [...row])`（更快、也无环境依赖）；**这条"改前先拷"是 core 的隐形纪律，写 04 册时会反复出现。**

### 3.12 `JSON.stringify` / `JSON.parse`（以及它的两个用途与一个陷阱）

```js
JSON.stringify({ a: 1 })      // '{"a":1}'   对象 → 字符串
JSON.parse('{"a":1}')         // {a:1}       字符串 → 对象
```

**本项目**：
- **发给后端的请求体**：`src/services/api/client.ts:49` —— `body: body === undefined ? undefined : JSON.stringify(body)`（fetch 只能送字符串）；
- **后端返回**：`functions/utils/json.ts:3` —— `new Response(JSON.stringify(data), {...})`；
- **本地存储**：登录会话/设置需要把对象存进 `localStorage`（那里只能存字符串）。

**陷阱（必须记）**：`JSON.parse` 遇到不合法字符串会**抛异常**；所以"从 localStorage 读回对象"必须 `try/catch` 或先判断空。另外 `JSON` 会丢 `Date`、`Map`、`undefined`，本项目的数据全是纯对象/数组，所以安全。

### 3.13 错误处理：`throw` / `try` / `catch`

```js
try {
    risky()
} catch (e) {
    /* 处理 */ 
} finally {
    /* 无论成败都执行 */
}
```

**本项目的两条不同策略（很重要）**：

| 层 | 策略 | 例子 |
|---|---|---|
| `core/**` | **基本不抛异常**：用返回值表达失败（如 `parse` 返回"失败原因"而不是丢异常） | 因为 core 要被后端复用：后端里"用户输入非法"是**正常业务**，不该变成 500 |
| 兜底处 | 真的"不可能发生却发生了"才 `throw` | `generator.ts:136` `if (!solved.length) throw new Error('生成失败')`（挖空后连一个解都求不出来 = 算法前提被破坏） |

**上层怎么接住**：`services/api/**` 把网络失败转成"错误文案"写进 `error.value`，页面只管显示（见 08 册）。

### 3.14 `Promise` 与 `async / await`

**是什么**：`Promise` = "未来会有结果（成功或失败）"的占位符；`async/await` 是**用同步写法处理异步**的语法糖。

```js
const res = await fetch('/api/games')      // await：等结果回来再往下走
const data = await res.json()
```
- 只能在 `async` 函数里用 `await`；
- `await` 会**暂停当前函数**（不阻塞整个页面）；
- 失败时 `await` 会抛出，所以通常配 `try/catch`。

**本项目**：所有网络动作都是 async：`useAuth.ts:74` `await userStore.register(...)`、`useCustomFlow.ts:81` `await create({...})`。
**async 不得进 core**（core 必须同步可预测），也**不该进页面**（页面只接线）—— 见 03 册分层。

### 3.15 定时器与"防抖"

**是什么**：`setTimeout(fn, ms)` 是"过 ms 之后执行一次"；**防抖（debounce）** = "连续触发时，只在停止 ms 后执行一次"，典型用于搜索框（边打字边请求会发几十个请求）。

```js
setTimeout(() => doSearch(keyword), 300)
clearTimeout(timer)     // 取消上一次（这是防抖的关键）
```

**本项目**：自定义模式/搜索里"输入变化 → 稍后再查"，避免每敲一个字就请求一次后端（见 `useSearchPuzzle` 与 06 册）。

### 3.16 `Math` 与"为什么 core 不用 `Math.random`"

- `Math.floor / max / min / abs` 是纯函数，core 里到处用；
- **但 `Math.random()` 在 core 里被禁用**（守卫查 `Math.`）：它**不可复现** —— 同一份代码、同一份数据，每次跑出不同结果，测试和"复现 bug"都无从谈起。

**本项目的做法**：把"随机"变成**参数**（`Rng`，一个"给种子就给出稳定随机数序列"的函数），调用时才注入真正的随机源。这样：
- 测试里传固定种子 → 结果**每次一样**，可断言；
- 线上传随机种子 → 题目每局不同。
**"把不确定性推到边界、让核心保持确定"是这份代码最重要的设计思想之一**，04 册会专门讲。

## 4. TypeScript 必会清单（本项目所有你会在代码里撞到的类型写法）

> 一句话先天概念：**TS 类型只在"写代码 / 检查"时存在，编译后全部消失**（所以它能帮你抓错，但运行期不会有"类型"这个东西）。

### 4.1 类型注解与类型推断

```ts
const n: number = 1                    // 注解：你自己写
const m = 1                            // 推断：TS 从值猜出 m 是 number
const add = (a: number, b: number): number => a + b   // 参数要注解，返回值可写
```

**本项目**：函数返回值大量显式标注（`const createGroupScanner = (S: number, B: number): GroupScanner =>`，`groups.ts`）。**好处**：写函数时就确定"我给谁、返回什么"，且改坏了立刻报错。

### 4.2 `interface` 与 `type`（都是"给结构起名"）

```ts
interface Cell { v: number; lock: boolean }     // 对象结构（可扩展）
type Board = Cell[][]                            // 别名（数组、联合、函数都能起名）
```

**本项目（`src/types/board.ts:1-9`）**：

```ts
export interface Cell { v: number; lock: boolean }
export type Board = Cell[][]              // 二维：格子盘
export type NumBoard = number[][]         // 二维：数字盘（0 = 空）
export type ConflictMask = boolean[][]    // 二维：冲突标记
export type Snapshot = Cell[][]           // 二维：某一步的快照
export type Position = readonly [row: number, col: number]
```

**看这段要看出三件事**：
1. `Cell` 里 `v` 是数字、`lock` 是"是否锁死（题目给定，不能改）"→ 这就是"格子盘能表达的信息比数字盘多"的根源；
2. `NumBoard` 与 `Board` 是**两种盘面**（详见 04 册第 1 节），互相转换是显式函数，不许偷偷混用；
3. `Position` **不是普通数组**，见 §4.4。

### 4.3 字面量类型 + 联合类型（"只允许这几个值"）

```ts
type AuthMode = 'login' | 'signup'          // 只能是这两个字符串之一
let m: AuthMode = 'login'
m = 'abc'                                    // ❌ 报错：不在允许范围内
```

**本项目（`src/constants/pages.ts:1-14`）**：

```ts
export const PAGE = {
    Home: 'home',
    Difficulty: 'difficulty',
    ...
    Login: 'login',
} as const                                    // ← 关键
```

`as const` 的效果：`PAGE.Game` 的类型不是宽泛的 `string`，而是**字面量** `'game'`。
于是路由名写错一个字母 → **类型检查直接拦下**（而不会变成"运行时白屏"）。页面里没有裸写的 `'game'` 字符串，全用 `PAGE.Game`，这也是 R 规则里"路由名字集中一处"的做法。

### 4.4 元组与只读元组（`Position` 为什么不是普通数组）

```ts
type Pair = [number, number]                        // 元组：固定长度、固定位置含义
type Position = readonly [row: number, col: number]  // ① 只读 ② 还给了"位置名字"
```

**元组 vs 数组**：

| | 数组 `number[]` | 元组 `[number, number]` |
|---|---|---|
| 长度 | 任意 | 固定为 2 |
| 位置含义 | 无 | 第 0 位=行，第 1 位=列 |
| 写错 | 看不出来 | `p[2]`、只传一个都报错 |

`readonly` 的意义：**防止"顺手改坐标"**（`p[0] = 3` 会报错）。"位置"是值对象，改它等于换一个格子，绝不该原地改。
**具名标签 `[row: number, col: number]`** 的好处：你在 VS Code 里悬停能看到 `row`/`col`，而不是冷冰冰的 `0`/`1`。

### 4.5 可选属性、可选参数、默认值

```ts
interface Opts { size?: number }                     // 可缺省
const f = (a: number, b?: string) => {}              // 可缺省参数（必须放最后）
const g = (a: number, n = 9) => a * n                // 默认值（缺省时用 9）
```

**本项目**：`functions` 里查询参数（如 `?limit=`）天然可能缺失；处理时一定先判空（见 02 册后端的入参校验）。

### 4.6 `null` / `undefined` 与"类型收窄"

**是什么**：TS 会在 `if` 里**自动收窄**类型 —— 判断过后，后面的代码就能安全使用。

```ts
const read = (u: User | null): string => {
    if (!u) return ''          // 这一行之后，TS 知道 u 一定是 User
    return u.name              // ✅ 不再报"u 可能为 null"
}
```

**本项目**：`useAccountPanel.ts:20` `const loadUid = async (): Promise<string | null> => userStore.uid` —— 返回类型老老实实写 `string | null`，调用方必须处理"没登录"的情况。**这就是"看起来啰嗦但防雷"的写法**：把不确定性写在类型里，而不是"靠运气没崩"。

### 4.7 `Record` / `Readonly` / 索引签名

```ts
type Copy = Record<string, string>       // 任意字符串键 → string 值（相当于"文案字典"）
type Dict = Readonly<Record<string, number>>  // 只读，防误改
```

**本项目**：`constants/` 下的一批文案表（`AUTH_COPY`、自定义模式文案等）就是 `Record` 形状的**常量字典**；
**为什么必须"集中一处"**：历史上同一个"取消"按钮文案在 11 个地方重复写过，改一处漏一处 —— 现在统一从常量取（守卫也查"禁止在组件里裸写中文文案"这类散落）。

### 4.8 非空断言 `!` 与类型断言 `as`

```ts
map.get(v)!.push([r, c])        // ! ：我保证这里不是 null/undefined
const el = document.querySelector('#app') as HTMLDivElement   // as：我比你更懂它的类型
```

- `!`（非空断言）：**只在"你确实确定"时用**；用错 → 运行期 `Cannot read properties of undefined`；
- `as`（类型断言）：**强制重解释**，TS 不再检查。**本项目 `as` 只用于"外部世界的边界"**（如 `JSON.parse` 的结果、`wrangler` 的环境绑定），core 里几乎不出现。

**判据**：能用 `if` 判断解决就不用 `!`；能用类型守卫解决就不用 `as`。

### 4.9 泛型 `<T>`（"类型也可以是参数"）

**是什么**：写工具函数时不知道元素类型，就用 `<T>` 占位，调用时自动确定。

```ts
const first = <T>(arr: T[]): T | undefined => arr[0]
first([1, 2])        // T = number → 返回 number | undefined
first(['a'])         // T = string
```

**本项目（`src/core/array.ts` 全文，逐行）**：

```ts
import type { Rng } from "../types/rng";

/** 洗牌：原地打乱（Fisher–Yates），随机源由外部传入（可复现） */
export const shuffle = <T>(arr: T[], rng: Rng): void => {
    for (let i = arr.length - 1; i > 0; i--) {
        const j = Math.floor(rng() * (i + 1))
        ;[arr[i], arr[j]] = [arr[j], arr[i]]     // ← 解构交换：一行完成互换个
    }
}

/** 造 s×s 的二维数组，每个元素用同一个工厂函数生成 */
export const makeGrid = <T>(s: number, fn: () => T): T[][] =>
    Array.from({ length: s }, () => Array.from({ length: s }, fn))

/** 二维映射：把 T 的格子逐个变成 U（core/board/model.ts 用它做两种盘面互转） */
export const mapGrid = <T, U>(grid: T[][], fn: (v: T) => U): U[][] =>
    grid.map(row => row.map(fn))

/** 一维切块（分页/挖空都用到） */
export const chunk = <T>(arr: T[], size: number): T[][] =>
    Array.from(
        { length: Math.ceil(arr.length / size) },
        (_, i) => arr.slice(i * size, (i + 1) * size)
    )
```

**四个值得注意的点**：
1. `shuffle` 接 `rng: Rng` 而**不是**内部 `Math.random()` —— 这就是 §3.16 说的"可复现"；
2. `makeGrid` 接**工厂函数** `fn: () => T` 而不是"值"：因为要造 s×s 个**各自独立**的元素（传值会全是同一个引用！）；
3. `mapGrid<T, U>` 是"两个类型参数"，输入 `T[][]` 输出 `U[][]` —— 盘面互转的通用底座；
4. `Array.from({ length: s }, fn)` 的第一个参数只是"告诉我造几个"，`_` 表示"这个下标我用不到"（**用不到就显式用 `_` 命名**是本项目的约定：告诉读者"我故意忽略它"）。

### 4.10 函数类型（"把函数当参数传"）

```ts
type Rng = () => number                       // 无参、返回数字
type Handler = (n: number) => boolean         // 接数字、返回布尔
```

**本项目最典型的一处（`src/core/sudoku/generator.ts:131-137`）**：

```ts
const solved: NumBoard[] = []
solveGrid(seed, boxSize, rng, board => {      // ← 回调：搜到一个解就调用一次
    solved.push(board)
    return true                               // ← 返回 true = "够了，停止搜索"
})
if (!solved.length) throw new Error('生成失败')
return solved[0]
```

**这段话的含义**：求解器**不关心"你要一个解还是全部解"**，它只负责"搜到就问你一下"。
- 返回 `true` → 停止（本项目要**任一解**，够快）；
- 返回 `false` → 继续（"数独有多少解"这种统计就是靠它）。

**这是"控制反转"的最小例子**：把"继续/停止"的决定权交给调用方，而不是写死在算法里。`Rng`、`Validator` 都是同一套路。

### 4.11 `readonly` 与"不改入参"（core 的铁律在类型上的体现）

```ts
const push = (target: number[], item: number) => { target.push(item) }        // 会改调用者的数组！
const safe = (src: readonly number[]): number[] => [...src, 0]               // 声明"我不改你"
```

**本项目**：core 里凡是"读别人数据"的参数，尽量标 `readonly`（如 `readonly Position[]`）；要改就先复制（§3.11）。
**好处**：你"手滑写了 `board[r][c] = 5`"会**当场报错**，而不是等上线后出现"页面数据莫名变了"的诡异 bug。

### 4.12 `import type` 为什么要单独写

```ts
import type { NumBoard } from "../../types/board"     // ✅ 类型：编译后整行消失
import { makeGrid } from "../array"                    // ✅ 值：会被打包
```

如果写成 `import { NumBoard } from ...` —— 开着 `verbatimModuleSyntax` 时会**报错**，因为打包器不知道 `NumBoard` 是类型还是值，可能把"不存在的运行时代码"留在产物里。
**结论**：**只要 import 的东西"只用来当类型"，就写 `import type`**（守卫也会查）。

### 4.13 常见报错速查（看到就直接查这里）

| 报错 | 含义 | 该怎么改 |
|---|---|---|
| `TS6133: 'x' is declared but its value is never read` | 声明了没用 | 删掉它（或补上使用） |
| `TS2339: Property 'x' does not exist on type 'Y'` | Y 上没有 x 这个字段 | 名字拼错了 / 类型写错了 / 该字段不存在 |
| `TS18048: 'x' is possibly 'undefined'` | 可能为 undefined | 先 `if (!x) return`，或用 `??` 给默认值 |
| `TS2345: Argument of type 'A' is not assignable to parameter of type 'B'` | 传参类型不对 | 看两边类型差在哪（最常见：`number` vs `number \| null`） |
| `TS7006: Parameter 'x' implicitly has an 'any' type` | 参数没类型也推不出来 | 补注解 `(x: number) =>` |
| `TS2554: Expected 2 arguments, but got 1` | 参数个数不对 | 补参数或改签名 |
| `TS2322: Type 'A' is not assignable to type 'B'` | 赋值类型不兼容 | 同 TS2345，看"谁给的、谁要的" |

**读报错的顺序**：先看**第一行**（后面的错往往是被它连带的）→ 看**文件:行:列** → 悬停那个变量看 TS 认为它是什么类型。
