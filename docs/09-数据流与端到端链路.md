# 09 · 数据流与端到端链路

> **这一册讲什么**：把 04~08 册的零件**串成整链** —— 每条链路从"用户做了什么"出发，逐跳标注 **经过哪个文件、哪一层、哪个函数**，最后落在"哪块像素变了 / 哪条数据落了库"。
> **为什么要这一册**：单个文件看懂 ≠ 整条流程看懂。**排查问题时，你需要的是链路，不是函数。**

---

## 0. 读法

每条链路的格式：

```
【触发】用户/系统做了什么
  ① 文件:函数                      〔层〕  说明
  ② …
【落点】最终发生了什么
【如果断了】常见断点与排查方向
```

**层次标记**：`〔展示〕`= pages/components · `〔编排〕`= composables · `〔状态〕`= stores · `〔算法〕`= core · `〔适配〕`= render/services · `〔后端〕`= functions

**十二条链路**：
| # | 链路 | 一句话 |
|---|---|---|
| 1 | 系统生成一局 | 难度页 → Worker → 开局 → 画布 |
| 2 | **落子** | 点击 → 重绘 + 判胜 + 历史（**最核心的一条**） |
| 3 | 提示 | 选中格 → 候选 → 文案 |
| 4 | 重开 / 回退 | 历史快照跳转 |
| 5 | 导出题目 | 只导题面（不含答案与玩家填数） |
| 6 | 出题（两阶段） | 手填 → 锁题 → 填答案 → POST |
| 7 | 编辑 | 载入 → 两阶段 → PATCH |
| 8 | 自定义开局 | 两串 → 校验 →（可选提交）→ 开局 |
| 9 | 登录（五个子链） | 注册 / 登录 / 刷新恢复 / 退出 / 401 |
| 10 | 搜索 → 预览 → 挑战 | 列表 → 详情 → 开局 + 热度 |
| 11 | 求解 | Worker 多解 → 逐解浏览 |
| 12 | 我的题目行内改动 | PATCH/DELETE → 缓存失效 → 重拉 |

---

## 1. 十二条端到端链路

### 链路 1：系统生成一局

```
【触发】难度页点「▶ 开始游戏」
  ① pages/difficulty/SystemPage.vue          〔展示〕  按钮条 v-for → actions[0].onClick
     └─ actions 来自 useDifficultyFlow
  ② composables/game/useDifficultyFlow.apply()  〔编排〕
     ├─ if (loading) return                  双击保护
     ├─ const cfg = { boxSize, blankRatio }  现造干净的 cfg
     ├─ await generateInWorker(cfg.boxSize, blankCount)   ← blankCount 是 core 的 blankCountOf 派生
     │     └─ services/sudoku/workerClient.runInWorker
     │           ├─ new Worker(new URL('./worker.ts', import.meta.url), { type: 'module' })
     │           ├─ worker.postMessage({ kind: 'generate', boxSize, blanks })
     │           │     └─ services/sudoku/worker.onmessage〔适配〕
     │           │           └─ core/sudoku/generator.generatePuzzle(boxSize, blanks, Math.random)〔算法〕
     │           │                 ├─ generateSolution：patternBoard → randomTransform → 保留骨架 → solveGrid
     │           │                 └─ digPuzzle：三阶段挖空
     │           └─ onmessage → finish({ puzzle, solution })
     ├─ gameStore.startGame(puzzle, solution, cfg, GAME_ORIGIN.System)   〔状态〕
     │     ├─ mode/origin/config/board(=fromPuzzle(puzzle, true))/solution/meta
     │     └─ resetHistory()（第 0 步 = 开局盘）
     └─ router.replace({ name: PAGE.Game })
  ③ pages/GamePage.vue onMounted             〔展示〕
     └─ composables/game/useGameFlow 的 onMounted 守卫：mode 必须是 Game 且有盘 → 否则送回难度页
  ④ GamePage 的 boardParams computed          〔展示〕
     └─ store 的 board/sudoku.B/selected/conflictMask/zoom
  ⑤ components/BoardView.vue ─ useBoardCanvas.draw  〔适配〕
     └─ render/board.renderBoard(canvas, params) → 画出来
【落点】游戏页出现一道**题面锁定**（深色粗体）的盘；历史第 0 步已建立；`origin = System`（所以会显示「📋 导出题目」）
【如果断了】
  · 一直转圈 → Worker 超时（`DEFAULT_TIMEOUT` 15s）或 `generatePuzzle` 抛 "生成失败"
  · 跳到游戏页又弹回难度页 → `startGame` 没被调用（mode/board 没准备好）
  · 盘是空白的 → `renderBoard` 收到空 board（`board.value.length === 0`）
```

### 链路 2：落子（**最核心的一条**）

```
【触发】玩家点棋盘某一格 → 点数字键「5」
  ① components/BoardView.vue 的 canvas 收到 click        〔展示〕
     └─ useBoardCanvas.onCanvasClick(event)
           ├─ 三个守卫：canvas 存在 / interactive !== false / board 非空
           ├─ render/board.getClickPos(canvas, e, size)  〔适配〕
           │     └─ core/board/metrics.offsetToCell(offsetX, offsetY, rect.width, size)〔算法〕
           │           → [r, c] 或 null（越界）
           └─ onCellClick(pos) → emit('cell-click', pos)
  ② pages/GamePage.vue 模板                              〔展示〕
     └─ @cell-click="gameStore.select"     ← 页面直接把 store 动作接到事件上
  ③ stores/game.select(pos)                              〔状态〕
     └─ selected.value = pos
  ── 到这里只是"选中" ──
  ④ GamePage.boardParams 重算（含 selected）              〔展示〕
     └─ 传给 BoardView 的 props 变 → useBoardCanvas 的 watchEffect(draw) 命中
        → renderBoard 重画（新的选中框）                       〔适配+算法〕
  ⑤ 玩家点数字键 → components/NumberPad.vue emit('pick', 5)  〔展示〕
     └─ GamePage: @pick="gameStore.inputNum"
  ⑥ stores/game.inputNum(5)                              〔状态〕
     ├─ ① status 必须是 Playing（赢了/没开局不许落子）
     ├─ ② selected 必须存在
     ├─ ③ cell.lock 为假（题目给定的格子不能改）
     ├─ ④ cell.v !== 5（同值不重复写）
     ├─ cell.v = 5                        ← 就地改嵌套对象（深层响应式）
     └─ pushHistory()                     ← splice 截断未来 + push(cloneBoard(board))
  ⑦ 响应式连锁（同一次 tick 里 Vue 自动完成）              〔状态→展示〕
     ├─ board 变 → numBoard computed 失效
     │     ├─ conflictMask 重算（core/sudoku/rules.findConflicts）〔算法〕
     │     ├─ isWin 重算（rules.isSolved：isFull && !hasConflict）〔算法〕
     │     └─ status 重算（core/game/derive.statusOf）〔算法〕
     ├─ GamePage 的 boardParams 重算 → BoardView props 变
     └─ useBoardCanvas.draw → renderBoard 重画（数字 + 红底 + 选中框）〔适配〕
  ⑧ 若 status 变成 Won                                  〔展示〕
     └─ useGameFlow.winOverlay computed 有值 → <Overlay :show="!!winOverlay"> 弹出通关
【落点】格子显示蓝色「5」；如果造成冲突立刻变红底；历史条多一步；若填满且无冲突 → 通关遮罩
【如果断了】
  · 点了格子没反应（画布不变）→ `draw()` 的依赖没读到（watchEffect 早退问题，06 册 §4.2 ②）
  · 数字填不进去 → inputNum 的四个守卫之一（最常见：格子是 lock，或 status 不是 Playing）
  · 数字进去了但画布不更新 → 深层响应式断了（有人把 board 换成了 shallowRef）
  · 历史条没多一步 → pushHistory 没被调用（或 `cell.v === n` 提前 return 了）
```

### 链路 3：提示（💡）

```
【触发】点「💡 提示」
  ① GamePage 的按钮条 → actions 里的 hint.onClick    〔展示〕
     └─ useGameFlow.hint()                            〔编排〕
           ├─ const cands = gameStore.selected ? gameStore.getCandidates(selected) : []
           │     └─ stores/game.getCandidates(pos)
           │           └─ core/sudoku/rules.getCandidates(numBoard, pos)〔算法〕
           │                 （标记数组扫行列宫 → 返回可用数字）
           ├─ tip.value = core/game/derive.hintTextOf(gameStore.selectedCell, cands)〔算法〕
           │     （三分支：没选中 / 锁定格 / 可以填：3、5）
           └─ 结果写进 useGameFlow 的 tip ref（**不进 store**）
  ② GamePage 模板：<p v-if="tip" class="tip">{{ tip }}</p>   〔展示〕
【落点】页面上出现一行提示（例如「此格可以填：3、5、7」，或「无法更改初始题目」）
【如果断了】
  · 点提示没文字 → selected 为 null（提示会说「请选中一个格子」）
  · 提示「无候选」→ 说明玩家前面某个数字放错了（这不是 bug，是**诊断信息**，04 册 §15.2）
```

### 链路 4：重开 / 回退（历史快照）

```
【触发 A】点「↺ 重开」
  ① useGameFlow.restart()                        〔编排〕
     ├─ gameStore.jump(0)                        〔状态〕
     │     ├─ 越界守卫：0 < 0 || 0 >= snapshots.length → return（有守卫）
     │     ├─ board.value = cloneBoard(snapshots.value[0])   ← 必须再拷（05 册 §2.17）
     │     └─ currentStep.value = 0
     └─ answerOpen.value = false（收起答案遮罩）
【触发 B】点历史条上「第 1 步」
  ① components/PagerStepsView emit('change', 1)   〔展示〕
     └─ PagerBar.go(1)：按 mode 归一化边界 → emit('change', 1)
  ② GamePage: @change="gameStore.jump"            〔展示→状态〕
  ③ stores/game.jump(1)                           〔状态〕
     ├─ board.value = cloneBoard(snapshots.value[1])
     └─ currentStep.value = 1
  ④ 重绘 + 三个派生重算（同链路 2 的 ⑦）
【落点】盘面回到那一刻；`currentStep` 变了 → 步骤条高亮跟着走（`PagerStepsView` 还会自动把当前步滚进视野）
【如果断了】
  · 点了历史条没变化 → `jump` 的越界守卫拦住了（step 超出 snapshots 范围）
  · 跳回去之后盘面「混着」旧数据 → 有人把 `cloneBoard` 去掉了（快照与活动盘共享 Cell）
```

### 链路 5：导出题目（📋）

```
【触发】点「📋 导出题目」（只在 origin === System 时存在）
  ① useGameFlow.trailActions 里的 export 项（条件拼装产生）  〔编排〕
     └─ exportPuzzle()
           ├─ if (!gameStore.board.length) return
           └─ showExport(core/sudoku/parse.boardToStr(core/board/ops.givenBoard(gameStore.board)))
                 ├─ givenBoard：只留 lock 的格子（**抹掉玩家填的**）〔算法〕
                 └─ boardToStr：二维 → 空格分隔的串〔算法〕
  ② composables/usePuzzleExport.show(text)        〔编排〕
     └─ puzzleText.value = text; tip.value = ''; open.value = true
  ③ GamePage 的 Overlay（插槽里是 <textarea readonly :value="exportPuzzleText">）  〔展示〕
【触发】点遮罩里的「📋 复制题面」
  ④ usePuzzleExport.copyPuzzle()                  〔编排〕
     └─ composables/useClipboard.copy(text)
           └─ navigator.clipboard.writeText(text)〔适配/浏览器〕
     ├─ 成功：tip = '题面已复制'
     └─ 失败：tip = AUTH_COPY.copyFail 类似的兜底文案
【落点】剪贴板里是**纯题面串**（不含答案、不含玩家填的数字）—— 别人粘到「自定义」或「题目求解」就能用
【如果断了】
  · 按钮不显示 → `origin !== System`（自定义/挑战题不给导出，06 册 §5.6 ①）
  · 复制了但内容不对 → 用了 `toNum` 而不是 `givenBoard`（把玩家填的数也导出去了）
```

### 链路 6：出题（两阶段：题面 → 答案 → POST）

```
【触发】首页点「✏️ 出题模式」→ /create
  ① pages/CreatePage.vue onMounted → useCreateFlow.restart(默认 B)  〔编排〕
     ├─ reset()：resetStage() + showSuccess = false
     └─ gameStore.startCreate(boxSize)           〔状态〕
           └─ startInput(Create, boxSize)：fromPuzzle(空盘, false) → **不锁定**、可增量改
【阶段① 填题面】
  ② 点棋盘选格 → gameStore.select → 点数字键 → gameStore.inputNum（同链路 2）
     （此时格子 lock 全为 false → 都能改；历史照常记录）
  ③ 点「📤 提交题目」（actions 按 phase 切换文案）
     └─ usePuzzleStage.submitPuzzle()            〔编排〕
           ├─ core/message.puzzleSubmitErrorOf(numBoard, B, sudoku)〔算法〕
           │     四步：全空 → 有空行/列/宫 → 冲突 → 40%~65%（返回第一条不过的文案）
           ├─ 失败：errorMsg = 文案（**就地提示**，不弹遮罩）→ return false
           ├─ puzzleSnapshot.value = gameStore.numBoard    ← 存快照（题面要与答案成对）
           ├─ gameStore.lockPuzzle()                       〔状态〕
           │     └─ board = lockGiven(board)（非空格全部 lock=true）+ resetHistory()
           └─ phase = Solution
【阶段② 填答案】
  ④ 玩家继续点数字填满（输入的是"答案"）→ inputNum（现在题面格已锁定，改不了）
  ⑤ 点「📤 提交答案」
     └─ useCreateFlow.submitSolution()             〔编排〕
           ├─ ① checkSolution() → usePuzzleStage.checkSolution()
           │        └─ core/sudoku/rules.validatePuzzle(puzzleSnapshot, numBoard)〔算法〕
           │             四步：sameShape → hasConflict → isSubset → isSolved
           │        └─ 失败：errorMsg + showFail = true（弹遮罩）→ return false
           ├─ ② 标题校验（非空 + ≤ TITLE_MAX）→ 失败同样弹遮罩
           ├─ ③ await services/api/puzzleApi.create({ title, puzzleText: boardToStr(puzzleSnapshot),
           │        solutionText: boardToStr(gameStore.numBoard) })
           │     └─ client.request('/puzzles', { method:'POST', body })〔适配〕
           │           └─ functions/api/puzzles/index.ts onRequestPost〔后端〕
           │                 ├─ requireUser（Bearer → session → user）
           │                 ├─ checkPuzzle（**复用 core**：parsePuzzle / countBlanks / hasEmptyGroup /
           │                 │     isBlankRatioOk / validatePuzzle）
           │                 ├─ visibilityOf 白名单
           │                 ├─ makeUniqueId(makePid / makeRowId)
           │                 └─ INSERT INTO puzzle (...)
           ├─ ④ showSuccess = true（弹「🎉 出题完成」+「📋 去我的题目」）
           └─ 失败：errorMsg = errorTextOf(err, '提交失败，请重试') + showFail = true
【落点】题库里多一道题（`visibility` 默认 public）；出题页显示完成遮罩
【如果断了】
  · 提交题目没过 → `puzzleSubmitErrorOf` 的第一条不合格（看 errorMsg 就是原因）
  · 提交答案弹「未通过」→ `validatePuzzle` 四步之一失败（题面与答案不匹配 / 答案不是终盘）
  · 后端 400 → 服务端 `checkPuzzle` 拦下（**与前端同一套 core 规则**，所以前端过了后端也一般过）
```

### 链路 7：编辑自己的题（PATCH）

```
【触发】我的题目页某行点「编辑」→ /puzzle/:pid/edit
  ① useMyPuzzles.openEdit(rowId)                 〔编排〕
     ├─ loadPid(rowId) → puzzleStore.detailOf(rowId).pid（**走详情缓存**）
     └─ router.push({ name: PAGE.EditPuzzle, params: { pid } })
  ② pages/EditPuzzlePage.vue onMounted → useEditFlow.load()  〔编排〕
     ├─ const id = String(route.params.pid ?? '')（路径参数）
     ├─ if (!id) { goMyPuzzles(); return }
     ├─ resetStage()（清上一轮残留）
     ├─ await services/api/puzzleApi.getOne(id)    〔适配〕
     │     └─ functions/api/puzzles/[pid].ts onRequestGet〔后端〕
     │           ├─ load → 404 检查 → 可见性矩阵（private 非作者 → 404）
     │           └─ 答案按 show_solution 或"作者本人"下发
     ├─ core/sudoku/parse.parsePuzzle(detail.puzzleText)〔算法〕
     └─ gameStore.startCreate(parsed.boxSize, parsed.board)  〔状态〕（不锁定 → 可增量改）
【阶段① 改题面】③ 同链路 6 的 ② ③（提交题面 = 校验 + 锁题 + 进阶段②）
【阶段② 重填答案】④ 同链路 6 的 ④
  ⑤ 点「📤 提交答案」→ useEditFlow.submitSolution()
     ├─ checkSolution()（同链路 6，成对校验）
     └─ await update(pid, { puzzleText, solutionText })     〔适配〕
           └─ functions/api/puzzles/[pid].ts onRequestPatch〔后端〕
                 ├─ requireUser + 作者检查（row.uid === me.uid，否则 404）
                 ├─ 动态 sets/vals 拼接（只改给了的字段）
                 ├─ 若给了题面/答案 → checkPuzzle 复校 + 重算 blank_count
                 └─ UPDATE puzzle SET ... WHERE pid = ?
     └─ 成功后 goMyPuzzles()（**没有成功遮罩**，直接回列表）
【落点】库里这道题的题面/答案被更新（`created_at` 不变）
【如果断了】
  · 进页面就弹「题目不存在或不可访问」→ 不是作者（后端 404）或 pid 错
  · 保存后列表还是旧的 → 列表页没重拉（正常路径不需要：编辑是从列表进的，回列表会重挂载 → onMounted 重新 load 当前页）
```

### 链路 8：自定义开局（+ 可选提交）

```
【触发】难度页「自定义」Tab → 粘两串 → 点「▶ 开始游戏」
  ① pages/difficulty/CustomPage.vue v-model 写进 useCustomFlow 的 puzzleText/solutionText  〔展示→编排〕
  ② 输入框下方的实时提示                                   〔编排〕
     └─ puzzleInfo/solutionInfo computed：`${长度} 字符 · 识别为 9×9`
           └─ parsePuzzle（computed，**只解析一次**，校验/开局/提交三处复用）
  ③ 点「▶ 开始游戏」→ useCustomFlow.apply()                〔编排〕
     ├─ ① validate()：
     │     两串非空 → parsePuzzle 题面 → parsePuzzle 答案 → 尺寸一致 → isBlankBoard
     │     → getSudoku(B).hasEmptyGroup → getSudoku(B).validatePuzzle   ← **全在 core**
     │     （注意：**这里不查 40%~65%**，06 册 §5.5 ⑤）
     ├─ ② if (saveToMine && isGuest) → 提示"需要登录"并停住
     ├─ ③ if (saveToMine) { if (!(await save())) return; puzzleStore.flashSaved('已保存…') }
     │     └─ save()：标题校验 → blankRatioErrorOf（**比例只在提交时查**）→ create({ …, visibility: Private })
     ├─ ④ gameStore.startGame(p.board, s.board, { boxSize, blankRatio }, GAME_ORIGIN.Custom)〔状态〕
     └─ ⑤ router.push({ name: PAGE.Game })
  ④ 游戏页 onMounted（useGameFlow）
     ├─ 守卫通过
     └─ const saved = puzzleStore.takeSavedTip()   ← **取走即清**（跨页一次性提示的读取端）
           └─ tip.value = saved → 页面上出现「已保存到我的题目」
【落点】开局（题面锁定）；若勾了保存则题库里多一道 **private** 题，并在游戏页看到那条轻提示
【如果断了】
  · 提示"需要登录"→ 勾了保存但是游客（`saveToMine && isGuest`）
  · 提示比例不合规 → `blankRatioErrorOf`（这一步只在"提交到我的题目"时才有）
  · 开局了但没看到"已保存"提示 → `flashSaved` 与 `takeSavedTip` 没配对（或被 onMounted 之外的地方取走了）
```

### 链路 9：登录相关的五个子链

```
【子链 A：注册】
  ① LoginPage 表单 @submit.prevent → useAuth.submit()      〔展示→编排〕
     ├─ if (loading) return；error = validate()（UNAME_PATTERN / PASSWORD_MIN / 两次一致）
     ├─ await userStore.register({ uname, password })      〔状态〕
     │     └─ services/api/userApi.register()
     │           ├─ client.request('/register', { auth: false })〔适配〕
     │           │     └─ functions/api/register.ts〔后端〕
     │           │           ├─ UNAME_PATTERN / PASSWORD_MIN 复校
     │           │           ├─ makeUniqueId(makeUid) → makeSalt → hashPassword(PBKDF2) → INSERT user
     │           │           └─ makeToken → INSERT session → { token, user }
     │           ├─ setToken(res.token) + setLastUid(res.user.uid)   ← **凭据落在 api 层**
     │           └─ return { token, user }
     │     └─ userStore.profile = (await apiRegister()).user   ← **直写真源**
     └─ createdUid.value = userStore.uid → **不跳页**（弹账号 ID 卡片）
  ② 卡片：复制（useClipboard）或「我已保存」→ doneAfterSignUp()
     └─ createdUid = '' + router.replace(safeRedirect(redirect) || Home)

【子链 B：登录】
  ① useAuth.submit() → userStore.login() → userApi.login() → setToken/setLastUid → profile 赋值
  ② router.replace(safeRedirect(route.query.redirect) || { name: PAGE.Home })
     └─ safeRedirect 防开放重定向（06 册 §3.1 ②）

【子链 C：刷新页面后静默恢复】
  ① main.ts 装配 router → router/index.ts 的路由守卫
     └─ await userStore.restore()                     〔状态〕
           └─ pending ??= (async () => { profile = await apiMe() })()  ← **只发一次 + 可 await**
                 └─ userApi.me()：**无 token 直接返回 null（不发请求）**
                       └─ client.request('/me') → functions/api/me.ts onRequestGet → requireUser
  ② 若 401 → client.notifyUnauthorized() → clearToken + 广播 → userStore 的订阅把 profile 置 null

【子链 D：退出】
  ① useAccountPanel.logout()                             〔编排〕
     └─ await userStore.logout()                         〔状态〕
           └─ try { await apiLogout() } finally { profile = null }   ← 服务端失败也要清本地
                 └─ userApi.logout()：try{ request('/logout') } finally { clearToken() }
  ② await router.replace({ name: PAGE.Home })

【子链 E：任意请求遇到 401（token 过期）】
  ① 任何 services/api 调用 → client.request
  ② res.status === 401 → notifyUnauthorized()
     ├─ clearToken()                      本地凭据先清
     └─ unauthorizedListeners.forEach(cb => cb())
           └─ userStore 的 onUnauthorized 回调：profile.value = null
  ③ 继续走：抛 ApiError(401, 后端文案) → 调用方 catch → errorTextOf 显示（例如「登录已过期，请重新登录」）
  ④ 顶栏（AppLayout）立刻变成「👤 登录」            〔展示〕
【落点】登录态全局一致：本地凭据、store、界面三处同步
【如果断了】
  · 登录后顶栏还是「登录」→ `useAccountMenu` 忘了包 computed（06 册 §3.2 ①）
  · 刷新后登录态丢了 → `restore()` 没被守卫调用，或 `me()` 短路了（localStorage 里没 token）
  · 退出后还能请求 → `logout` 的 `finally` 忘了 `clearToken`，或 request 的 `auth` 默认值被改
```

## 2. 症状 → 链路排查法（**这一节最实用**）

### 2.1 通用排查顺序（**从下游往上游查**）

```
① 数据变了吗？        → 打开 Vue DevTools 看 store 的 ref / 组件的 props
② 如果没变：动作执行了吗？ → 在 composable 的动作里打断点 / console.log
③ 如果没执行：事件到了吗？ → 检查组件 emit 与页面的 @事件 绑定
④ 如果事件没到：DOM 元素对吗？ → 检查 v-if 条件、pointer-events、cursor
⑤ 如果数据变了但界面没变：   → 响应式断了（解构 / shallowRef / 忘了 computed）
```

### 2.2 十种常见症状 → 对应的链路断点

| 症状 | 最可能的断点 | 看哪一册 |
|---|---|---|
| **点了棋盘格子没反应** | `useBoardCanvas.onCanvasClick` 的三个守卫（`interactive===false` / 空盘 / 越界）；或 `draw()` 依赖没建立 | 06 §4.2 |
| **数字填不进去** | `inputNum` 的四个守卫（status / selected / lock / 同值） | 05 §2.16 |
| **数据变了但画布不更新** | 深层响应式断了（`board` 被换成 shallowRef / 有人直接替换了 `board.value[r]`） | 05 §2.16 ⑤ |
| **历史条不动** | `pushHistory` 没被调用，或 `cell.v === n` 提前 return | 05 §2.9 |
| **跳回历史后盘面"混"了** | 少了 `cloneBoard`（快照与活动盘共享 Cell） | 05 §2.17 |
| **搜索能搜、刷新就空白** | `useListQuery` 的 `watch(..., { immediate: true })` 被去掉 | 06 §2.4 |
| **翻页/搜索陷入死循环** | `loadAndClamp` 的 `if (bounded !== page.value)` 判断被删 | 06 §2.4 ⑥ |
| **登录后顶栏没变** | `useAccountMenu` 直接返回了 `userStore.isGuest` 的快照（没包 computed） | 06 §3.2 |
| **请求报"Unexpected token <"** | 接口路径写错 → 打到 `index.html`；`client.ts` 的非 JSON 检查被绕过 | 08 §4.3 |
| **一直转圈不结束** | 某个 `loading` 没在 `finally` 里复位 | 06 §8.1 |

### 2.3 三条"链路级"的纪律（本册的结论）

| 纪律 | 含义 | 例子 |
|---|---|---|
| **响应式链路要"全程连着"** | 从数据源到画布，中间任何一处"取值快照"都会断链 | `() => props` / `computed(() => store.x)` / 深层响应式 |
| **失败路径要和成功路径一样完整** | 每条 try 都要有 catch + finally；每个 loading 都要复位 | `finally { loading = false }` / 失败清数据 |
| **跨层只传"数据 + 回调"** | 事件向上、数据向下；适配器只暴露简单接口 | emit / props / `load` 注入 / `Action[]` |

### 2.4 一次"从症状到定位"的推理演示

> ⚠️ **这是演示**（用一个假设的症状，展示"沿链路排查"的方法），不是项目当前存在的 bug。

**假设症状**：在 16×16 盘面上玩，点格子后**选中框没出现**（但数字能填进去）。

```
① 数据变了吗？         DevTools → gameStore.selected 有值 ✅（说明 select 执行了）
② 界面变了吗？         看 BoardView 的 props：selected 有值 ✅（boardParams 重算了）
③ 那为什么没画？        → 嫌疑落在"画布重绘"这一段
④ 检查 useBoardCanvas.draw：它读 input() 拿到 selected → 传给 renderBoard ✅
⑤ 检查 renderBoard/drawCell：isSelected = !!selected && selected[0] === r && selected[1] === c ✅
⑥ 换个盘面试（9×9）：正常 ✅ → 说明逻辑没错，问题与"尺寸/缩放"有关
⑦ 看 16×16 的不同之处：zoom 默认 1.5（BOARD_ZOOM.default[4]）
⑧ 猜想候选（按链路顺序）：
   (a) useBoardZoom 的 watch 复位了 zoom → 触发重绘，而这次重绘用的是旧 props
   (b) draw() 的依赖没建立（watchEffect 早退）→ selected 变化不触发重绘
   (c) canZoom* / defaultZoomOf 的键用错 → zoom 异常导致画面裁剪，选中框在可视区外
⑨ 用"可控实验"区分三者：
   · 把盘面换成 9×9（缩放不变）→ 若正常 → 排除 (b)
   · 手动改 zoom（点缩放按钮）→ 若选中框正确移动 → 排除 (c)
   · 在 draw() 里打印 input().selected → 若每次都有值却"画了又被盖" → 指向 (a)
⑩ 定位到 (a) 的修法：确认重绘时机与 props 的更新顺序（或在 zoom 复位时同步触发一次重绘）
```
> **这段演示的重点不是结论，而是方法**：
> **① 先用"数据/事件/渲染"三段把范围缩小 → ② 再用"改变一个变量做对照实验"区分候选原因 → ③ 最后才去看那一行代码。**
> 这正是本册的最终目的 —— **把"猜"变成"查"。**
