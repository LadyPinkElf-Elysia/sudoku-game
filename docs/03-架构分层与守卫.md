## 1. 为什么需要"分层"（先讲痛点，再讲答案）

### 1.1 知识点：不分层的四个真实后果

| 后果 | 长什么样 |
|---|---|
| **改一处、崩三处** | 棋盘画法改一行，登录页也白屏了（因为大家都直接依赖底层细节） |
| **同一个规则有两份实现** | 前端提交校验"挖空 40%~65%"写一份，后端再写一份 → 总有一天两边不一致（本项目真的踩过：常量 65 而文案写 70） |
| **算法混在界面里** | 一个页面 `.vue` 里既有按钮，又有回溯求解 —— 想复用/想测试都做不到 |
| **新人不知道代码该放哪** | 同一个功能，三个人放在三个地方（有人放页面、有人放 store、有人放 utils） |

### 1.2 知识点：分层的本质是两件事

1. **职责边界**：每一层只干一类事（算法 / 状态 / 编排 / 绘制 / 接线）。
2. **依赖方向单向**：**上层可以依赖下层，下层绝不能依赖上层**。

**为什么"单向"这么重要**：如果 A 依赖 B、B 又依赖 A，那就变成"一团"：改 A 必然影响 B，反之亦然 —— **无法单独理解、无法单独替换、无法单独测试**。
单向依赖（类似组织结构里的"谁向谁汇报"）才可能出现"**我只读这一层的代码就能懂它**"。

### 1.3 本项目的一句话记忆

> **core 不认识 vue；stores 不认识 router；types 谁都不认识（除 types / constants）；组件不认识 store。**

这四句话对应四条最容易违反的红线（R3 / R4 / R13 / R5）。

## 2. 本项目的五层 + 三类适配器（`ARCHITECTURE.md §一`）

### 2.1 分层总表（带"判据"——怎么一眼认出这段代码属于哪层）

| 层 | 目录 | 一句话职责 | **判据**（出现什么就在这里） |
|---|---|---|---|
| 数据层 | `types/` `constants/` `stores/` `services/` | 有什么数据、存在哪、从哪来 | 需要「**记住**」或「**出去取**」 |
| 纯函数层 | `core/` | **怎么算** | 入参定则输出定，不碰任何外部 |
| 组合式层 | `composables/` | **什么时候算、算完干什么** | 出现 `ref` / `watch` / 生命周期 / `router` / `await` |
| 渲染适配器 | `render/` | **唯一碰 canvas** | 出现 `ctx` / `devicePixelRatio` |
| 服务适配器 | `services/` | **唯一碰 Worker / HTTP / 本地存储** | 出现 `new Worker` / `fetch` / `localStorage` |
| 后端适配器 | `functions/`（仓库顶层） | Cloudflare Functions + D1 | 出现 `D1Database` / `PagesFunction` |
| 展示层 | `components/` `pages/` | 画出来 / 接线 | **不写算式**（`Math.` 是被禁的） |

**"适配器"是什么意思**：**适配器 = 项目与外部世界（浏览器 / 网络 / 云）之间的那层薄壳**。
外部世界是"不纯"的（canvas 要画、网络会失败、localStorage 可能抛异常），所以把这些不纯的东西**集中封在少数几个文件里**，其余 90% 的代码（core、stores、composables）就能保持干净、可预测、可复用。

> **本项目的三环境复用**就是靠这个结构：`core` 不碰任何外部 → 于是它能被**浏览器主线程 / Web Worker / 后端函数**三处同时 import（02 册 §1.6）。

### 2.2 知识点：组合根（唯一的例外）

`src/main.ts` 与 `src/App.vue` 是**组合根（composition root）**：它们的职责是"**把整个应用装配起来**"（装 router、装 pinia、挂根组件），所以**它们可以依赖一切**（矩阵里写的是 `src: null, pkg: null`）。

**这条例外的意义**：不要为了"纯粹"把装配代码东躲西藏；**允许"最外层知道一切"，但只允许这一个地方知道**。

### 2.3 知识点：怎么用"判据"回答"这段代码该写哪层"

按顺序问自己（与 `CODE-GUIDE §6` 的决策树同源）：

```
1. 它只是"把现成数据摆到页面上"吗？            → pages（R6：只接线、声明 ≤10、禁 Math.）
2. 它能只靠入参算出确定结果吗？                → core（纯函数）
3. 它是"要记住的数据 / 要去取的数据"吗？        → stores（状态）或 services（取数据）
4. 它需要 ref / watch / 生命周期 / router 吗？  → composables
5. 它是"画"（props 进、事件出）吗？             → components
6. 它碰 canvas / 网络 / Worker / 本地存储吗？   → render / services（适配器）
```

**关键点**：**从下往上找第一个符合的**（算法归 core，不要因为"暂时只有页面用"就写进页面）。

## 3. 依赖矩阵（`ARCHITECTURE.md §二` = 守卫里的 `MATRIX`）逐格讲

### 3.1 矩阵原文（它也**字面**存在于 `scripts/check-arch.mjs:51-64`）

| 目录 | 允许的 src 前缀 | 允许的外部包 |
|---|---|---|
| `src/constants/` | （无） | （无） |
| `src/types/` | `src/types/`　`src/constants/` | （无） |
| `src/core/` | ＋`src/core/` | （无） |
| `src/services/` | ＋`src/services/` | （无） |
| `src/render/` | ＋`src/render/` | （无） |
| `src/stores/` | ＋`src/services/`　`src/stores/` | `vue`　`pinia` |
| `src/composables/` | ＋`src/render/`　`src/stores/`　`src/composables/` | `vue`　`vue-router` |
| `src/components/` | `src/components/`　`src/composables/`　`src/constants/`　`src/types/` | `vue`（**禁 `vue-router`**） |
| `src/pages/` | `src/pages/`　`src/components/`　`src/composables/`　`src/stores/`　`src/constants/`　`src/types/` | `vue`　`vue-router` |
| `src/router/` | `src/router/`　`src/stores/`　`src/constants/`　`src/types/` | `vue-router` |
| `src/`（`main.ts` / `App.vue`） | **允许一切** | 允许一切 |
| `functions/` | `functions/`　`src/core/`　`src/constants/`　`src/types/` | （无） |

### 3.2 逐行解释"为什么是这些"（这是本节的核心）

**① `constants/` 是叶子：谁也不依赖。**

```ts
// src/constants/game.ts 顶部 —— 一个 import 都没有（只有值和类型注解）
export const BLANK_RATIO = { min: 0.4, max: 0.65, step: 0.01 } as const
```
**为什么要求"零依赖"**：常量会被**所有层**引用（前端页面、后端函数、core 算法都读 `BLANK_RATIO`）。如果它自己还依赖别人的东西，就变成"**所有人都依赖它，它又依赖某些人**" → 循环风险。
**"只放值、不放类型"**（R10）也是这个道理：类型属于 `types/`，混进 constants 会让"值和契约"纠缠。

**② `types/` 只能依赖 `types/` + `constants/`（R13 "types 是叶子"）。**

**为什么**：类型是"**契约**"。如果 `types/board.ts` 里 `import` 了 `core` 的实现，就等于"契约依赖实现" → 实现一改，契约被迫改，最后所有引用类型的地方一起崩。
**所以**：`PuzzleData` 这种"由 core 产出的形状"也必须**手写**在 `types/` 里（不能 `ReturnType<typeof generatePuzzle>` 推导），就是为了**切断这层依赖**。

**③ `core/` 只能依赖 `core/` + `constants/` + `types/`，且外部包为零。**

- **零外部包**：core 不许 `import vue` / `pinia` / `vue-router` / `axios` / 任何第三方 → 保证它能被任何一个环境（浏览器 / Worker / 后端）直接跑；
- **不能依赖 stores**：如果 core 读 store，那它就"有状态"了，同一份输入可能出不同结果（**不可测、不可复现**）；
- **不能依赖 services**：core 里不能发请求/读 localStorage（那是"外部世界"）。

**④ `services/` 只能依赖 `services/` + `core/` + `constants/` + `types/`，且不许碰 `stores` / `router`。**

**这是"服务适配器"最关键的一条**（`ARCHITECTURE R2` 专门强调）：

```ts
// ✅ 正确：services/api/client.ts 只管"发请求 + 把响应变成数据/错误"
// ❌ 错误：import { useUserStore } from '@/stores/user'   ← 违反 R2
```

**为什么禁**：如果"请求层"去操作 store，就会出现**隐式耦合**：
- 你只想"请求一下数据"，却意外改了全局状态；
- 更糟的是**循环**：`stores/user.ts` 要调用 `apiLogin()`（services），services 又反过来 import `stores/user` → **环**。
**那"401 时清登录态"怎么办**（02 册 §1.6 提到的）？→ 用**观察者模式**解耦：`client.ts` 维护一个监听者集合（`new Set<Listener>()`，`unauthorizedListeners`），`stores/user.ts` 注册回调（`onUnauthorized(() => { profile.value = null })`）。

> **知识点**：**当下层需要通知上层时，用"事件/回调注册"，不要让下层 import 上层**。这是打破循环依赖的标准手法（浏览器里的 DOM 事件、Node 的 EventEmitter 都是同一思想）。

**⑤ `render/` 同理（外部包为零、不碰 stores/router）**：它只负责"给我数据和 canvas，我画出来"。`render/board.ts` 里甚至**只用 `@/core/board/metrics` 的纯计算**（`boardSideOf` / `cellSizeOf`）—— **尺寸换算属于"算"，所以归 core；draw 属于"画"，所以归 render**。这个切分非常讲究。

**⑥ `stores/` 可以依赖 `services`（取数据）+ `core`（算数）+ `constants`/`types`，外部包只有 `vue` + `pinia`。**

- 不能 `vue-router`（R4）→ **跳转是"编排"，归 composables / pages / router**；
- 不能写 `for (` / `.forEach(` / `Math.`（R4）→ store 只做"**取值 → 调 core 的纯函数 → 写回**"。
  **为什么**：算法写在 store 里就**没法被后端/Worker 复用**了（core 才能复用）。

**⑦ `composables/` 可以依赖 `render` / `stores` / `core` / `services` / `constants` / `types`，外部包 `vue` + `vue-router`。**

这是**唯一既有响应式又有 router 又有异步的层** —— 所以"什么时候算、算完干什么"全在这里（R7）。它是**五层里最"自由"的一层**，但也因此有两条约束不要忘：禁 `Math.`（算式下沉 core）、"一页一份"的实例只在页面 setup 顶层调一次。

**⑧ `components/` 不许碰 `stores`，也不许碰 `vue-router`（R5）。**

```ts
// ✅ BoardView.vue 的做法：props 进、事件出
const props = withDefaults(defineProps<{ board: Board; boxSize: number; ... }>(), {...})
const emit = defineEmits<{ 'cell-click': [pos: Position] }>()
```

**为什么禁 store**：组件要**可复用**（`BoardView` 同时用于"玩游戏"和"看答案"）—— 如果它自己去读 `gameStore.board`，那就没法在"看答案"场景里复用（那里要显示的是答案盘）。
**为什么禁 router**：路由跳转是"页面的决定"，组件只该 `emit` 事件；顺带解释了为什么"需要读 store 的布局组件"放在 `pages/`（`pages/AppLayout.vue`）而不是 `components/`。

**⑨ `pages/` 是唯一能用 `vue-router` 的展示层（配 R6）。**

页面要 `RouterLink`、`useRouter`（返回上一页、登录后跳转）。但**只许接线**（声明 ≤10、禁 `Math.`）—— 具体动作仍要落到 composable。

**⑩ `router/` 可以依赖 `stores`**（这是矩阵里少见的"向上"依赖）：

```ts
// router/index.ts 的守卫会 await userStore.restore() 再判断登录态
```
**为什么允许**：路由守卫的职责本身就是"**在进入页面前检查全局状态**"（如未登录就送去登录页）。它能读 store，但**不能反向被 store 依赖**（store 不许 import router，R4/R2）。
**注意这也解释了为什么 `stores/user.ts` 的 `restore()` 要做成"幂等 + 并发去重"**：守卫可能被多次触发（02 册 §2.3 ⑥）。

**⑪ `functions/`（后端）只能依赖 `functions/` + `src/core/` + `src/constants/` + `src/types/`：**

- **不能 `import vue` / `pinia`** —— 后端没有 Vue；
- **能 import `core`** —— 这正是"规则只有一份"的实现方式（02 册 §1.6）。

### 3.3 知识点：相对路径按"解析后路径"判定

矩阵检查的不是"你写了什么字符串"，而是**解析后的仓库路径**：

```ts
// scripts/check-arch.mjs 的 repoTarget()
'@/board/metrics'   →  'src/board/metrics'        // 别名先还原成 src/...
'../array'（在 src/core/sudoku/rules.ts 里）  →  'src/core/array'   // 相对路径按目录拼、遇 .. 弹出
```

**所以**：`src/core/sudoku/rules.ts` 里 `import { makeGrid } from "../array"` = 依赖 `src/core/array` ✅（同层允许），而不是"看起来的上一层"。
**这也是为什么不让 core 用 `@/` 别名**（00 册 §2.5）：core 要在三个环境里跑，而别名只在 Vite/前端的 tsconfig 里有。

### 3.4 知识点：两条全局禁令

1. **禁 `axios`**（`FORBIDDEN_PKGS`，报错信息："已移除，请用 fetch"）
   **为什么**：多一个第三方 HTTP 库 = 多一份体积、多一套错误模型。本项目统一用 `fetch` + 自己在 `services/api/client.ts` 里做"统一错误处理"，**请求层的规则只有一处**。
2. **允许 `node:` 前缀**（如 `node:fs`）—— 守卫脚本本身用，业务代码几乎不用。

### 3.5 知识点：为什么禁"桶文件"（R12）

```ts
// ❌ 被禁的写法（桶文件 / barrel file）
export * from './board'
export * from './sudoku'
```

**为什么禁**：
- **隐式依赖**：别人 `import { digPuzzle } from '@/core'`，看不出它到底从哪个文件来；删除/移动文件时错误信息也指向桶；
- **打包负担**：`export *` 让打包器难以 tree-shake（本来只用 1 个函数，可能把整目录拖进来）；
- **循环依赖的温床**：两个桶互相 `export *` 就成环。

**本项目的替代做法**：**谁用谁直接从源文件 import**（`import { digPuzzle } from '@/core/sudoku/digger'`）—— 显式、可追踪、可删除。

## 4. 规则逐条（R1~R15：每条 = 为什么 + 机器怎么查 + 违规长什么样 + 怎么改）

> 级别说明：🔴 = 守卫会拦（`pnpm guard` exit 1）；评审 = 脚本查不了，靠人和 PR 检查。
> **所有正则与预算常量都在 `scripts/check-arch.mjs` 顶部**（§6 会讲它们怎么被执行）。

### R1 顶层目录白名单 🔴

- **规矩**：`src/` 下只能有 `core services render stores composables components pages constants types styles router main.ts App.vue`（还有 `assets`）。
- **为什么**：**目录结构就是架构**。允许随手加 `src/utils/`、`src/libs/`，一年后就会变成"什么都往里塞"的垃圾桶目录，分层立刻失效。
- **机器怎么查**：

```js
const TOP_ALLOW = new Set(['core','services','render','stores','composables','components',
                           'pages','constants','types','styles','router','main.ts','App.vue','assets'])
// 扫描 src/ 顶层名；不在集合里 → err('R1', `src/${name}`, '顶层不在白名单（见 ARCHITECTURE.md R1）')
```
- **违规长什么样**：报错文本是 `[R1] src/utils  顶层不在白名单（见 ARCHITECTURE.md R1）`
- **怎么改**：想放工具函数 → 归到一个已有层（能纯算 → `core/`；要响应式 → `composables/`；只放值 → `constants/`）。真想加目录 → **先改 `ARCHITECTURE.md §一/§二` 与守卫 `TOP_ALLOW`，再写代码**（顺序不能反）。

### R2 依赖只按矩阵向下 🔴

- **规矩**：`§3.1` 那张表；`src/**` 与 `functions/**` 都查；外部包按白名单查。
- **为什么**：矩阵是"**架构可维护性的全部技术手段**"—— 只要依赖方向不乱，任何一层都能被单独理解/替换/测试。
- **机器怎么查**（守卫核心循环，逐 import 判断）：

```js
for (const spec of importsOf(code)) {
    if (spec.startsWith('@/') || spec.startsWith('.')) {          // 内部依赖
        const target = repoTarget(file, spec)                     // → src/xxx 这种仓库路径
        const allow = MATRIX[layerOf(file)].src                    // 本层允许的 src 前缀
        if (!allow.some(p => target.startsWith(p))) err('R2', file, `不允许依赖 ${target}`)
    } else {                                                      // 外部包
        if (FORBIDDEN_PKGS.has(bare)) err('R2', file, `${spec} 已移除，请用 fetch`)
        if (!pkgAllow.includes(bare)) err('R2', file, ...)
    }
}
```
- **违规长什么样**：`[R2] src/components/BoardView.vue  不允许依赖 src/stores/game`
  （注意：如果违规的是"组件 import store"，守卫会**优先报 R5** —— 更精确的规则先报，见 R5）
- **怎么改**：① 数据用 props 从页面传下来；② 或者把这段逻辑搬去 composable，页面调 composable。

### R3 core 纯度 🔴

- **规矩**：`core/**` 不许出现 `window` `document` `localStorage` `sessionStorage` `navigator`、`new Worker`、`Math.random`、`Date.now`、`new Date(`、`console.`；也不许 `vue`/`pinia`/`vue-router`（那条由 R2 管）。
- **为什么**：core 要在**三个环境**里跑（浏览器 / Worker / 后端），而且要被**测试与复现**。碰宿主对象 → 后端跑不起来；用 `Math.random`/`Date.now` → 同一输入不同输出，不可测。
- **机器怎么查**：

```js
const HOST   = /\b(window|document|localStorage|sessionStorage|navigator)\b/
const IMPURE = /Math\.random|Date\.now|new Date\(/
// core 文件里命中 → err('R3', file, 'core 不得访问宿主对象' / 'core 不得用不可控随机/时间，请由调用方注入 rng')
```
- **违规长什么样**：`[R3] src/core/sudoku/generator.ts  core 不得用不可控随机/时间，请由调用方注入 rng`
- **怎么改**（本项目标准答案）：**把"不确定"变成参数**（00 册 §3.16）：

```ts
// ❌ const i = Math.floor(Math.random() * n)
// ✅
export const generatePuzzle = (boxSize: number, blanks: number, rng: Rng) => { const x = rng() }
```
调用方（services/composables）负责提供真正的随机源；测试时传固定序列。

### R4 数据层不写算法 🔴

- **规矩**：`stores/**` 禁 `for (`、`.forEach(`、`Math.`；禁 `vue-router`。
- **为什么**：
  - **禁算法**：store 里的算法**没法被后端/Worker 复用**（只有 core 能）；而且"数据层出现 for 循环"往往意味着"这段逻辑本该是 core 的一个纯函数"。
  - **禁路由**：跳转属于"流程编排"，放 composables / pages；store 一旦能跳转，就再也没法在非路由环境里用（也不可测）。
- **机器怎么查**：

```js
const ALGO_IN_DATA = /\bfor\s*\(|\.forEach\(|Math\./
// stores 文件命中 → err('R4', file, '数据层出现算法，请下沉 core')
// import vue-router → err('R4', file, 'store 不得碰路由')
```
- **违规长什么样**：`[R4] src/stores/game.ts  数据层出现算法，请下沉 core`
- **怎么改**：把循环/算式写成 core 的纯函数（例如 `getCandidates` 在 `core/sudoku/rules.ts`），store 里只写：

```ts
// store 允许的形态：取值 → 调 core → 写回
const cands = getCandidates(numBoardOf(board), pos)
```
（`for` 只能出现在 core；`map/filter` 这类**没有显式 `for` 关键字**的写法在 store 里也不该用来做"算法"，但守卫只拦得到 `for (`/`.forEach(`/`Math.` —— 所以 R4 也有"评审"的部分。）

### R5 展示层不碰状态 🔴

- **规矩**：`components/**` 禁 `@/stores/**`；**也禁 `vue-router`**。
- **为什么**：
  - **禁 store** → 组件才能复用（同一个 `BoardView` 既能显示"玩游戏"的盘，也能显示"参考答案"的盘，还能显示"预览"的盘）；
  - **禁 router** → 组件不知道"我在哪个页面"，它只 `emit` 事件，让页面决定跳不跳。
- **机器怎么查**：

```js
// 组件里 import '@/stores/...' → 报 R5（而不是 R2）：更精确的规则优先
const id = under(file, 'src/components') && target.startsWith('src/stores/') ? 'R5' : 'R2'
// 组件里 import vue-router → 也是 R5
```
- **违规长什么样**：`[R5] src/components/PuzzleCard.vue  展示层不得依赖 store / router`
- **怎么改**：
  1. 数据由页面通过 props 传下来（`<BoardView v-bind="boardParams" />`）；
  2. 动作 emit 给页面（`@cell-click="gameStore.select"`）；
  3. **"需要读 store 的布局"放 `pages/`**（`pages/AppLayout.vue`）—— R5 的注释专门写了这条，因为"布局"最容易被误当成组件。

### R6 页面只接线 🔴

- **规矩**：`pages/**`（含子页面 `pages/difficulty/*.vue`）：
  ① **声明（`const`/`function`）≤ 10**；
  ② **禁 `Math.`**；
  ③ 只许 import `vue` `vue-router` 与 `@/pages` `@/components` `@/composables` `@/stores` `@/constants` `@/types`（**不许 `core` / `services` / `render`** —— 那条由 R2 保证）。
- **为什么**：
  - **声明 ≤10** 是"**页面薄**"的**可度量指标**：逻辑一多必然超，于是"逼"你把逻辑搬去 composable；
  - **禁 `Math.`** 保证"算式只有一份（在 core）"；
  - **不许 import core/services/render** 保证页面**不越层**：页面要"算好的值"就找 composable 要。
- **机器怎么查**：

```js
const MAX_PAGE_DECLS = 10
const MATH = /Math\./
// 只取 <script…> 到 </script> 之间的内容，然后数"行首（允许缩进）的 const / function / async function"
const script = code.slice(code.indexOf('<script'), code.indexOf('</script>'))
const decls = (script.match(/^\s*(const|function|async function)\s/gm) || []).length
if (decls > MAX_PAGE_DECLS) err('R6', file, `页面声明 ${decls} 个 > ${MAX_PAGE_DECLS}`)
if (MATH.test(bare)) err('R6', file, '页面出现算式（Math.），请下沉 core 或放进 composable')
```

**注意它是"代理指标"（近似算法）**：
- `^\s*` 允许缩进 → **函数体内部的 `const` 也会被算进去**（所以它是**偏严**的，宁可多算也不漏算）；
- `computed` 也是一个 `const` → **写几个 `computed` 就算几个声明**；
- 好在 `MATH` 那条是**精确**的（直接查 `Math.`），所以 R6 的"防守"是双保险。
- **违规长什么样**：`[R6] src/pages/GamePage.vue  页面声明 12 个 > 10`
- **怎么改**：把相关的 `ref`/`computed`/`watch`/函数**成组搬进一个 composable**（本项目就是这么长出一批 `useXxxFlow` 的：`useGameFlow`、`useCreateFlow`、`useSolveFlow`…），页面只保留"取它返回的东西 + 传给组件"。
  **真实对照**：`GamePage.vue` 现在只有 **7 个声明**（正文 01 册 §1.12 有清单）。

### R7 组合式只编排 🔴

- **规矩**：
  - `composables/**` 禁 `Math.`（算式下沉 core）；
  - **"一页一份"的实例**（`useBoardZoom` / `useZoom`）**只在页面 setup 顶层调一次**，其余地方靠**参数注入**；
  - 可复用的控件定义（需要闭包的）**随 composable 返回**，由页面 spread（例：`useBoardZoom(…).zoomActions`）。
- **为什么**：
  - **禁 Math.**：见 R6；
  - **只调一次**：如果"棋盘缩放"在多处各调一次 `useZoom()`，就会有两份互不相干的 `zoom`（点了没反应 / 显示不一致）。**同一块 UI 的缩放必须是一份状态**；
  - **控件随 composable 返回**：按钮"能不能点"取决于状态（缩放到头了就不能再放大）—— 只有持有 `zoom` 的 composable 知道这件事，所以按钮数据（`Actions`）由它给出（`01 册 §3.7` 的 `zoomActions`）。
- **机器怎么查**：只用 `MATH` 查 `Math.`（"只调一次"和"参数注入"是**评审规则**，脚本查不了）。
- **违规长什么样**：`[R7] src/composables/game/useGameFlow.ts  组合式出现算式，请下沉 core`
- **怎么改**：把算式写进 core 的纯函数（如 `defaultZoomOf(boxSize)`、`hintTextOf(cell, cands)`），composable 只调用。
- **例外**：**E5**（`usePuzzlePreview` 内部的 `useZoom`）是"不同 canvas 的独立缩放"，**不算违反"只调一次"**（因为作用域本来就不同）。

### R8 命名成套 🔴（常量命名）/ 评审（其余）

- **规矩**：命名必须能"望文知义"：

| 前缀/后缀 | 含义 | 本项目实例 |
|---|---|---|
| `xxxOf` | **由入参算出来的值** | `cellSizeOf(side, size)`、`defaultZoomOf(boxSize)`、`hintTextOf(cell, cands)` |
| `is` / `has` / `can` | 返回布尔 | `isBlankRatioOk`、`hasEmptyGroup`、`canZoomInFrom` |
| `get` | 取值（可能带缓存） | `getSudoku(boxSize)`、`getCandidates` |
| `make` / `create` | 造出一个新对象 | `makeId`、`makeGrid`、`createSudoku` |
| `generate` | 生成（一次性造一整份） | `generatePuzzle` |
| `parse` / `xxxToStr` | 字符串 ↔ 数据 | `parsePuzzle(text)`、`boardToStr(board)` |
| `clone` | 拷贝 | （本项目用 `map(row => [...row])` 表达，未单独命名） |
| `use` | 组合式函数（composable） | `useGameFlow`、`useBoardZoom` |

- **展示项的契约**：`Action = { key, text, onClick? }` —— **不给 `onClick` 就是纯文本**（禁用态也这么表达，见 `useZoom.ts` 的 `zoomActions`）；`Menu` / `Menus` 是首页入口（`key / icon? / message / routeName / disabled?`），两者**不再共用基类**。
- **机器怎么查**（只查得动两条）：

```js
const CONST_NAME = /^[A-Z][A-Z0-9_]*$/                 // constants 导出名必须 UPPER_SNAKE
const COMPOSABLE_NAME = /\/use[A-Z]/                    // composables/** 的 .ts 文件名必须 use 开头
const COMPOSABLE_EXEMPT = new Set(['src/composables/puzzle/metaText.ts'])   // 例外 E8
```
- **违规长什么样**：`[R8] src/constants/game.ts  常量名 blankRatio 应为 UPPER_SNAKE_CASE`
- **怎么改**：改名（并全局替换引用）；纯函数模块（如 `puzzle/metaText.ts`）要么改名 `useXxx`，要么登记到 `COMPOSABLE_EXEMPT`。

### R9 体量预算 🔴

- **规矩**：单文件 **≤ 200 行**；`core` 单文件导出 **2~8 个**；`core` 的"唯一入口模块"允许 1 个导出但 **≥ 50 行**（避免碎成一堆小文件）。
- **为什么**：
  - **200 行**：一份文件能"一眼看完"的上限。超了说明它承担了多个职责 → 该拆；
  - **导出 2~8 个**：导出太少 → 文件太碎（找起来累、跳转多）；太多 → 这个模块是"大杂烩"，说明该分域（本项目 `core/board/model.ts` 与 `core/board/ops.ts` 就是这么分出来的）。
- **机器怎么查**：

```js
const MAX_LINES = 200, MAX_CORE_EXPORTS = 8, MIN_SOLO_MODULE_LINES = 50, MAX_PAGE_DECLS = 10
if (lines > MAX_LINES) err('R9', file, `${lines} 行 > ${MAX_LINES}，请拆文件`)
if (exp > MAX_CORE_EXPORTS) err('R9', file, `core 导出 ${exp} 个 > ${MAX_CORE_EXPORTS}`)
if (core && exp === 1 && lines < MIN_SOLO_MODULE_LINES) err('R9', file, '单函数文件，请并入同域文件')
```
- **注意**：**行数按"不含结尾换行"计**（守卫修过 off-by-one）—— 所以你正好 200 行不会被误报。
- **怎么改**：拆分而非放宽上限。**"要加第 9 个导出时不要放宽限制，改拆文件"**是这条规则的明文要求。

### R10 类型归位 🔴（多数）/ 评审（`extends` 用法）

- **规矩**（六条，都很实用）：
  1. **共享类型（≥2 个"非父子"文件使用）→ `types/`**；
  2. **types/ 里的类型必须有使用点**（死类型删掉或登记 `RESERVED_TYPES`）；
  3. **组件本地 props / emits → 就地写在 `defineProps<{…}>` / `defineEmits<{…}>`**；
  4. **单文件私有类型 → 留在原文件**（例：`core/sudoku/tracker.ts` 的 `Change`）；
  5. **一个形状只留一份接口**：需要"少一个字段"时**不要 `extends` / `Omit` 再开一个名字**，改成把该字段变成**函数参数**；
  6. **`constants/` 不许导出类型**；**敏感字段不进前端类型**（`uid` 不出现在题目相关类型里；列表不下发题面串）。
- **为什么**：
  - **禁 `Omit/Pick/Partial` 派生**：那会造出"同形状的第二个名字"，读代码时要来回跳着对照（"这个 `Omit<Puzzle, 'uid'>` 到底是什么？"）。**改成函数参数**（`fn(puzzle, { omitUid: true })` 或直接拆函数）更清晰；
  - **禁死类型**：`types/` 是"共享契约目录"，放没人用的类型会让人误以为"这里的东西都在用"；
  - **外部资源不进数据对象**：`canvas` / `DOM` / `Worker` / 定时器要**用参数传**（否则"纯数据"就被污染，没法序列化、没法传给 Worker）。
- **机器怎么查**：

```js
const TYPE_DERIVE = /\b(Omit|Pick|Partial|Required|Exclude|Extract)/   // 命中 → 报错
const RESERVED_TYPES = new Set([])                                     // 死类型白名单（当前为空）
// 扫描 types/ 的每个导出名，出现次数 < 2 且不在白名单 → '只有定义没有使用点'
```
- **违规长什么样**：`[R10] src/types/puzzle.ts:12  不要用 Omit/Pick/Partial 派生「同形状的第二个名字」，改成函数参数`
- **怎么改**：见上（拆函数 / 直接手写契约 / 删掉死类型）。
- **对照组**：`types/board.ts` 的 `Cell` `Board` `NumBoard` `ConflictMask` `Snapshot` `Position` 都被 ≥2 个文件用 → 合格；`GameStore` 类型留在 `stores/game.ts`（因为它依赖 Pinia 的 store 实例类型，不能进 `types/`，见 E3）。

### R11 core 必须可测 🔴（可测性）/ **不强制测试**

- **规矩**：`core/**` **不得有模块级可变状态**（顶层 `let` / `var` / `new Map|Set|WeakMap|WeakSet`）。
- **为什么**：模块级状态**会在用例之间串味** —— 上一个用例写进去的东西，下一个用例还能看到，于是"单测通过了但合起来跑就失败"。纯函数层必须"每次调用都从零开始"。
- **机器怎么查**：

```js
const CORE_STATE = /^(?:let|var)\s|^const\s+\w+\s*=\s*new\s+(?:Map|Set|WeakMap|WeakSet)\b/m
const CORE_STATE_EXEMPT = new Set(['src/core/sudoku/rules.ts'])     // 例外 E1
```
- **唯一的例外 E1**：`core/sudoku/rules.ts:169` 的 `const cache = new Map<number, Sudoku>()`（`getSudoku` 的记忆化缓存）。它登记为"**对入参可观察等价于纯函数**"——因为 `Sudoku` 是按 `boxSize` 生成的**无状态工厂**，缓存它不改变任何可观察行为。
  > **这就是"例外要登记、并说明理由"的价值**：不是"我不管规则了"，而是"这里确实需要一个缓存，且它不影响纯度"。
- **重要澄清**：**这条规则不要求你写测试**：
  > v1.7 废止的是「每个 `core/**/*.ts` 配同名 `.test.ts` + `--strict` 考核」那套**强制测试**；
  > v1.9.6 恢复的是「**可测**」这条**设计约束**。「可以测」≠「必须测」。
  守卫里 `isTest = file => file.endsWith('.test.ts')`（**测试文件被豁免，不会被拦**）—— 你想补测试随时补，只是仓库不预置测试工具链。

### R12 禁桶文件 🔴

- **规矩**：不写 `export * from`；不跨层再导出。
- **为什么**：见 §3.5。
- **机器怎么查**：`const BARREL = /^export\s+\*\s+from/m` → `err('R12', file, '禁止桶文件（export * from）')`
- **怎么改**：谁用谁直接 import 源文件。

### R13 types 是叶子层 🔴

- **规矩**：`types/**` 只许 `./xxx`、`@/types/...`、`@/constants/...`。
- **为什么**：见 §3.2 ②（契约不能依赖实现）。
- **机器怎么查**：由 R2 矩阵顺带保证，但**报错会单独标 R13**（方便你一眼知道是"类型层越界了"）：

```js
const id = under(file, 'src/types') ? 'R13' : 'R2'
```
- **违规长什么样**：`[R13] src/types/puzzle.ts  不允许依赖 src/core/sudoku/shape`
- **怎么改**：把需要的形状**手写**在 `types/` 里（本项目 `PuzzleData`、`Sudoku` 都是手写契约，见 `ARCHITECTURE §九`）。

### R14 有棋盘就必须能缩放 🔴

- **规矩**：任何 `.vue` 里 import 了 `BoardView`，就必须出现 `useZoom(` / `useBoardZoom(` 或 `:zoom-actions="…"`。
- **为什么**：大棋盘（16×16、36×36…）在小屏上根本放不下，**缩放不是可选功能**。把这条写成机器规则，就不会出现"新页面忘了加缩放"。
- **顺带的两条设计约定**：
  - **默认缩放按盘面大小取**（`BOARD_ZOOM.default` 字典：键 = 宫边长 B，如 9×9 → 1.25、36×36 → 2.5），并且**跟着盘面大小走**（`useBoardZoom` 在尺寸变化时自动复位，01 册 §1.5）；没登记时兜底 `BOARD_ZOOM.min = 1`；
  - **列表项不渲染棋盘**（列表里只显示元信息，避免一页几十个 canvas）。
- **机器怎么查**：

```js
const BOARD_VIEW = /BoardView\.vue/
const ZOOM_ENTRY = /useZoom\(|useBoardZoom\(|zoom-actions=/
```
- **怎么改**：给棋盘接上缩放数据（页面一行：`const { zoom, zoomActions } = useBoardZoom(() => gameStore.config.boxSize)`）。

### R15 状态归位 评审

- **规矩（一句话）**：**位置放路由，过程放 state；影响数据请求的放 query，纯 UI 偏好的放本地偏好。**
- **七个具体判断**：
  | 数据是什么 | 放哪 | 本项目实例 |
  |---|---|---|
  | **子页面** | 子路由（`'' → redirect` 实现"不记忆"） | 难度页 `system` / `custom` |
  | **带参数** | 路径参数 | `/p/:pid`（分享落地）、`/puzzle/:pid/edit`（编辑） |
  | **影响数据请求** | query | `/search?q=&sort=&page=`、`/my-puzzles?sort=&page=`、`/login?mode=&redirect=` |
  | **纯 UI 偏好** | 本地偏好（`services/prefs.ts`，`sudoku.` 前缀） | `pagerMode` |
  | **流程阶段 / 弹层 / 游戏状态** | 保持 state | 题面→答案两阶段、预览 / 参考答案 / 确认框 |
  | **全站布局** | 父路由（`AppLayout` 作为 `/` 的父路由，主内容进 `<RouterView/>`） | 顶栏 + 内容区 |
  | **返回来源** | 靠浏览器历史（`router.back()`，无历史兜底 `/difficulty`） | **不把来源写进 URL** |
- **为什么**：这直接决定"**能否分享、能否刷新、能否后退**"：
  - 放进 query 的状态 → 刷新/分享后还在（搜索条件）；
  - 放进 state 的状态 → 刷新就没了（弹层、游戏进度）—— 但这**正是我们想要的**；
  - 纯偏好放 localStorage → 换页面还在（浏览方式）。
- **两条收敛规则**（也在 R15 里）：换排序/关键词 → `page` **重置 1**；`page` 越界 → **收敛到最后一页**；`pageCount ≤ 1` → **隐藏分页条**。
- **脚本查不了**，所以是评审规则 —— **但它比大多数红规则更容易写错**，因为它涉及"用户体验直觉"。

## 5. 例外登记 E1~E8（"规则之外的合法特例"）

**知识点**：任何规则都会遇到"特殊情况"。健康的做法**不是**"悄悄违反"，而是**显式登记 + 说明理由** —— 这样下一个人看到时知道"这是有意的"，而不是"前人写错了"。

| 例外 | 内容 | 为什么合法 | 登记在哪 |
|---|---|---|---|
| **E1** | `core/sudoku/rules.ts` 的 `getSudoku`：模块级 `Map` 记忆化缓存 | **对入参可观察等价于纯函数**（`Sudoku` 是按 `boxSize` 生成的无状态工厂） | 守卫 `CORE_STATE_EXEMPT`（R11 的例外） |
| **E2** | `render/board.ts` 的 `setupCanvas`：读 `devicePixelRatio` / 写 canvas 尺寸 | **它本来就是 canvas 适配器**（§2.1 判据："出现 `ctx` / `devicePixelRatio` 就在这层"） | 文档（`render/` 职责描述） |
| **E3** | `GameStore` 类型放 `stores/game.ts`，**不放 `types/`** | 它依赖 Pinia 的 store 实例类型 → 放进 `types/` 会违反 R13（types 不能依赖实现） | 文档 + R10 说明 |
| **E4** | 预留类型登记在 `RESERVED_TYPES` | 允许"暂时没人用但有意保留"的类型存在（**必须显式登记**），否则 R10 报"死类型" | 守卫 `RESERVED_TYPES`（当前是**空集** = 现在没有预留类型） |
| **E5** | 预览遮罩的缩放由 `usePuzzlePreview` 自己 `useZoom` 持有 | 与页面主盘的 `zoom` **作用域不同（不同 canvas）**，不算违反 R7 的"只调一次" | 文档（R7 说明里） |
| **E6** | `useBoardCanvas` 的 `ResizeObserver` 是"容器宽度的唯一测量源"；渲染器保留"没传宽度就自己量一次"的兜底 | 主路径不读布局（性能），兜底分支保证 `renderBoard` 单独调用时也能工作 | 文档 |
| **E7** | `core/sudoku/tracker.ts` 的 `place()` 返回**闭包撤销函数** | 撤销记录**不跨模块**（`Change` 类型保持私有），不违反 R10 的"单文件私有类型留原文件" | 文档 |
| **E8** | `composables/puzzle/metaText.ts` 不是 composable（纯文本拼装函数，无 `ref` / 生命周期） | 文件名不以 `use` 开头是**故意的**；登记后 R8 不会拦 | 守卫 `COMPOSABLE_EXEMPT` |

**读懂这张表的姿势**：
- **E1 / E4 / E8 是"机器例外"**（必须写进守卫脚本，否则会报错）；
- **E2 / E3 / E5 / E6 / E7 是"语义例外"**（写进文档说明"为什么这样不算违规"）。
两者区别：机器例外是"脚本查不了上下文"；语义例外是"人查得出上下文，但要留下解释"。

## 6. 守卫是怎么工作的（读 `scripts/check-arch.mjs`，288 行）

### 6.1 整体结构（三段）

```js
// 第一段：R1 —— 只看 src/ 顶层目录名
for (const name of readdirSync('src'))
    if (!TOP_ALLOW.has(name)) err('R1', `src/${name}`, '顶层不在白名单（见 ARCHITECTURE.md R1）')

// 第二段：逐文件检查（src/** + functions/** 的 .ts 与 .vue）
for (const file of files) {
    const code = read(file)                  // 原文（数行数用）
    const bare = stripComments(code)         // 去注释（做正则检查用）
    const imps = importsOf(code)             // 所有 import 说明符
    // …R9 行数 → R2/R5/R13 矩阵 → R3/R9/R11 core → R4 stores → R6 pages → R7 composables
    //  → R8 命名 → R12 桶文件 → R14 棋盘缩放
}

// 第三段：R10 —— 跨文件统计（types/ 每个导出名在全文出现几次）
for (const file of files.filter(f => under(f, 'src/types'))) { ... }

// 汇总：逐条打印 → 打印分布 → exit 1 or 0
```

### 6.2 六个工具函数（都很值得学）

```js
const read = f => readFileSync(f, 'utf8')
const stripComments = s => s.replace(/\/\*[\s\S]*?\*\//g, '').replace(/\/\/[^\n]*/g, '')
const importsOf = code => [...code.matchAll(/(?:from|import)\s*['"]([^'"]+)['"]/g)].map(m => m[1])
const under = (file, dir) => file.startsWith(dir + '/')
const isTest = file => file.endsWith('.test.ts')
const layerOf = file => layerKeys.find(k => file === k || under(file, k))     // 最长前缀优先
```

| 函数 | 为什么这么写 |
|---|---|
| `stripComments` | **必须先去掉注释再查正则**：否则注释里写"这里不要用 `Math.random`"都会被误报（所有"正则检查"的第一步） |
| `importsOf` | 一条正则同时抓 `import x from 'y'` 与副作用导入 `import 'y'` |
| `layerOf` | `layerKeys` 按**字符串长度降序**排 → 让 `src/core/board` 这类更长更具体的前缀优先命中（否则 `src/core` 先匹配） |
| `under(file, 'src/components')` | 比 `startsWith('src/components')` 更严谨（不会把 `src/components-x` 算进去） |
| `isTest` | **测试文件豁免**（R11 只要求"可测"，不要求"必须测"） |

**一个诚实的盲点**：`importsOf` **抓不到动态 `import()`**。本项目 `router/index.ts` 写的是：

```ts
component: () => import('@/pages/GamePage.vue')
```

这种写法**不会被 R2 检查**（正则要求引号紧跟 `import`，而这里是 `import(`）。
这里不影响架构正确性（路由指向页面本就合理），但**你要知道守卫不是万能的** —— 这也是 R15 这类规则只能靠评审的原因之一。

### 6.6 守卫查不到什么（→ 评审）

| 查不到的 | 为什么 | 靠什么保证 |
|---|---|---|
| **R15 状态归位** | "该放 query 还是 state"是语义判断 | 评审 + §4 R15 的七条判断 |
| **R8 命名语义** | `is` / `get` / `make` 的**含义**正则判断不了 | 评审（机器只查"常量大写"与"文件名 use 开头"） |
| **R4 的"用 `map` 写算法"** | 没有 `for` 关键字 | 评审 |
| **`extends` 用法是否合理** | 要判断"是不是同形状的第二个名字" | 评审 |
| **动态 `import()`** | 正则抓不到（§6.2 盲点） | 评审 |
| **"这个页面是不是真的只接线"** | 声明 ≤10 + 禁 `Math.` 只是**代理指标** | 评审（看它是否"只在取数据、传组件"） |

### 6.7 改规矩的顺序（顺序错了会踩坑）

```
① 先改 ARCHITECTURE.md（§一 分层 / §二 矩阵 / §三 规则 / §五 例外）
② 再改脚本（MATRIX / TOP_ALLOW / 预算常量 / EXEMPT 集合 / 正则）
③ 最后改代码
```

**为什么不能反**：先改代码、再改脚本，中间这段时间**守卫会一直报错**，别人分不清"你正在改规矩"还是"你真写错了"。
**文档先行**保证"规则只有一个权威来源"（`ARCHITECTURE.md` 顶部原话：**改规矩的顺序：先改这一页 → 再改守卫脚本 → 再改代码**）。

## 7. 归位原则（`ARCHITECTURE.md §六`）与三个演练

### 7.1 归位原则总表（"这段东西该写在哪"的权威答案）

| 这段东西是什么 | 归到哪 | 本项目实例 |
|---|---|---|
| 纯静态、无格式化 | `constants/` | `GAME_COPY.win`、`AUTH_COPY.needLogin` |
| 需要按入参拼装 | **core 纯函数** | `hintTextOf`、`percentOf`、`blankRatioErrorOf` |
| 纯展示、只在模板里出现 | 留在页面 / 组件模板 | 一行说明文字 |
| 可复用的控件定义（含闭包） | **随 composable 返回，由页面 spread** | `zoomActions` |
| 位置 / 可分享的状态 | **路由与 query**（R15） | `/search?q=&sort=&page=` |
| 纯 UI 偏好 | 本地偏好（`services/prefs.ts`） | `pagerMode` |
| 过程 / 依赖内存的状态 | state（store 或组件内） | 游戏进度、弹层开关 |
| 全站共用的界面 | 父路由布局（`AppLayout`），主内容进 `<RouterView/>` | 顶栏 |
| 页面要显示的"算好的值" | **由 composable 暴露**（composable 才能 import core） | `pageCount`、`percent` |
| 跨页共用的视觉规格 | 全局样式 `styles/*.css` | `card` / `form` / `overlay`（`.text-btn` 是"可点击文本"的唯一样式） |
| 跨页共用的流程 | 公共组合式 | `useListQuery`、`usePuzzlePreview`、`useClipboard`、`usePuzzleStage`、`useSolveFlow` |
| 悬浮提示 / 无障碍名 | **只在传入数据里有才用；没给就不加**（不自行发明文案） | `title` 属性 |

**最后一行值得特别说**：它防的是"**AI 式自作聪明**"——比如给一个没有标题的按钮硬编一个 `title="点击这里"`。规则要求**文案必须来自数据**（props / constants），因为你随手编的提示会与业务文案不一致。

### 7.2 演练一：我要加一个"收藏题目"功能（完整走一遍）

| 步骤 | 归到哪 | 具体 |
|---|---|---|
| ① 数据表 | 后端 | `schema.sql` 加 `puzzle_fav(pid, uid, created_at)`（复合主键）+ 索引；先改文档（REQUIREMENTS/ARCHITECTURE） |
| ② 接口 | `functions/api/puzzles/[pid]/fav.ts` | POST/DELETE；`requireUser` → 查在不在 → upsert / 删除；只回 `{ ok, favCount }` |
| ③ 类型 | `types/puzzle.ts` | `PuzzleDetail` 加 `favCount?: number`；**不要 `Omit`** 派生新名字 |

| ⑤ 状态 | `stores/puzzle.ts` | 只放"需要记住的"（如"我收藏的 id 集合"）；**不写 for / Math.** |
| ⑥ 编排 | `composables/puzzle/usePuzzleDetail.ts` | `toggleFav()`：调 services → 更新 store → 出错写 `error.value`（**异步与 router 只在这层**） |
| ⑦ 按钮数据 | 同上 | 返回 `favActions: Actions`（收藏/已收藏两种文案 + `onClick`） |
| ⑧ 画 | `components/` | **不用改**（按钮用通用 `TextAction`） |
| ⑨ 接线 | `pages/PuzzleViewPage.vue` | 加一行 `v-for` 渲染 `favActions`；**声明 ≤10 别超** |
| ⑩ 自检 | — | `pnpm guard && pnpm typecheck && pnpm typecheck:functions`；跑 `build` |

**注意 ⑧**：这是分层做对了的标志 —— **新功能没有让任何组件变复杂**（按钮数据化 + 通用组件复用）。

### 7.3 演练二：页面声明超了 10 个（真实会遇到的报错）

```
[R6] src/pages/SolvePage.vue — 页面声明 13 个 > 10
```

**处理顺序**（不要靠删变量糊过去）：
1. 看这 13 个声明里哪些是**同一个流程**的（例如"输入题面 → 校验 → 求解 → 浏览多解"）；
2. 把它们整体搬进 `composables/solve/useSolveFlow.ts`；
3. 页面只留：`const { ... } = useSolveFlow()` 一行 + 拼 `computed` + 渲染入参；
4. 重跑 guard，直到 0；
5. **顺手确认**新 composable 里没有 `Math.`（R7）。

### 7.4 演练三：我在组件里想用 router 跳转

```
[R5] src/components/PuzzleCard.vue — 组件不得引入路由（RouterLink / RouterView 是全局组件）
```

**正确做法**：组件把"用户点了挑战"这件事 **emit 出去**，由页面决定跳转：

```ts
// 组件：只有"事实"
const emit = defineEmits<{ challenge: [pid: string] }>()
// 模板：<button @click="emit('challenge', item.pid)">挑战</button>

// 页面：决定"事实之后干什么"（或交给 composable）
const onChallenge = (pid: string) => router.push({ name: PAGE.PuzzleView, query: { pid } })
```
**如果多个页面都要这段跳转**：把它放进 composable（页面调 composable），**不要**为了省事给组件开 router 的口子。
